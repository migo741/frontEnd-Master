# 第 18 章：可观测性、成本与性能

## 本章目标

让一次 Agent 运行可解释、可关联、可计费、可报警，并在质量不下降的前提下优化延迟与成本。

## 1. Trace 结构

run root span 下包含 model attempts、tools、retrieval、guardrails、handoffs、approval、queue/DB。传播 trace_id/run_id；并行和异步保持 parent/link。不要把所有内容塞一个日志字符串。

## 2. 结构化属性

model/provider/version、prompt version、input/output/缓存 token、tool、attempt、latency、status、error category、tenant（安全 id）、budget、dataset case。高基数全文不做 metric label。

## 3. Logs、metrics、traces

logs 看离散事件；metrics 看聚合趋势/SLO；traces 看单次路径。三者用 ids 关联。OpenTelemetry 等开放语义有利于供应商可替换，但 Agent-specific 字段要有自己的 schema/version。

## 4. 隐私与采样

Prompt、tool args/result、检索文档可能含 PII/secret。默认记录 metadata/安全摘要；内容级 trace 需明确同意、加密、RBAC、TTL、审计。错误采样更高也不能绕过隐私。

## 5. 成本模型

按 run/tenant/feature 归因 model tokens、embedding/rerank、tools、向量/存储、计算和人工审批。价格带 version；预算是估算，账单定期 reconcile。报告 cost/successful-task，而非只 cost/request。

## 6. 延迟分解

queue、context/retrieval、time-to-first-token、generation、tools、approval。并行独立读取、stream 提升感知延迟；不应并行有依赖/写操作。P95/P99 比平均更能说明尾部。

## 7. 优化顺序

1. 删无价值步骤/上下文/工具。
2. cache 确定或语义安全结果。
3. 模型路由/小模型局部任务。
4. 并行独立 I/O。
5. 控制输出长度/检索 top-k。
6. batch embedding/offline。

每次用 eval 验质量，不能只看价格。

## 8. Cache

key 包 model/prompt/schema/input/permissions/data version。模型响应 cache 对个性化/时效/安全敏感；RAG cache 需文档/ACL version。不要让一个 tenant 的 cache 命中另一个。

## 9. SLO 与报警

定义可用性、任务成功、P95、cost/task、approval wait、stuck run、tool error、safety violation。模型 provider 5xx 与业务失败分开。报警需要 runbook 和 owner。

## 10. Debugging

从 failed run 重放确定性 tools/model fixture；比较 prompt/model/workflow/config versions；先定位层再修。生产 trace 不能要求保存隐藏 chain-of-thought。

## 11. 容量

按并发 run、每 run fan-out、provider rate、DB pool、queue depth、stream connections 估算。加 tenant fairness、global/provider/tool bulkhead，防一个复杂 run 拖垮系统。

## 本章速记

Agent 可观测性必须贯穿模型、检索、工具和状态。优化目标是每个成功任务的质量、成本和尾延迟，不是 token 越少越好。
