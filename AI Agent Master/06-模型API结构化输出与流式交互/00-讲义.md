# 第 06 章：模型 API、结构化输出与流式交互

## 本章目标

构建可靠模型网关：请求/响应契约、结构化输出、stream、错误、重试、usage 与供应商差异都可测试。

## 1. API 边界

SDK 是便利层，不是领域模型。应用定义自己的 `ModelRequest/ModelEvent/Usage/ModelError`，adapter 映射供应商对象。只抽象真正共同语义；reasoning、cache、tool parallelism 等差异放 capabilities。

## 2. 消息与指令

区分 developer/system policy、user data、assistant history、tool result。不要把权限策略拼到用户字符串里。保存 prompt template version、变量摘要和模型版本，才能复现。

## 3. Structured Outputs

机器消费输出使用严格 JSON Schema/Pydantic。Schema 要小、清晰、有限 enum、禁止 extra；复杂业务拆多步。解析失败是 protocol error，可做有限 repair/retry，但不得无限让模型“再试一次”。

结构正确不等于语义正确：日期可符合格式却是编造，ID 可符合字符串却不存在，仍需领域验证/证据。

## 4. Tool call 与普通结构化输出

工具调用表示“请求应用执行能力”；structured response 表示“返回数据”。不要把“退款建议”伪装成退款 tool call；副作用工具走授权/审批流程。

## 5. Streaming

流不是字符串不断 append 那么简单。事件可能是 text delta、tool arg delta、tool call completed、usage、error、response completed。只有对应 completed 事件后才信任完整结构。

SSE/WebSocket 处理断线、重连、重复事件、sequence、UTF-8、backpressure。用户取消后是否停止远端计费需按 provider 语义验证。

## 6. 错误分类

- authentication/configuration；
- rate limit/quota；
- timeout/network；
- provider 5xx；
- invalid request/schema/policy；
- protocol parse；
- cancelled；
- model refusal/unsupported capability。

只有部分错误可 retry。保留 provider request id，公开信息脱敏。

## 7. 幂等和重试

纯生成可有限重试，但会产生不同文本和成本。tool output 已执行后重试模型请求时，必须带完整已执行结果并防重复 tool call。客户端超时不代表 provider 未完成；可查询/使用 request id 时优先恢复。

## 8. Usage 与成本

统一记录 input/output/cached/reasoning/tool tokens（按 provider 能提供的字段）、模型和价格版本。成本计算与账单可能存在延迟/差异；做估算字段并定期对账。

## 9. Provider adapter contract

contract tests 覆盖：文本、结构化、工具、并行工具、stream、refusal、usage、取消、超时、未知事件。录制响应要脱敏并标版本，不能永远代替真 API smoke。

## 10. 兼容演进

SDK/model API 变化快。adapter 窄、版本固定、升级 diff + eval。避免在课程代码写某个“永远最新”模型；模型 id 由配置/registry 选择。

## 本章速记

模型 API 是概率服务加事件协议。可靠系统等待完整事件、验证结构和语义、分类错误、记录 usage，并通过 adapter/contract test 隔离供应商变化。
