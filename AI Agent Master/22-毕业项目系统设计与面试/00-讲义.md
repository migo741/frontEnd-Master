# 第 22 章：毕业项目、系统设计与高级面试

## 本章目标

把前 21 章收束成生产级作品和可答辩证据。最终项目不是聊天 UI，而是一套可测、可恢复、可审计的企业知识工作 Agent 平台。

## 1. 毕业项目：Enterprise Operations Copilot

场景：多租户企业客服/工单。Agent 可查知识和订单、生成有引用回复、提出评论/状态/退款动作、等待人工批准、跨天恢复。另提供研究子流程和只读 MCP server。

```text
apps/
  api/              # FastAPI submit/status/events/cancel/approve
  web/              # TypeScript UI，可复用你的前端能力
services/
  worker/           # durable runs
packages/
  domain/           # Pydantic/domain/events/errors
  model_gateway/    # 多 provider/capabilities
  tools/            # auth/policy/idempotency
  workflows/        # hand-written + LangGraph
  rag/              # ingestion/retrieval/citation
  mcp_server/       # 只读工单能力
  evals/            # datasets/graders/reports
infra/
  postgres/ redis/ object-store/ telemetry/
docs/adr/ threat-model/ runbooks/
```

## 2. 必须交付的能力

- Python 3.13、strict typing、Pydantic v2、async、FastAPI、pytest、Ruff。
- provider-neutral model gateway + structured/stream/tool contract。
- 手写 loop 与 LangGraph flow 至少各一个，解释选择。
- hybrid RAG、ACL、citation、version/delete 和分层 eval。
- MCP Python server + TypeScript/Python consumer contract。
- tool risk、proposal/approval/execute、idempotency、审计。
- checkpoint、worker lease、crash recovery、workflow migration。
- trace/metrics/cost、dashboard、SLO、alerts/runbooks。
- prompt injection/跨租户/SSRF/重复写/沙箱红队。
- Docker/CI、canary/rollback、模型和 prompt 版本。

## 3. 质量门槛

- 单元/契约测试全过，关键 side effect 故障注入不重复。
- 至少 150 条 eval；关键任务按 slice 达标。
- 跨租户、越权执行、未批准高风险动作必须 0 通过。
- 每个 claim citation 可追踪；无证据拒答。
- P95、cost/success、最长 run、资源上限有明确预算。
- API key/PII 不进入仓库和默认 trace。

## 4. ADR

至少 8 份：语言与版本；手写 vs 框架；provider abstraction；RAG；MCP；durable runtime；memory；安全/approval；部署可多选。每份写背景、选项、决策、后果和复审条件。

## 5. 系统设计答题框架

1. 澄清用户、任务、风险、规模、SLO。
2. 判断代码/workflow/Agent/multi-agent。
3. 画数据流、信任边界和状态机。
4. 定义 tools/Schema/permissions/side effects。
5. 设计 RAG/memory/context 和数据生命周期。
6. 设计 durable execution、HITL、幂等、取消。
7. 设计 eval/observability/cost/safety。
8. 容量、部署、灰度、降级、DR。
9. 说明取舍和何时演进。

## 6. 高频高级问题

1. 什么时候不该用 Agent？
2. workflow、single-agent、multi-agent 如何选？
3. 为什么 Python 是主流，TypeScript/Java/Go 何时更合适？
4. tool calling loop 如何终止并恢复？
5. structured output 保证了什么、没保证什么？
6. Prompt injection 为什么不能靠 Prompt 解决？
7. 如何防模型伪造 tenant/user/approval？
8. 写工具如何做到不重复副作用？
9. context、state、memory、RAG 有什么区别？
10. 如何评 RAG 是 retrieval 还是 generation 出错？
11. LangGraph checkpoint 重放对 side effect 有何要求？
12. MCP 带来什么，风险是什么？
13. 多 Agent 何时反而更差？
14. LLM-as-judge 如何校准？
15. 如何建立 Agent eval dataset 与发布门禁？
16. 如何追踪一次 run 的成本和质量？
17. 如何设计长任务 API/SSE/取消？
18. 模型/Prompt/graph 升级如何灰度回滚？
19. Browser/Code Agent 如何沙箱？
20. 如何在 provider outage 时降级？
21. 如何处理跨天审批期间的版本变化？
22. 举例说明一次牺牲“智能”换可靠性的设计。

## 7. 回答标准

每题包含：机制、失败例、系统控制、测试/指标、取舍。只说“加 guardrail”“用 LangChain”“上向量库”不算高级回答。

## 8. 作品证据

展示 architecture/state/threat diagrams、trace、eval report、故障注入视频/日志、性能成本前后、ADR、runbook、一次事故复盘。面试重点讲“如何证明不会/如何发现”，不只展示成功聊天。

## 9. 90 分钟模拟答辩

- 20 分钟系统设计。
- 20 分钟故障/安全评审。
- 15 分钟读 trace 定位质量问题。
- 15 分钟 Python async/tool 代码 review。
- 10 分钟模型升级/成本优化。
- 10 分钟复盘取舍。

## 10. 毕业判定

项目 ≥80 分且无安全一票否决；随机 10 题至少 8 题能用真实失败路径回答；在 30 分钟内从 trace 正确定位 3 个跨模型/检索/工具/状态问题。

## 本章速记

高级 Agent 工程师的核心不是让 Demo 更像人，而是把概率能力装进可控制、可恢复、可评测、可治理的软件系统，并能用证据解释取舍。
