# 第 14 章：MCP 协议与工具生态

## 本章目标

理解 Model Context Protocol 的 client/server、tools/resources/prompts、transport 和授权边界，能构建安全 Python MCP server 并由 TS/Python 客户端消费。

## 1. MCP 解决什么

MCP 让 host/client 用统一协议发现并调用 server 的能力，减少每个 Agent 对每个系统写专用 glue。它是互操作协议，不自动带来可信、安全、幂等或业务正确。

## 2. 角色

- Host：承载 Agent/用户体验和安全政策。
- Client：与某个 server 建连接，协商能力、调用。
- Server：暴露 tools、resources、prompts 等。

保持每个 server 边界清楚，避免“万能内部系统 MCP”拥有所有权限。

## 3. Tools、Resources、Prompts

Tool 表示模型可请求执行的动作；resource 是可读取上下文；prompt 是可复用模板/工作流入口。不要把有副作用操作伪装成 resource，也不要把 secret 作为 resource 返回。

## 4. Transport

本地常用 stdio，远程常用 Streamable HTTP。stdio server 继承启动进程环境/权限，风险不低；远程需 TLS、认证、授权、网络边界、超时和速率。日志不能污染 stdio 协议流。

## 5. Capability/Schema

tool schema 小而严格；返回 structured content/artifact reference。client 对 server version/capabilities 做兼容检查。工具列表可能很大，按 allowed_tools/任务裁剪，降低 token 和攻击面。

## 6. OAuth 与 delegation

远程工具需明确是 service identity 还是 on-behalf-of user。token audience/scope/expiry 正确，server 每次资源级授权。Agent/模型看不到 raw token。禁止 confused deputy：server 不能因为 host 有高权 token 就替低权用户执行。

## 7. 审批

Host 按 risk 决定 approval；server 仍必须做授权。approval 展示工具、参数、目标、影响和数据外发，不只弹“是否允许”。批准绑定参数 hash/过期时间。

## 8. Prompt injection 与恶意 server

信任 server 开发者不等于信任 server 可访问的全部内容。恶意工具描述、过度参数、工具输出注入都可能窃取上下文。官方安全文档强调工具确认、最小访问和审查参数。[MCP 与 Connectors](https://developers.openai.com/api/docs/guides/tools-connectors-mcp)

## 9. Server 安全

输入验证、最小权限、allowlist、SSRF/路径规范化、secret 隔离、输出上限、timeout、审计。安装/启动第三方 stdio server 等同执行本地代码，固定来源和版本，在 sandbox 中运行。

## 10. SDK 选择

MCP 官方 SDK 列表中 Python、TypeScript、Go 为 Tier 1（以调研日页面为准）。课程 server 用 Python，另写一个 TypeScript consumer 验证跨语言。[官方 SDK](https://modelcontextprotocol.io/docs/sdk)

## 11. Contract tests

initialize/capabilities、list tools、valid/invalid call、cancel、timeout、auth、approval、schema evolution、oversize、malicious content、concurrent sessions。用 inspector 只是辅助，CI 仍需自动化。

## 本章速记

MCP 标准化连接，不标准化信任。Host、client、server 三层都要做自己的权限、审批、Schema、隔离和审计。
