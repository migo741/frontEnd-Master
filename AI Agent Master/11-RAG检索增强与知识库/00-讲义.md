# 第 11 章：RAG 检索增强与知识库

## 本章目标

从文档入库到有引用回答构建可评测 RAG，区分检索失败、上下文失败和生成失败。

## 1. RAG 解决什么

RAG 在请求时取外部知识，适合频繁变化、需要引用和权限控制的数据。它不保证答案正确；错误文档、差检索、注入内容和生成误读仍会失败。Fine-tuning 更偏行为/格式，不是把动态知识可靠写进参数。

## 2. Ingestion pipeline

采集 → 解析/OCR → 清洗 → 结构识别 → chunk → metadata/ACL → embedding/index → version。保存原文、checksum、parser version、chunk lineage，支持增量更新和删除。

## 3. Chunking

按标题/段落/代码/表格语义切分，保留父文档和邻接；固定字符窗只是基线。太小缺上下文，太大稀释匹配/增成本。表格、代码、PDF 多栏和扫描件需要专门策略。

## 4. Retrieval

向量召回擅长语义，BM25/关键词擅长精确实体；生产常用 hybrid + metadata filter。query rewrite/multi-query 可提升 recall，也会引入偏移和成本。

## 5. Rerank 与 context selection

先高 recall 召回，再 rerank/去重/多样化，按 token budget 组上下文。相同来源重复 chunk 不应挤掉其他证据。低分/无证据时拒答或澄清。

## 6. 权限必须在检索前/中

ACL/tenant filter 进入 query/index partition，不先全局取 top-k 再让模型忽略。引用链接也需授权；缓存 key 包权限上下文。

## 7. 引用

每个 context chunk 有 source id、title、location、version；生成输出引用到具体 evidence。返回前验证 citation id 存在、用户可访问、claim 有支持。引用存在不代表支持关系正确，需要 citation correctness eval。

## 8. 文档中的 Prompt Injection

文档是 data，不是 instruction。先做结构化检索/提取，把不必要自由文本隔离；检索 Agent 不获得高风险写工具。恶意文档安全测试必须进入 dataset。

## 9. RAG 评测分层

- ingestion：解析/表格/OCR 完整性。
- retrieval：Recall@k、MRR、nDCG、ACL。
- context：相关性、覆盖、冗余。
- answer：正确、完整、faithful、citation。
- system：延迟、成本、拒答、业务完成。

没有 ground truth 时人工标注、规则和 LLM judge 组合，并校准 judge。

## 10. 更新与删除

文档 version，index alias 原子切换；删除传播到 chunk/vector/cache。回答 trace 记录使用版本，便于事故追溯。不要让旧 chunk 与新文档同时无标识存在。

## 11. Graph RAG/Agentic RAG

只有多跳关系、实体图或动态工具查询确有收益时使用。先把单次 hybrid retrieval 做好，再以 eval 证明 query planning/多跳的增益。

## 本章速记

RAG 是数据与检索系统，不是“向量库 + Prompt”。高级能力是 lineage、ACL、hybrid/rerank、引用、分层评测和更新删除。
