# 第 19 章：Agent 安全、隐私与沙箱

## 本章目标

用威胁建模和纵深防御处理 prompt injection、越权工具、数据外泄、供应链、代码执行和多租户隔离。

## 1. 信任边界

用户输入、网页、邮件、PDF、RAG、工具输出、MCP server、模型输出均不可信。模型不是 policy enforcement point。身份、授权、网络/文件隔离、审批和审计由代码/基础设施执行。

## 2. Prompt injection

直接注入在用户输入，间接注入藏在文档/网页/工具结果。攻击目标是改变行为、窃取 context、触发工具。指令分隔/“忽略恶意内容”只能缓解，不能根治。

官方安全建议强调：不可信数据不要直接驱动行为，先提取有限结构字段，结合 guardrail、工具确认和隔离；structured output 会降低风险但不能消除。[官方安全文档](https://developers.openai.com/api/docs/guides/agent-builder-safety#combine-techniques)

## 3. 最小权限

按用户/tenant/run/task 动态 tool allowlist；read/write 分离；短期 token、最小 scope、资源级授权。敏感读取和外发组合尤其危险，即使两工具单独看都合理。

## 4. Data flow control

标记数据来源/敏感度/tenant，限制从 secret/private source 流向 public sink。发送邮件、HTTP、搜索 query、日志都可能成为外泄通道。工具参数做 DLP/策略检查，不只输出文本审核。

## 5. Approval

高风险动作默认 human confirmation，展示实际目标和参数。避免 approval fatigue：风险分级、批量但精确授权、可撤销。批准不能覆盖服务端授权。

## 6. Code/Shell/Browser sandbox

容器不自动安全。使用非 root、只读文件系统、临时 workspace、CPU/内存/pid/time 限制、seccomp/虚拟化、网络 deny-by-default/allowlist、无 host socket/credential、输出上限、销毁环境。高风险执行考虑 microVM/专用沙箱服务。

## 7. SSRF 与文件

URL 重新解析每次 redirect，禁 private/link-local/metadata；DNS rebinding 防护。路径 resolve 后检查在 workspace 内，拒绝 symlink escape、`..` 和设备文件。上传文件隔离解析、大小/格式/压缩炸弹限制。

## 8. 多租户

tenant isolation 进入 DB row policy/query、vector namespace、cache key、object path、queue、trace access。绝不依赖 Prompt 提醒。用两个真实 tenant fixture 做负向测试。

## 9. Secret 与隐私

secret manager 注入工具进程，不进模型/trace；日志 redaction 不能只 regex。PII 最小化、目的限制、保留/删除、数据地域和供应商政策。开发 eval 用合成/脱敏数据。

## 10. 供应链

锁依赖、SBOM、签名/来源、漏洞扫描；第三方 MCP/工具相当于代码执行与数据访问。插件升级重新审查 capabilities/permissions。模型/Prompt/数据集也要版本和访问控制。

## 11. Red team

覆盖直接/间接 injection、编码/多语言、工具混淆、参数走私、越权、跨租户、exfiltration、DoS、重复写、恶意 MCP、sandbox escape。自动生成攻击 + 人工创新；修复进入 regression。

## 12. Incident response

kill switch 可禁模型/某工具/某 tenant；轮换 secret、冻结写操作、保留安全 trace、定位受影响 run、通知和复盘。安全报警不要把恶意全文再次广播到日志/工单 Agent。

## 本章速记

Prompt 不是安全边界，模型也不是授权引擎。生产 Agent 依靠最小权限、信息流控制、审批、沙箱、隔离和可操作的事件响应。
