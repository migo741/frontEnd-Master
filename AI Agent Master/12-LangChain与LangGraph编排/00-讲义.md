# 第 12 章：LangChain 与 LangGraph 编排

## 本章目标

在理解手写 loop 后使用 LangGraph 构建显式、有状态、可中断恢复的工作流，并避免把框架对象侵入全部业务层。

## 1. 生态定位

LangChain 提供 model/tool/agent 抽象和集成；LangGraph 是低层 orchestration runtime，强调 durable execution、streaming、HITL、persistence。官方也建议先理解 models/tools，再进入低层图。[官方概览](https://docs.langchain.com/oss/python/langgraph/overview)

## 2. StateGraph

state 是 typed schema；node 是接收 state/context、返回 update 的函数；edge/conditional edge 决定路由；compile 产生 runnable。保持 node 单一职责和可观测边界，不把整个 Agent 放一个 node。

## 3. Reducer 与并行

并行 node 可能同时更新 state；reducer 必须定义合并语义。append messages 容易重复；使用稳定 id/dedup。共享可变 state/隐式全局会破坏重放。

## 4. Checkpointer/thread

checkpoint 按 thread/run 保存 state snapshot，使 HITL、memory、time travel、故障恢复成为可能。开发可内存，生产用持久 store。thread_id 是数据隔离关键，不可让用户任意猜到其他 thread。

## 5. Interrupt/HITL

interrupt 保存状态并等待外部输入。审批前 side effect 必须幂等或放到批准后独立 node；恢复可能重新进入 node。官方强调 side effect 和 idempotency，这是可靠执行的核心。[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)

## 6. Retry 与错误路由

transient 用 RetryPolicy；模型可修复错误走 repair edge；需要用户输入 interrupt；不可恢复异常上抛/失败。不要让所有异常回到 Agent 自己解释。

## 7. Subgraph

在可独立测试、状态/团队/权限边界明确时用 subgraph。不要把每个函数都变 subgraph。父子 checkpoint、namespace 和 memory visibility 要明示。

## 8. Durable execution 约束

可重放 flow 中非确定性和 side effect 放 task/node，并保存结果；state 必须可序列化。节点粒度决定 checkpoint/重做/trace 清晰度与存储开销。

## 9. Streaming

区分 values/updates/messages/custom events。面向 UI 输出稳定应用事件，不直接让前端绑定框架内部 event shape。stream 断开与 run 生命周期分离。

## 10. 框架隔离

domain、tools、policy、RAG、eval 不依赖 LangGraph；workflow adapter 把它们组图。否则框架升级等于全仓重写，单元测试也难以脱离 runtime。

## 11. 测试

node unit、graph path、checkpoint resume、interrupt approve/reject/edit、concurrent thread、failure injection、state migration。固定 fake model/tool，另有少量真模型 eval。

## 本章速记

LangGraph 的价值不是画图，而是显式状态、节点边界、checkpoint 和中断恢复。业务规则仍应在框架外，副作用必须按可重放语义设计。
