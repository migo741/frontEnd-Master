# 第 04 章：Python 异步、并发与工程化

## 本章目标

能构建高并发但有界的 Agent 服务，正确处理取消、超时、资源池、包管理、测试和 FastAPI 生命周期。

## 1. async 不是自动并行

调用 async 函数得到 coroutine，必须 await 或由 task 调度。event loop 适合 I/O；CPU 密集 tokenization/rerank/解析会阻塞 loop，应移到进程、线程（仅释放 GIL/库适合）或独立服务。

```python
async def fetch_one(client, url):
    response = await client.get(url)
    response.raise_for_status()
    return response.json()
```

## 2. 结构化并发

优先 `asyncio.TaskGroup`/AnyIO task group，让子任务生命周期受父作用域管理。裸 `create_task` 容易丢异常和泄漏后台任务。并发 fan-out 必须 semaphore/worker pool 有界。

## 3. 超时与取消

超时是预算，不等于底层副作用停止。`asyncio.timeout` 触发取消；库若吞 CancelledError 或同步线程继续跑，操作可能完成。cleanup 用 finally，通常不要吞取消。外层总 deadline 要向工具、HTTP、数据库传播剩余预算。

## 4. retry

只重试暂时性、可安全重复的操作；指数退避 + jitter，尊重 Retry-After。模型 4xx schema/policy 错误不是重试对象。写操作使用 idempotency key 或先查询结果；重试预算属于总 deadline/cost budget。

## 5. backpressure

queue 设置 maxsize；producer await put，让 consumer 速度反向限制生产。流式 token 不应无限缓存；慢客户端可合并 delta、断开或落盘。并发上限按 provider、tenant、tool 分层，而非一个全局数字。

## 6. HTTP client 与资源池

复用 AsyncClient/连接池，不为每次 tool call 创建 client。设置 connect/read/write/pool timeout、最大连接、响应大小、TLS 和代理策略。应用 lifespan 中创建并关闭资源。

## 7. FastAPI 边界

route 只做认证、Schema、提交 run、stream/status；长 Agent 不占用单个请求生命周期，应进入 worker/queue。SSE/WebSocket 断开要传播取消或按产品策略继续后台 run。

## 8. Python 工程工具

- `pyproject.toml` 是项目与工具配置中心。
- `uv.lock`/lockfile 固定可复现依赖；应用提交 lockfile。
- Ruff lint/format，Pyright/mypy strict，pytest。
- `src/` layout 防测试误 import 工作目录源码。
- 配置与 secret 在启动边界解析，不散落 `os.getenv`。

## 9. 测试异步代码

用 fake clock/transport/model，不在 unit test 真 sleep/真调模型。测试取消、超时、partial failure、最大并发和 cleanup。对 provider SDK 做 contract/integration test，并用预算和标记隔离。

## 10. 日志

结构化字段：run_id、trace_id、tenant、step、tool、model、latency、usage、status；不记录完整 prompt/response/secret。使用 contextvars 传播请求上下文，但后台 task 要显式复制/设置。

## 11. Python 3.14 意识

3.14 的 annotations 运行时行为变化会影响读取 `__annotations__` 的库；使用官方 API/新版本依赖，不依赖内部细节。课程 CI 测 3.14，但主线 3.13。

## 本章速记

Agent 天然有大量网络 I/O 和长任务。生产 Python 的关键是结构化并发、预算传播、取消与幂等，而不是简单把 def 改成 async def。
