# 第 02 章：函数、迭代器、装饰器与资源管理

## 本章目标

掌握 Python API 设计和资源生命周期，为后续流式模型、工具注册、trace decorator 与异步生成器打基础。

## 1. 参数设计

Python 支持 positional-only、普通、`*args`、keyword-only、`**kwargs`：

```python
def call_model(prompt: str, /, *, timeout: float, retries: int = 2) -> str:
    ...
```

公共 API 用 keyword-only 防参数含义混淆。不要把 `**kwargs` 当兼容万能袋；它隐藏拼写错误和契约。默认值在定义时求值，可变默认用 None 后创建。

## 2. 一等函数与闭包

函数可传递、返回和存入 dict，适合 tool registry。闭包捕获的是名称绑定；循环中创建 lambda 会晚绑定：

```python
handlers = [lambda x, i=i: (i, x) for i in range(3)]
```

但默认参数修复技巧不应掩盖复杂生命周期；复杂 handler 用工厂函数/对象。

## 3. 装饰器

装饰器在定义时包装函数。必须用 `functools.wraps` 保留 name/doc/annotations，Agent 工具常根据签名生成 Schema，丢签名会直接破坏 tool definition。

```python
def traced(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper
```

同步/异步 decorator 不能混淆；不要对 async 函数返回未 await coroutine 的同步 wrapper。

## 4. iterable、iterator、generator

iterable 能产生 iterator；iterator 有状态、通常只能消费一次。generator 通过 `yield` 惰性产生值，适合大文档 chunk、stream event。

```python
def batched(items, size):
    batch = []
    for item in items:
        batch.append(item)
        if len(batch) == size:
            yield batch
            batch = []
    if batch:
        yield batch
```

不要对一次性 iterator 先 `list()` 只为调试大数据。生成器异常在迭代时才发生，不在创建时。

## 5. `yield from` 与 generator 清理

`yield from` 委托另一个 generator，并能传递 return value/throw/close 协议。consumer 提前 break 时，资源是否释放取决于 generator/上下文管理设计；用 `try/finally` 清理。

## 6. context manager

`with` 表达获取—使用—释放，适用于文件、数据库事务、trace span、临时目录和锁。

```python
@contextmanager
def span(name):
    started = monotonic()
    try:
        yield
    except Exception as exc:
        record_error(exc)
        raise
    finally:
        record_duration(monotonic() - started)
```

`__exit__` 返回 truthy 会吞异常，除非明确设计，不要这样做。异步资源用 `async with`/`asynccontextmanager`。

## 7. 类与协议思维

Python 类常通过 dunder protocol 与语言合作：`__iter__`、`__enter__`、`__call__`、`__repr__`。组合通常优于深继承。依赖倒置可用 `typing.Protocol`，不必要求第三方类继承你的基类。

## 8. dataclass 的定位

dataclass 减少值对象样板，但不自动做外部验证。`frozen=True` 阻止属性重新绑定，却不深冻结内部 list。外部输入交给 Pydantic；内部稳定值可用 frozen dataclass。

## 9. 异常与资源边界

生成器、context manager 和 callback 都要明确：谁拥有资源、谁关闭、提前退出如何处理、cleanup 失败是否覆盖主异常。API client 要关闭 session/stream；工具 timeout 后后台线程是否仍执行也必须理解。

## 10. Agent 关联

- decorator：注册工具、trace、重试，但不能隐藏权限。
- generator：模型流、检索流、事件流。
- context manager：run/span、数据库事务、沙箱。
- Protocol：模型 provider、tool executor、checkpoint store。

## 本章速记

Python 高级语法的价值在协议和生命周期。用于 Agent 时，保留函数签名、区分一次性流、明确资源所有权，比写炫技装饰器重要。
