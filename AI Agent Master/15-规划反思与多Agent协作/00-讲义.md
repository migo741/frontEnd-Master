# 第 15 章：规划、反思与多 Agent 协作

## 本章目标

掌握 planner-executor、reflection、handoff、supervisor 等模式，并以可测收益决定是否增加多 Agent 复杂度。

## 1. 计划的两种形态

固定 workflow 的计划由代码定义；开放任务可让模型产生结构化 plan。Plan 不是事实，只是候选动作图；每步执行前重新验证前置条件、权限和预算。

## 2. Plan-and-Execute

planner 产目标/步骤/依赖/成功标准，executor 每次只执行 ready step，观察结果后 replan。限制 plan 大小和 replan 次数，避免“计划写得很漂亮但不做事”。

## 3. ReAct

模型在观察与动作间迭代，适合动态工具任务。不要把隐藏推理过程当审计；保存 tool request/result、结构化 decision summary、evidence 和 final rationale。

## 4. Reflection/Critic

critic 可发现遗漏，但同模型容易共享盲点，也会增加成本/延迟。能用 deterministic validator、compiler、tests、retrieval ground truth 的先用；LLM critic 用于主观或开放维度，并校准。

## 5. 多 Agent 模式

- Router → specialists。
- Supervisor → workers。
- Handoffs：控制权转移。
- Agents-as-tools：主 Agent 保持控制。
- Parallel debate/review。

多 Agent 的合理原因：上下文隔离、权限隔离、并行独立子任务、不同专长/模型、组织边界。不是为了模拟公司角色。

## 6. 协议

Agent 间传 Pydantic task/result、artifact ids、evidence、budget，不传无限自然语言历史。每个子任务有 owner、deadline、max turns、allowed tools 和 completion criteria。

## 7. 失败模式

任务乒乓、重复劳动、相互确认幻觉、共享错误证据、上下文爆炸、预算乘法、责任不清、权限升级。supervisor 也可能失败，控制面需硬预算和循环检测。

## 8. 并行

只并行独立 DAG 节点；有共享写状态时用锁/version/merge。结果聚合需处理冲突、来源和 partial，不让一个 summarizer 无证据覆盖分歧。

## 9. 评测多 Agent

与最强 single-agent/workflow baseline 比较任务成功、cost、latency、variance、tool errors、human intervention。若增益不稳定或只让 trace 更复杂，回退。

## 10. 组织与安全

不同 Agent 可拥有不同工具 scope；handoff 不自动继承全部权限。跨 Agent 输入仍是不可信；共享 memory 防污染。高风险动作集中在受控 executor，不让多个 Agent 各自执行。

## 本章速记

规划和多 Agent 都是控制结构，不是智能倍增器。用结构化协议、DAG、预算、权限和 baseline eval 约束，否则只会放大不确定性。
