# 第 03 章：Vue 与 TypeScript 类型系统

## 高级的目标是让非法状态难以表达

`lang="ts"` 不是类型安全。真正的收益来自：领域模型区分、组件契约可推导、API 边界运行时校验、模板也纳入检查、尽量不使用断言逃逸。开启 `strict`，CI 执行 `vue-tsc --noEmit`。

## 组件契约

```ts
type Status = 'idle' | 'loading' | 'success' | 'error'
type Emits = {
  select: [id: string]
  retry: []
}

const props = defineProps<{ rows: readonly Row[]; status: Status }>()
const emit = defineEmits<Emits>()
const model = defineModel<string[]>({ required: true })
```

事件名和参数应由类型表达，boolean soup 应改为 discriminated union。一个请求视图如果允许 `{ loading: true, data: [...], error: Error }` 同时存在，就是模型问题。

## 泛型组件与插槽

Vue SFC 支持 `<script setup lang="ts" generic="T extends { id: string }">`。泛型适合表格、选择器等“结构相同、数据类型不同”的组件；不要为只用一次的业务组件增加类型体操。`defineSlots` 可以声明 slot props，使使用方模板得到推导。

## 边界原则

TypeScript 只证明编译期假设，`fetch().json()` 仍是外部输入。将响应先视为 `unknown`，用 schema 校验后才进入领域层。区分 DTO 与 Domain：后端的 nullable、snake_case、字符串时间不应污染整个 UI。

避免：`as any`、非空断言链、到处 `Partial<T>`、把枚举当数据库、用一个巨型 `ApiResponse<T>` 掩盖不同错误语义。优先使用 `satisfies` 保留字面量窄类型并校验结构。
