# Vue Master 课程总索引

这份索引回答三个问题：每章到底解决什么生产问题、学到什么程度才算完成、章节之间为什么这样排序。它不是讲义替代品。

## 三层知识优先级

| 层级 | 含义 | 处理方式 |
|---|---|---|
| 稳定必修 | 当前 Vue 3.5 生产项目普遍适用，错误会直接损害正确性、质量或交付 | 深读、实现、测试、口述 |
| 条件必修 | 只在 SSR、组件库、Monorepo、微前端等特定产品形态成立 | 先掌握决策边界，有项目时完整实现 |
| 前沿观察 | Vue 3.6 RC、Vapor 等尚不能作为本课程稳定默认值 | 阅读原理、做隔离实验，不进入关键生产路径 |

## 逐章学习合同

### 01｜响应式心智模型

**生产问题**：搜索页快速切换条件后旧请求覆盖新结果；watcher 重复注册监听器；解构后更新丢失；大对象深度代理造成额外成本。

**必须掌握**：

- `track → trigger → scheduler → job → render` 的因果链；
- `ref`、`reactive`、`computed`、`watch`、`watchEffect` 的语义差别；
- 动态依赖清理、computed 脏标记、watcher flush 时机；
- `effectScope`、`onScopeDispose`、`onWatcherCleanup` 的所有权；
- `shallowRef`、`markRaw`、`toRaw` 的边界，而非优化口诀。

**完成证据**：最小响应式内核 + 一个能够抵抗乱序返回和卸载的异步 watcher。

### 02｜渲染、编译与更新调度

**生产问题**：列表输入框串值、一次点击产生多次昂贵渲染、`nextTick` 后仍拿不到外部请求结果、缓存页面恢复后监听器重复。

**必须掌握**：

- template 到 render function、VNode、patch flag、block tree 的关系；
- keyed diff 为什么需要身份，LIS 只解决哪一部分移动；
- job 去重、父子更新顺序、pre/render/post 队列；
- `nextTick` 只等待 Vue 更新队列，不等待任意异步任务；
- `KeepAlive`、`Teleport`、`Suspense`、异步组件的逻辑树/DOM 树/生命周期差异。

**完成证据**：一个可重复的列表身份事故 + Devtools/Performance 时间线 + 修复前后断言。

### 03｜Vue 与 TypeScript 类型系统

**生产问题**：组件传入了互斥 props、事件 payload 漂移、泛型表格列名写错、模板 ref 到处 `as`、依赖注入退化为 `unknown`。

**必须掌握**：

- `defineProps`、`defineEmits`、`defineModel`、`defineSlots`、`defineExpose`；
- 响应式 props 解构和默认值的版本语义；
- 泛型 SFC、discriminated union、`InjectionKey<T>`；
- `useTemplateRef`、组件公开实例和 `vue-tsc`；
- 静态类型与运行时不可信输入的分界。

**完成证据**：一个不使用 `any` 的泛型数据组件 + CI 中的 `vue-tsc --noEmit` 失败样例。

### 04｜Composable 与副作用治理

**生产问题**：请求、timer、WebSocket 或全局监听器在组件卸载后继续工作；共享 composable 意外跨用户；取消一个调用者却中断所有调用者。

**必须掌握**：

- composable 是资源所有权协议，不只是“把代码移到 useX”；
- `MaybeRefOrGetter`、`toValue`、readonly output 与 command API；
- latest-wins、AbortSignal、singleflight、引用计数和清理；
- 组件 scope、手工 scope、模块单例和请求 scope；
- 注入 adapter，使时间、网络和平台副作用可测试。

**完成证据**：一个可取消、后发优先、卸载安全且使用可控 Promise 测试的 `useLatestTask`。

### 05｜组件 API 与无头组件

**生产问题**：37 个布尔 props 形成非法组合；弹窗视觉正确但键盘不可用；透传 attrs 覆盖内部事件；父组件只能通过 ref 操纵子组件内部。

**必须掌握**：

- props、events、slots、`v-model`、provide/inject 的职责边界；
- 受控/非受控状态和 single source of truth；
- fallthrough attributes、公开实例和最小命令接口；
- headless state machine 与 styled shell 分层；
- Dialog/Combobox 的焦点、键盘、ARIA、Teleport 与嵌套策略。

**完成证据**：无头 Dialog 或 Combobox，至少有键盘、焦点和关闭原因测试。

### 06｜Pinia 与服务端状态

**生产问题**：Pinia 变成全局杂物箱；列表返回后覆盖刚刚的乐观编辑；持久化字段升级导致白屏；SSR 请求共享 store。

**必须掌握**：

- 组件局部、URL、表单草稿、Pinia、服务端缓存的状态分类；
- setup/options store、`storeToRefs`、`$patch`、`$subscribe`、`$onAction`；
- Pinia plugin、持久化 schema 版本与迁移；
- cache key、stale/fresh、失效、乐观更新和回滚；
- 每个 SSR 请求创建独立 Pinia 实例。

**完成证据**：状态所有权表 + 一条支持失效、乱序保护和失败回滚的数据变更链路。

### 07｜Router、权限与数据加载

**生产问题**：先显示页面再被守卫踢走；导航 A 的数据进入页面 B；动态路由刷新 404；把菜单隐藏误认为授权。

**必须掌握**：

- match、guard、resolve、confirm、DOM update、afterEach 的导航时序；
- beforeEach/beforeResolve/in-component guard 的放置标准；
- typed routes 和 route meta 契约；
- before/after navigation data fetching 取舍；
- RBAC 展示控制与服务端资源授权的边界；
- 取消、重定向、错误、scroll behavior 与 KeepAlive 联动。

**完成证据**：无闪屏权限导航 + 快速切路由的确定性竞态测试。

### 08｜API 类型安全与前端安全

**生产问题**：后端字段漂移却被 `as User` 掩盖；十个请求同时 401 触发十次刷新；富文本和跳转 URL 引入 XSS；重复点击产生重复订单。

**必须掌握**：

- transport DTO、运行时 schema、domain model 三层；
- 一致的成功/业务错误/协议错误/网络错误模型；
- Abort、timeout、幂等键、重试预算；
- access token 刷新 singleflight 与失败清场；
- XSS、CSRF、CSP、Cookie、URL、上传下载的前后端共同责任。

**完成证据**：一个运行时验证客户端 + 并发 401 测试 + 恶意富文本/URL 安全用例。

### 09｜Vite、包边界与 Monorepo

**生产问题**：开发正常而生产构建失败；`VITE_` 密钥泄露；插件拖慢所有 transform；业务包反向依赖页面；公共包发布后类型或 CSS 丢失。

**必须掌握**：

- Vite dev 原生 ESM 与 production bundling 的差异；
- resolve/load/transform 和虚拟模块；
- env 是构建输入，客户端前缀不是秘密存储；
- dependency pre-bundling、chunk、library mode 与 sourcemap；
- package exports、peerDependencies、依赖方向和架构测试；
- 先模块化单体，再按发布/所有权证据决定 Monorepo。

**完成证据**：一个最小 Vite plugin + CI 中会拒绝非法跨层 import 的架构守卫。

### 10｜测试策略与可测试设计

**生产问题**：测试数量很多但关键风险仍漏；全部 shallow mount；用 sleep 等异步；快照稍改就全量更新；E2E 偶发失败无人治理。

**必须掌握**：

- unit/component/integration/E2E/visual/a11y 各自承担什么风险；
- behavior over implementation detail；
- `nextTick`、VTU mutation await、`flushPromises` 的不同等待对象；
- MSW 的协议边界、Playwright 的用户路径和可访问定位；
- fake timer、可控 Promise、SSR/hydration 与 flaky 诊断。

**完成证据**：为一个复杂功能写最小风险矩阵，并用三层以内测试覆盖最大损失路径。

### 11｜性能、内存与可观测性

**生产问题**：团队凭感觉加 memo；首屏快但交互卡；虚拟列表滚动抖动；切页后内存不断增长；优化无法证明对用户有效。

**必须掌握**：

- 先定义用户症状、预算和可复现实验；
- 下载/解析/执行、响应式 invalidation、render、layout/paint 的链路；
- props stability、computed、`v-once`/`v-memo`、shallow data 的条件；
- code splitting、虚拟化、长任务拆分与 worker 边界；
- Performance、Vue Devtools、Memory、Web Vitals 和真实用户监测；
- before/after、回归阈值与停止优化条件。

**完成证据**：一份含基线、profile、假设、改动、结果、风险和回归门禁的报告。

### 12｜SSR、Hydration 与 Nuxt 4

**生产问题**：服务端 HTML 与客户端首帧不同；用户 A 的状态泄露给用户 B；服务端请求成功但客户端重复请求；全站 SSR 增加成本却没有收益。

**必须掌握**：

- `createSSRApp`、server render、HTML、hydrate 的双端链路；
- deterministic first render 和 browser-only API 隔离；
- request-scoped app/router/store/cache；
- Nuxt `useFetch`、`useAsyncData`、`useState` 与 payload；
- universal/client/hybrid/edge 的页面级选择；
- cache key、用户隔离、SEO 和水合错误测试。

**完成证据**：一个水合 mismatch 最小复现 + 并发请求隔离测试 + 页面渲染模式 ADR。

### 13｜Design System 与复杂组件

**生产问题**：组件库只是视觉复制品；设计 token 和组件行为耦合；复杂表格不可键盘操作；破坏性升级影响 600 个调用点。

**必须掌握**：

- token、primitive、headless behavior、styled component、business wrapper 分层；
- 状态机、ARIA pattern、focus management、overlay stack；
- Combobox/DataGrid 的异步、虚拟化和组合输入边界；
- semantic version、deprecation、codemod、双轨期与删除条件；
- story/interaction/a11y/visual regression 的发布门禁。

**完成证据**：一个复杂组件的状态转移表、键盘/ARIA 测试和一次兼容迁移计划。

### 14｜大型应用、微前端与迁移

**生产问题**：目录分层漂亮但依赖无约束；微前端为解决“代码多”反而增加重复依赖和一致性事故；Vue 2 全量重写长期不能发布；追预发布特性进入关键路径。

**必须掌握**：

- feature/module 边界、公开 API、依赖规则和 ownership；
- 模块化单体、package、custom element、microfrontend 的成本模型；
- 路由、样式、鉴权、事件、版本与观测契约；
- strangler migration、compatibility layer、指标和回滚；
- Vue 3.6/Vapor 的 opt-in、API 子集和隔离试验边界。

**完成证据**：一份含替代方案、失败模式、退出指标和回滚路径的 ADR。

### 15｜综合项目与高级面试

**生产问题**：作品只有 happy path；架构图与代码不一致；性能数据不可复现；面试只能背原理，无法解释一次真实取舍。

**必须掌握**：

- 从风险清单反推最小可交付切片；
- 需求、状态、API、模块、测试、性能和发布证据相互一致；
- 故障注入、降级、回滚、可观测与复盘；
- 在 2 分钟、10 分钟和 30 分钟三个尺度讲同一设计；
- 承认边界，并给出下一步验证，而不是伪造确定性。

**完成证据**：一个可运行切片 + README/ADR/测试/性能报告/事故复盘 + 模拟答辩录像或文字稿。

### 16｜组件实例、生命周期与源码

**生产问题**：setup 期间依赖注入错位；props/attrs/slots 边界混乱；异步 setup 在卸载后提交；生命周期重复注册；组件资源 owner 不清。

**必须掌握**：

- `createComponentInstance → setupComponent → setupStatefulComponent → handleSetupResult → finishComponentSetup`；
- instance 的 vnode、type、parent/root、scope、props、attrs、slots、setupState、proxy、subTree；
- public proxy 与 access cache，为什么内部字段不是业务 API；
- currentInstance、effectScope、生命周期注入和 error handling；
- emit、fallthrough attrs、provide/inject、async setup 与 Suspense 接口。

**完成证据**：固定 v3.5.42 的组件创建调用链 + 一次 props/attrs/lifecycle 所有权事故复现与回归测试。

### 17｜响应式系统源码精读

**生产问题**：动态依赖没有清理；computed 重复或过早计算；Map/Set/数组触发行为被误判；effect 泄漏；批处理中读到错误阶段。

**必须掌握**：

- Dep、Link、Subscriber 双向链与 version；
- activeSub、shouldTrack、track/trigger、prepare/cleanup deps；
- reactive handlers、array instrumentations、collection handlers；
- ref、computed 的 dirty/version/globalVersion；
- batch、watch、effectScope 与 cleanup 边界。

**完成证据**：真实源码插桩 trace + 动态分支、computed cache、collection 与 stop/scope 的确定性测试。

### 18｜SFC 与编译器源码精读

**生产问题**：宏只在编译期存在却被当运行时函数；模板优化信息丢失；scoped CSS/SSR source map 问题难定位；自定义编译检查误伤合法模板。

**必须掌握**：

- compiler-sfc 的 descriptor、compileScript、compileTemplate、compileStyle；
- compiler-core 的 parse → AST → transform → codegen；
- `v-if`/`v-for`、expression scope、helper、hoist；
- patch flags、block、dynamicChildren 怎样把静态知识交给 runtime；
- source map、错误位置、自定义 transform 的私有边界。

**完成证据**：一个 SFC 从源代码到生成代码的逐阶段档案 + 一个有位置、fixture 和负例的模板诊断实验。

### 19｜Renderer、Diff 与 Scheduler 源码

**生产问题**：错误 key 使本地状态串行；DOM 测量发生在错误阶段；父子更新顺序误判；递归更新；性能归因只看 Big-O。

**必须掌握**：

- `patch` 的 VNode type/shape 分派；
- `processComponent → mount/updateComponent → setupRenderEffect`；
- render effect 与 `queueJob` 的接缝；
- pre/component/post/nextTick、job 去重和异常清理；
- keyed children 五阶段、`newIndexToOldIndexMap`、LIS 与反向 anchor。

**完成证据**：old/new 列表完整手算 + 教学 tracer + Vue 状态保持测试 + scheduler phase/递归更新复现。

### 20｜内置组件、Router 与 Pinia 源码专题

**生产问题**：KeepAlive 离开后仍轮询；Teleport Modal 焦点和样式失效；Suspense 被误当 error boundary；旧导航回写；SSR store 跨用户污染。

**必须掌握**：

- KeepAlive cache/LRU、activate/deactivate/unmount；
- Teleport 的逻辑树/物理树、双锚点和 target move；
- async component 与 Suspense pending/resolve/error 的边界；
- Router matcher、guard pipeline、cancellation 与 finalize；
- Pinia instance/store registry、defineStore/useStore、actions、patch、SSR request scope。

**完成证据**：一个 built-ins 生命周期实验 + Router/Pinia 并发导航与 SSR 隔离测试；源码分别固定到 Vue 3.5.42、Router 5.3.0、Pinia 4.0.3。

## 学完后如何判断“高级”

高级不等于所有 API 都记住。面对陌生问题时，如果你能稳定执行下面的过程，才说明课程开始转化为能力：

1. 明确用户可见症状和失败损失；
2. 写出状态、资源、时序和信任边界；
3. 提出至少两个方案及不采用条件；
4. 用最小复现、测试、profile 或指标排除猜测；
5. 实现最小安全改动并保留回滚路径；
6. 用别人可复核的证据解释结果。

每章的题目都只是这个过程的载体。
