# 第 16 章：组件实例、生命周期与源码——Vue 组件究竟怎样“活起来”

> 源码基线：Vue Core `v3.5.42`，commit `d63616ca17de965ed32dcb449a4c5cd9982f15d2`。本章只把固定版本内部实现用于解释和排障；业务代码不得依赖私有 instance 字段、内部枚举或 `runtime-core/src/*`。

## 0. 本章目标

“会写组件”与“理解组件运行时”之间差了一层关键模型。学完后你应能回答：

1. 组件 VNode、组件定义、组件 instance 和 public instance 分别是什么？
2. `props`、`attrs`、`slots`、`emit` 在什么时候初始化，谁拥有它们？
3. `setup()` 返回对象或 render function 时，Vue 分别怎样处理？
4. 模板中的 `count` 为什么能依次访问 setup state、data、props、ctx？
5. `getCurrentInstance()` 为什么只在特定同步上下文可靠？
6. 生命周期 hook 为什么必须在 setup 同步阶段注册？
7. provide/inject 怎样沿逻辑组件树查找，为什么 Teleport 不影响它？
8. async setup、Suspense、KeepAlive 和 errorCaptured 怎样改变生命周期？
9. 一个组件卸载后，哪些响应式 effect 会自动停止，哪些外部资源不会？

目标是建立“实例是资源所有权边界”的模型，不是背一张生命周期图。

## 1. 事故钩子：弹窗关了，监听器却越来越多

一个第三方地图组件：

```ts
export default {
  async setup() {
    await loadMapSdk()
    const instance = getCurrentInstance()

    window.addEventListener('resize', resizeMap)
    onUnmounted(() => {
      window.removeEventListener('resize', resizeMap)
    })

    return { instance }
  },
}
```

开发环境出现警告：`onUnmounted is called when there is no active component instance`。弹窗每开一次就多一个 resize listener。

问题不是生命周期 API 偶发失效。调用链告诉我们：Vue 只在执行同步 `setup()` 时设置 current instance；async setup 遇到第一次 `await` 后，后续 continuation 不再天然处于该同步实例上下文。hook 应在 await 前注册，资源引用在异步完成后填入：

```ts
setup() {
  let disposed = false
  let cleanup: (() => void) | undefined

  onUnmounted(() => {
    disposed = true
    cleanup?.()
  })

  void loadMapSdk().then(sdk => {
    if (disposed) return
    cleanup = mountMap(sdk)
  })
}
```

这正是源码阅读的价值：把“不要在 await 后注册 hook”还原为 current instance 与所有权的因果关系。

## 2. 四个容易混淆的对象

| 对象 | 例子 | 生命周期 |
| --- | --- | --- |
| component definition/type | `defineComponent({...})` 返回值 | 通常被模块复用，不等于一次挂载 |
| component VNode | `h(UserCard, { id: '42' })` | 父组件每次 render 可产生新 VNode |
| internal instance | runtime 创建，持有 uid/props/scope/subTree | 从 mount 到真正 unmount |
| public instance/proxy | template ref 或 Options API `this` 看见的表面 | 受 expose/publicPropertiesMap 约束 |

一个组件 definition 可以同时挂载 100 次，每次都有独立 internal instance。更新时父 render 创建新 component VNode，但 type+key 相同通常复用旧 instance。

```text
Component definition: TicketRow
  ├─ VNode key=A → instance uid=10 → subTree A
  ├─ VNode key=B → instance uid=11 → subTree B
  └─ VNode key=C → instance uid=12 → subTree C
```

不要把模块单例变量当 instance state：

```ts
// 错：所有 TicketRow 实例共享
let draft = ''

export default defineComponent({
  setup() {
    // 对：每次 setup 创建属于该实例的 ref
    const draft = ref('')
    return { draft }
  },
})
```

## 3. 源码地图与主调用链

固定版本入口：

- [`component.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/component.ts)：instance、setup 主线；
- [`componentProps.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/componentProps.ts)：props/attrs 分类与更新；
- [`componentSlots.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/componentSlots.ts)：slots normalize/update；
- [`componentPublicInstance.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/componentPublicInstance.ts)：public proxy 与 access cache；
- [`componentEmits.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/componentEmits.ts)：emit 校验、handler、once；
- [`apiLifecycle.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/apiLifecycle.ts)：hook injection；
- [`apiInject.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/apiInject.ts)：provide/inject；
- [`componentRenderUtils.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/componentRenderUtils.ts)：render root 与 fallthrough attrs；
- [`renderer.ts`](https://github.com/vuejs/core/blob/v3.5.42/packages/runtime-core/src/renderer.ts)：mount/update/unmount instance。

普通同步 stateful component 的主路径：

```text
renderer.mountComponent
  → createComponentInstance(vnode, parent, suspense)
  → setupComponent(instance)
    → initProps
    → initSlots
    → setupStatefulComponent
      → 创建 public proxy
      → setCurrentInstance(instance)
      → instance.scope.on()
      → call setup(shallowReadonly(props), setupContext)
      → reset current instance / scope.off()
      → handleSetupResult
        ├─ function → instance.render
        └─ object   → proxyRefs → instance.setupState
      → finishComponentSetup
  → setupRenderEffect
```

阅读时先走这条主路，再分别插入 async setup、functional component、SSR、runtime compiler、KeepAlive。

## 4. `createComponentInstance`：先建立空壳与父子关系

一个 internal instance 包含大量字段，可按职责分组，而不是整表背诵：

```text
身份/拓扑：uid, vnode, type, parent, root, appContext
渲染：render, subTree, update, job, next, proxy
输入：propsOptions, emitsOptions, props, attrs, slots
setup：setupState, setupContext, exposed, exposeProxy
响应式：scope, effect
生命周期：bm/m/bu/u/bum/um/a/da/ec/sp
异步：suspense, asyncDep, asyncResolved
状态：isMounted, isUnmounted, isDeactivated
依赖注入：provides
```

字段缩写是内部压缩选择，不是业务 API。建立分组的意义是排障：

- props 不更新：看 vnode/next/props update；
- 重复 effect：看 scope 与真正 unmount；
- KeepAlive 页面：看 isDeactivated 而不只 isUnmounted；
- async setup：看 asyncDep/asyncResolved/Suspense；
- template ref 暴露过多：看 exposed/exposeProxy。

### 4.1 `appContext` 与全局配置

根组件继承 app context，后代沿组件树拿到 globalProperties、components、directives、provides、option caches 等。不要在应用之间复用同一个 app context；SSR 每请求创建 app 的原因之一就在这里。

### 4.2 `provides` 的延迟分叉

子 instance 初始可以引用 parent provides。第一次 `provide` 时才创建以 parent provides 为 prototype 的新对象：

```text
root provides
  ↑ prototype
layout provides
  ↑ prototype
ticket page provides
```

inject 从当前逻辑父链查找最近 key。它不是全局 Map，也不按物理 DOM 查询。

## 5. `setupComponent`：先分输入，再运行用户代码

主步骤：

```ts
initProps(instance, vnode.props, isStateful, isSSR)
initSlots(instance, vnode.children, optimized)
return isStateful ? setupStatefulComponent(instance, isSSR) : undefined
```

顺序很重要：setup 执行时 props 与 slots 已可使用。

### 5.1 raw props 怎样分到 props 与 attrs

组件声明的 prop key 进入 `props`；符合 emit listener 的 key 不作为普通 attr fallthrough；其余进入 `attrs`。

```vue
<UserCard
  :user-id="id"
  class="compact"
  data-track="profile"
  @save="save"
  @click="auditClick"
/>
```

若组件声明 `userId` prop 与 `save` emit：

```text
props: userId
emit listener: onSave
attrs: class, data-track, onClick（除非 click 也声明 emit）
```

这解释了为什么 emits 不只是 TypeScript 文档：它还影响 listener fallthrough 归类。

### 5.2 props 只读不等于深层冻结

setup 在开发模式接收 shallow readonly props。子组件不能写 `props.user = ...`，但对象内部仍是父拥有的引用。子组件修改 `props.user.name` 仍会造成隐式父状态变更。

正确契约：emit 意图或复制为本地 draft，再明确提交。

### 5.3 Boolean/default casting

`resolvePropValue` 处理 default factory、Boolean casting 等。不要在 wrapper 中手工再实现一套不一致规则。对象/数组 default 应使用 factory，且 default 不是后端 schema 验证。

### 5.4 slots 是函数协议

slots normalize 后按函数调用。父决定 slot 内容的响应式依赖和作用域，子决定调用位置。不要在 setup 顶层一次调用 slot 后长期缓存 VNode：它会绕开正常 render 时机和更新语义。

## 6. `setupStatefulComponent`：建立 public proxy 与同步上下文

### 6.1 public proxy

instance proxy target 持有内部 instance 引用，Proxy handlers 决定模板/Options API `this` 的读取：

```text
setupState → data → props → ctx → public properties → globalProperties
```

精确优先级存在内部细节；重要的是重名会制造歧义。不要让 prop、setup return、data、global property 使用同名 key。

### 6.2 access cache

模板 render 会反复读取相同 key。若每次都对 setupState/data/props/ctx 做多次 `hasOwn`，热路径成本很高。固定版本使用 access cache 记录某个 key 上次来自哪个桶。

```text
第一次读 `count`：检查 setupState → 命中 → cache SETUP
后续读 `count`：直接从 setupState 取
```

这是一项实现优化，不表示业务可以运行时随意改变某 key 的来源。动态往 ctx/props 塞同名字段会与 cache 和可维护性冲突。

### 6.3 setCurrentInstance 与 scope

在调用 setup 前：

```text
currentInstance = instance
instance.scope.on()
```

调用结束后 reset。这样 setup 内调用 `inject`、`onMounted`、`watchEffect` 等，能关联到正确 instance/scope。

`getCurrentInstance` 是高级库/调试工具，不应替代 props/inject/composable 参数。把 internal instance 长期暴露到业务层会造成私有耦合。

## 7. setup context：attrs、slots、emit、expose

```ts
setup(props, { attrs, slots, emit, expose }) {
  // ...
}
```

### 7.1 attrs

attrs 是非 props 输入。不要解构后假定它像普通 ref 一样被 watch：

```ts
const { class: className } = attrs // 只是当前读取结果
```

wrapper 组件要定义明确转发策略：

```vue
<script setup lang="ts">
defineOptions({ inheritAttrs: false })
</script>

<template>
  <label class="field">
    <span>{{ label }}</span>
    <input v-bind="$attrs" />
  </label>
</template>
```

`class/style` 合并、listeners、安全敏感 attributes 和多 root 都需要测试。

### 7.2 emit

emit 根据组件 emits options 在开发模式校验，并按事件名寻找 handler；model listeners 还处理 modifiers。事件不会像原生 DOM 事件那样自动冒泡穿过组件树。

命令型事件应带明确 payload：

```ts
const emit = defineEmits<{
  save: [payload: { id: string; revision: number }]
  close: [reason: 'escape' | 'backdrop' | 'submit']
}>()
```

### 7.3 expose

组件默认应保持内部私有。只有父级 template ref 真正需要的命令才 expose：

```ts
defineExpose<{ focus(): void; validate(): Promise<boolean> }>({
  focus: () => input.value?.focus(),
  validate,
})
```

不要 expose store、内部 refs 和 DOM 结构，让父组件远程操纵所有实现细节。

## 8. `handleSetupResult`

### 8.1 返回函数

setup 返回 function 时，它成为 render function：

```ts
setup(props) {
  return () => h('p', props.message)
}
```

### 8.2 返回对象

对象经 `proxyRefs` 进入 `instance.setupState`，因此模板可直接写 `count` 而不是 `count.value`：

```ts
setup() {
  const count = ref(0)
  return { count }
}
```

`proxyRefs` 是访问便利，不改变 JavaScript/TypeScript 文件中 ref 的真实类型；在 composable 或普通函数中仍应明确 `.value`。

### 8.3 其他返回值

Promise 表示 async setup；非 object/function 的普通值没有可用 setup state，开发环境会警告。不要依靠隐式容错。

---

## 9. `finishComponentSetup`：确定 render function

若 setup 没返回 render function，Vue 使用组件已有 render；在带 runtime compiler 的构建中，可能把 template 编译为 render。预编译 SFC 通常在构建时已经产生 render。

生产应用优先 runtime-only + build-time compiler：

- bundle 更小；
- CSP 更容易；
- 编译错误提前；
- compiler 可做静态优化；
- 不接受服务端不可信字符串作为 template。

“运行时动态模板”不是低代码系统的安全捷径。Vue 模板可执行表达式，不可信 template 等同代码执行边界。

## 10. `renderComponentRoot` 与 fallthrough attrs

组件 render 后得到 root VNode。runtime 可能把 attrs 克隆/合并到单一 root element 或 component 上。多 root Fragment 无法猜测目标，通常要求显式绑定。

事故案例：

```vue
<template>
  <label>...</label>
  <p class="help">...</p>
</template>
```

父传 `id`、`aria-describedby`、`@focus`，Vue 不知道应给 label、input 还是 help。高级组件不能只靠默认 fallthrough；应把公开 attribute target 写入契约。

model listener 若对应声明 prop，render utils 会避免它错误 fallthrough 到 DOM root。这再次说明 props/emits 声明参与运行时行为。

## 11. 生命周期 hook 如何注册与调用

`onMounted(hook)` 最终把包装后的 hook 推入当前 instance 对应数组。包装器：

- 调用期间暂停依赖追踪；
- 临时设置 current instance；
- 经统一 async error handling 执行；
- 完成后 reset current instance 和 tracking。

### 11.1 为什么暂停 tracking

生命周期 hook 可能在一个 effect 的执行上下文附近被调用。hook 中偶然读取的响应式值不应错误成为外层 render effect 依赖。

### 11.2 注册时机

必须在 setup 同步执行期间注册：

```ts
onMounted(() => {
  // hook 本身以后运行
})

await something()
// 此处再 onUnmounted 可能已没有 active instance
```

可以在 await 前注册一个闭包；闭包内部以后读取已经赋值的资源。

### 11.3 mount/update/unmount 的核心阶段

```text
beforeMount
render + patch subtree
mounted（post-render）

state/props invalidated
beforeUpdate
render + patch old/new subtree
updated（post-render）

beforeUnmount
stop component effect/scope + unmount subtree
unmounted（post-render）
```

不要在 updated 中无条件写本次 render 读取的状态，否则可能递归更新。

## 12. Effect Scope 与资源所有权

setup 同步创建的 watchers/computed effects 会进入 instance scope，真正 unmount 时 scope stop。自动停止不覆盖所有资源：

| 资源 | Vue scope 自动处理？ | 你的责任 |
| --- | --- | --- |
| setup 同步创建的 watch/effect | 通常是 | 避免异步晚创建逃逸 scope |
| `setInterval` | 否 | clearInterval |
| DOM/window listener | 否 | removeEventListener |
| fetch | 否 | AbortController + stale guard |
| WebSocket | 否 | unsubscribe/close |
| Mutation/ResizeObserver | 否 | disconnect |
| 第三方 widget | 否 | destroy |
| module-level singleton subscription | 否 | 显式 owner/ref count |

危险写法：

```ts
setTimeout(() => {
  watch(source, callback) // 创建时可能已经不在组件 scope
}, 1000)
```

若确需异步创建，保存 stop handle 并在卸载状态下拒绝创建。

KeepAlive deactivated 不 stop instance scope，因为实例要恢复。需要暂停的资源应同时处理 `onActivated/onDeactivated`。

## 13. Provide/Inject：依赖解析，不是服务定位器滥用

类型安全 key：

```ts
export interface Analytics {
  track(event: { name: string; ticketId?: string }): void
}

export const analyticsKey: InjectionKey<Analytics> = Symbol('analytics')
```

provider：

```ts
provide(analyticsKey, analytics)
```

consumer：

```ts
const analytics = inject(analyticsKey)
if (!analytics) throw new Error('Analytics provider is required')
```

要决定 missing provider 是 fail fast、默认 no-op 还是 optional。不要让业务深处到处 `inject(...)!`。

如果提供 reactive object，默认由 provider 拥有 mutation；可提供 readonly state + commands，避免任意后代改内部字段。

Teleport 改变 DOM 位置，不改变 component parent；inject 仍沿逻辑组件树。微前端若是另一个 Vue app，则 app context 边界不同，不能想当然共享。

## 14. Async setup 与 Suspense

async setup 返回 Promise，instance 保存 async dependency。renderer 若有 parent Suspense，会注册依赖；未解析时可能使用 placeholder。完成后 `handleSetupResult` 与正常 render effect 才继续。

关键边界：

- hook 在第一次 await 前注册；
- Promise 完成时组件可能已经卸载；
- Suspense 协调 pending，不等于捕获所有错误；
- SSR 的 async setup 还影响 server render；
- 不要把每个组件都变 async setup，数据获取通常应由 route/query 边界治理。

更易测试的写法：setup 同步建立状态与 cleanup，再启动显式 async task。

---

## 15. ErrorCaptured 与错误传播

render、event handler、lifecycle、watch callback 等由 runtime 的 error handling 路径标注来源。`onErrorCaptured` 可沿父链观察/处理错误；返回 `false` 可停止继续传播到更高层（应按当前公开文档核对）。app-level `errorHandler` 是最后观测点之一。

错误边界 UI 要避免自身再次抛错，并区分：

- 用户可恢复错误：显示 retry；
- 权限/404：进入确定路由状态；
- programmer error：记录版本、component trace、request id，提供安全 fallback；
- secret/PII：不得进入日志。

错误捕获不自动回滚已发生的外部副作用。

## 16. 组件更新与 props/slots

父 render 产生新 component VNode 后，renderer 用 `shouldUpdateComponent` 判断是否需要子 render。需要时 `instance.next = nextVNode`，在更新前：

```text
updateProps
updateSlots
flush 当前实例 pre watchers
renderComponentRoot
patch oldSubTree/newSubTree
```

因此 props watcher 的时序与 DOM watcher 不同。默认 pre watcher 可在子 render 前看到新 prop，但子 DOM 仍旧；读新 DOM 用 post。

props 稳定性会决定能否跳过子 render：父不要把整个不断变化的大对象都传给所有行；先计算每行真正需要的稳定字段。

---

## 17. Public Instance 与 Template Ref

父通过 template ref 拿到的是 public surface，不应拿 internal instance：

```vue
<script setup lang="ts">
const editor = useTemplateRef<{
  focus(): void
  validate(): Promise<boolean>
}>('editor')
</script>

<template>
  <TicketEditor ref="editor" />
</template>
```

`defineExpose` 应最小化。更松耦合的交互优先 props/events/model；template ref 适合 focus、measure、imperative third-party bridge 等确实命令式的边界。

## 18. 调试路径

### 18.1 hook 警告没有 active instance

检查注册是否发生在：

- setup 的 await 后；
- 普通模块顶层；
- 事件回调中才第一次调用 composable；
- timer/Promise continuation 中；
- 被手工直接调用的 composable，且没有组件/active scope。

### 18.2 attrs 没落到目标元素

检查：

- 多 root；
- `inheritAttrs: false` 后是否显式绑定；
- emits 是否改变 listener 分类；
- wrapper 是否把 attrs 绑定到错误内部节点；
- Teleport 后测试查询的是否真实 DOM。

### 18.3 组件卸载后仍工作

记录 instance uid/key、mounted/deactivated/unmounted、scope cleanup 和外部 handle 数量。先判断只是 deactivated，还是 watcher 异步创建逃出 scope，或 module singleton 根本不属于组件。

### 18.4 setup state 模板读不到

检查 setup 是否返回 object、是否重名、是否返回 Promise 未被正确协调、是否在 `<script setup>` 与普通 setup 之间误用 expose、是否把 ref 放入 markRaw 容器。

## 19. 源码实验安全规则

1. clone 固定 `v3.5.42`，记录 commit；
2. 第一次只插桩普通同步组件路径；
3. 使用官方 tests 或最小 custom renderer/VTU fixture；
4. 插桩写入开发 fork，不进产品依赖；
5. 结论写“public behavior / v3.5.42 implementation / open question”；
6. 不截图代替可运行测试；
7. 版本升级后重新跑，而不是假定内部不变。

1. definition 可复用；VNode 每轮产生；instance 跨更新复用；public proxy 是受控表面。
2. create instance 后，先 init props/slots，再同步运行 setup。
3. setup 返回 function 是 render；返回 object 经 proxyRefs 成为 setupState。
4. public proxy 用 access cache 加速 setup/data/props/ctx 查找。
5. current instance 与 instance scope 只在受控同步上下文打开。
6. 生命周期必须在 setup 同步阶段注册；hook 本身以后执行。
7. 真正 unmount 会 stop instance scope；timer/listener/fetch/widget 仍需手工 cleanup。
8. KeepAlive deactivate 不等于 unmount。
9. provide/inject 沿逻辑组件树，与 Teleport 物理位置无关。
10. props/emits 声明会影响 attrs/listener runtime 分类。
