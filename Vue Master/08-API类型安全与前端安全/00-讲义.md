# 第 08 章：API 类型安全与前端安全

## API 层不是 axios 包一层

企业 API 边界至少包含 transport、schema/DTO、domain mapping、repository/query 四层。transport 处理 base URL、超时、request id 和网络错误；schema 做 runtime validation；mapper 把 DTO 变成领域模型；repository 表达 `ticketRepo.assign(id, owner)` 这样的业务意图。

OpenAPI 可生成 client 和类型，但生成代码属于基础设施，不应直接渗入每个组件。规范变更要在 CI 检测 diff；运行时仍要防后端异常响应。错误建模区分 validation、unauthorized、forbidden、conflict、rate-limit、network、unknown，UI 才能做正确恢复。

## 鉴权与刷新

多个请求同时 401 时，只能有一个 refresh 请求，其余等待；refresh 失败统一退出；原请求最多重放一次，避免无限循环。若使用 cookie，关注 SameSite、Secure、HttpOnly 与 CSRF；若 token 暴露在 JS，XSS 可窃取。不存在“放 localStorage 就天然安全”。方案必须结合后端与威胁模型。

## Vue 安全边界

Vue 默认转义文本和属性，但 `v-html`、动态模板、危险 URL、第三方 DOM 库会重新打开 XSS。永远不要把用户输入当 Vue template 编译。富文本必须使用可信 sanitizer 和明确 allowlist。前端环境变量会进入 bundle，不是秘密。

还要关注依赖供应链、CSP、点击劫持、文件上传、CSV 注入、敏感日志与 source map 访问控制。
