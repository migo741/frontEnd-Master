# 第 08 章：API 类型安全与前端安全——所有边界都从 `unknown` 开始

> 本章不是教你封装一个“万能 axios”。目标是建立可靠边界：请求可取消、响应可验证、错误可判别、重试有条件、认证可收敛，且前端从不越权承担后端安全职责。

## 0. 事故现场：TypeScript 说是数组，线上却是 `null`

后端灰度时把 `items` 从 `[]` 临时返回成 `null`。前端写着：

```ts
const response = await fetch('/api/tickets')
const data = await response.json() as TicketListResponse
return data.items.map(renderTicket)
```

编译通过，线上白屏。`as TicketListResponse` 没有检查任何字节，只是要求编译器停止追问。随后错误拦截器见到 401 就重试，5 个并发请求各自刷新 token；刷新本身也 401，形成请求风暴。

可靠 API 层要理解四个事实：

1. 网络输入、URL、storage、`postMessage` 都是 `unknown`；
2. TypeScript 类型在运行时被擦除；
3. HTTP 成功、业务成功、数据有效是三件事；
4. 重试会重复副作用，除非操作本身幂等或带幂等键。

```text
untrusted bytes
  -> transport（状态码/超时/取消）
  -> parse（JSON/文本/文件）
  -> schema decode（运行时证据）
  -> error normalization
  -> repository DTO -> domain
  -> Vue/query/store
```

---

## 1. 边界模型：DTO 不等于领域对象

### 1.1 OpenAPI 生成类型解决“同步”，不自动解决“信任”

OpenAPI 可以生成 path、method、request 和 response 的 TypeScript 类型，减少手写漂移。但生成的接口本身仍只是静态描述：

- 实际服务可能部署错版本；
- 网关、代理、mock、第三方服务可能返回不同结构；
- 错误响应不一定遵循成功 schema；
- 前端缓存/持久化中可能残留旧数据。

高风险边界应运行时校验。可以从同一 schema 生成 validator，或手写 Zod/Valibot/ArkType 等 decoder；选型次于“校验确实执行”。

### 1.2 DTO 到 Domain 的防腐层

```ts
interface TicketDto {
  id: string
  title: string
  status: 'OPEN' | 'CLOSED'
  updated_at: string
  assignee: { id: string; display_name: string } | null
}

interface Ticket {
  id: TicketId
  title: string
  status: 'open' | 'closed'
  updatedAt: Date
  assignee: { id: UserId; displayName: string } | null
}

function toTicket(dto: TicketDto): Ticket {
  return {
    id: ticketId(dto.id),
    title: dto.title,
    status: dto.status === 'OPEN' ? 'open' : 'closed',
    updatedAt: parseIsoDate(dto.updated_at),
    assignee: dto.assignee
      ? { id: userId(dto.assignee.id), displayName: dto.assignee.display_name }
      : null,
  }
}
```

领域层不需要到处知道 snake_case、枚举兼容或日期字符串。转换失败应在 repository 边界暴露为协议错误，而不是在组件深处出现 `Invalid Date`。

## 2. 一个可判别的错误模型

不要让组件解析 `error.message.includes('401')`。定义有限错误族：

```ts
export type ApiError =
  | { kind: 'aborted'; reason?: unknown }
  | { kind: 'timeout'; timeoutMs: number }
  | { kind: 'network'; cause: unknown }
  | { kind: 'http'; status: number; requestId?: string; body?: unknown }
  | { kind: 'validation'; issues: readonly ValidationIssue[]; body: unknown }
  | { kind: 'problem'; status: number; code: string; detail?: string; fields?: FieldError[] }

export class ApiFailure extends Error {
  constructor(readonly detail: ApiError) {
    super(detail.kind)
    this.name = 'ApiFailure'
  }
}
```

分层含义：

- `aborted`：用户/路由已不关心，通常不弹错误；
- `timeout`：客户端预算耗尽，不代表服务端一定没执行；
- `network`：无 HTTP 响应，例如离线/DNS；
- `http`：非 2xx 且错误体未知；
- `validation`：响应与约定 schema 不符，是协议/部署事故；
- `problem`：已验证的标准业务错误，可映射到字段或冲突 UI。

错误对象不要默认保存完整响应体。它可能包含个人信息、服务端栈或恶意超大内容。日志只记录允许字段：request id、endpoint 模板、status、error code、duration、release。

### 2.1 HTTP 2xx 也可能解析失败

`fetch` 只在网络层失败时 reject；404/500 会 resolve。204 没有 JSON；下载接口是 blob；错误页可能是 HTML。解析策略必须由 endpoint 契约决定，而不是所有响应一律 `.json()`。

## 3. 可组合而非万能的 HTTP 边界

### 3.1 Decoder 接口

```ts
export interface Decoder<T> {
  decode(input: unknown):
    | { ok: true; value: T }
    | { ok: false; issues: readonly ValidationIssue[] }
}

export interface RequestOptions<T> {
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE'
  headers?: HeadersInit
  body?: unknown
  signal?: AbortSignal
  timeoutMs?: number
  decoder: Decoder<T>
  idempotencyKey?: string
}
```

### 3.2 合并调用方取消与 timeout

现代运行时可使用 `AbortSignal.timeout()` 和 `AbortSignal.any()`；若目标环境不完整，需要兼容实现。核心原则是：调用方 signal 与超时任一发生，都应取消 fetch，同时清理 timer/listener。

```ts
function composeAbort(
  callerSignal: AbortSignal | undefined,
  timeoutMs: number,
): { signal: AbortSignal; cleanup(): void; timedOut(): boolean } {
  const controller = new AbortController()
  let didTimeout = false

  const onCallerAbort = () => controller.abort(callerSignal?.reason)
  callerSignal?.addEventListener('abort', onCallerAbort, { once: true })
  if (callerSignal?.aborted) onCallerAbort()

  const timer = window.setTimeout(() => {
    didTimeout = true
    controller.abort(new DOMException('Timed out', 'TimeoutError'))
  }, timeoutMs)

  return {
    signal: controller.signal,
    timedOut: () => didTimeout,
    cleanup() {
      clearTimeout(timer)
      callerSignal?.removeEventListener('abort', onCallerAbort)
    },
  }
}
```

timeout 后服务端可能已经完成写入，因此“客户端超时 = 操作失败”并不成立。写接口需要幂等键或查询最终状态。

### 3.3 URL 与 body 编码

```ts
function buildUrl(path: string, query: Record<string, string | number | boolean | null>) {
  const url = new URL(path, API_BASE_URL)
  for (const [key, value] of Object.entries(query)) {
    if (value !== null) url.searchParams.set(key, String(value))
  }
  return url
}
```

不要字符串拼 `?q=${input}`；`URLSearchParams` 负责编码。但编码不等于服务端安全：服务端仍需参数化 SQL、路径授权等。

JSON body 只有在 endpoint 需要时设置；`FormData` 不要手工设置 `Content-Type`，浏览器需要附带 boundary。

## 4. Abort、重试与幂等

### 4.1 哪些请求能自动重试

| 情况 | 默认策略 |
|---|---|
| GET 网络抖动/502/503/504 | 有界指数退避 + jitter，可重试 |
| 429 | 尊重 `Retry-After`，有总预算 |
| 400/401/403/404/422 | 不做通用自动重试 |
| POST 创建 | 只有服务端支持幂等键才安全重放 |
| PATCH/DELETE | 取决于服务端幂等语义和版本条件 |
| validation error | 不重试，报警协议漂移 |

退避示意：

```ts
const delay = Math.min(capMs, baseMs * 2 ** attempt)
const withJitter = Math.random() * delay
```

必须有尝试次数或总时长预算，并服从 AbortSignal。不要让页面离开后重试继续占用资源。

### 4.2 幂等键

创建订单、提交任务等操作可由客户端生成幂等键：

```ts
const key = crypto.randomUUID()
await api.request('/orders', {
  method: 'POST',
  idempotencyKey: key,
  body: input,
  decoder: orderDecoder,
})
```

关键契约在服务端：同一身份、同一 endpoint、同一 key、同一语义请求必须返回同一已确认结果或明确冲突，并有合理过期窗口。客户端只有 header 而服务端不存去重记录，没有任何保证。

用户双击时，UI disable 是体验优化，幂等键才覆盖双击、超时重试、代理重放等路径。

## 5. 401 singleflight：所有失败请求共享一次恢复

假设使用短期 access credential，恢复由安全 cookie/认证端点完成。并发请求同时 401 时：

```text
R1 ─401─┐
R2 ─401─┼─> getRefreshPromise() ─> refresh once ─> retry each once
R3 ─401─┘                          │
                                  └ failure -> clear session once
```

必须防止：

- 刷新请求本身再次触发 401 拦截；
- 每个请求各刷新一次；
- 重放原请求无限循环；
- 用户在刷新期间 logout 后，旧刷新又把他登录回来；
- body 为一次性 stream 时无法重放；
- 非幂等请求在“服务端已执行但响应 401/超时”时重复执行。

简化协议：

```ts
let refreshPromise: Promise<void> | null = null
let authEpoch = 0

function refreshOnce(): Promise<void> {
  if (refreshPromise) return refreshPromise
  const epoch = authEpoch

  refreshPromise = authRepository.refreshWithoutInterceptor()
    .then(() => {
      if (epoch !== authEpoch) throw new Error('auth context changed')
    })
    .finally(() => { refreshPromise = null })

  return refreshPromise
}

function logout() {
  authEpoch++
  session.clear()
  queryClient.clear()
}
```

每个原请求最多标记一次 `retriedAfterAuth`。刷新失败统一清会话并触发一次登录流程，不让每个响应弹一个 toast。

如果使用 HttpOnly session cookie，不一定存在前端 refresh token；仍可能需要 singleflight `/session` 恢复或统一处理过期。

## 6. Web 安全：Vue 默认转义不是万能护盾

### 6.1 XSS 与 `v-html`

Vue 文本插值和动态 attribute 默认转义，下面的 `userText` 不会被当 HTML 执行：

```vue
<p>{{ userText }}</p>
```

`v-html` 明确绕过转义：

```vue
<!-- 只有经过可信、配置明确的 HTML sanitizer 的结果才可进入 -->
<article v-html="sanitizedHtml" />
```

规则：

- 永不对用户输入、Markdown 转 HTML 结果、第三方富文本直接 `v-html`；
- sanitizer 要指定允许标签/属性/URL scheme，升级并回归测试；
- 不接受 `javascript:`、危险 `data:` 或未知 scheme；
- 服务端也应清洗/验证存储内容，防存储型 XSS；
- CSP 是纵深防御，不是清洗的替代品。

不要用正则“删除 `<script>`”当 sanitizer。事件属性、SVG、URL、编码变体都可绕过朴素正则。

### 6.2 URL 安全

```ts
function safeExternalUrl(value: string): URL | null {
  try {
    const url = new URL(value)
    return url.protocol === 'https:' ? url : null
  } catch {
    return null
  }
}
```

外链用 `target="_blank"` 时加 `rel="noopener noreferrer"`；redirect 只允许内部路径或可信 origin 白名单。不要把用户 URL 直接赋给 iframe、script、CSS `url()`。

### 6.3 CSRF

当认证凭证由浏览器自动携带（Cookie）时，要考虑跨站请求伪造：

- Cookie 使用合适的 `SameSite`、`Secure`、`HttpOnly`；
- 状态变更用非 GET；
- 服务端校验 CSRF token，常见为同步 token 或 double-submit（具体按后端架构）；
- 可校验 `Origin/Referer` 作为额外防线；
- CORS 不是 CSRF 的完整替代品。

将 token 放 localStorage 避免 CSRF，却扩大 XSS 凭证窃取面；不存在一个前端存储技巧能替代整体威胁模型。

### 6.4 CSP

生产 CSP 可限制脚本、连接、frame、对象和上报目标。推荐逐步从 Report-Only 收集违规，再收紧 nonce/hash，减少 `'unsafe-inline'`。第三方脚本每加一个域都扩大供应链信任面。

CSP 需要服务端响应头配合；meta CSP 能力有限。前端工程师需要知道构建产物、动态样式和第三方 SDK 对策略的影响。

## 7. 上传：验证、进度、取消与资源预算

### 7.1 客户端检查只改善 UX

```ts
interface UploadPolicy {
  maxBytes: number
  acceptMime: ReadonlySet<string>
}

function validateFile(file: File, policy: UploadPolicy): string[] {
  const errors: string[] = []
  if (file.size > policy.maxBytes) errors.push('文件过大')
  if (!policy.acceptMime.has(file.type)) errors.push('文件类型不支持')
  return errors
}
```

`file.type` 和扩展名都可伪造，服务端必须检查实际内容、大小、配额、权限，按需要做病毒扫描和内容重编码。对象存储直传使用短期、限 key/大小/type 的签名，不把云密钥发给浏览器。

大文件采用分片上传时要设计：uploadId、part checksum、并发上限、暂停/恢复、完成提交、过期清理、幂等 part。Vue state 只保存展示所需元数据；不要把几百 MB Blob 放入深层 reactive store。

### 7.2 上传进度

浏览器 `fetch` 的上传进度能力取决于环境；生产项目可能使用 XHR 或支持流的实现。无论工具，状态机应明确：

```text
queued -> hashing -> uploading -> verifying -> success
                       ├-> paused
                       ├-> canceled
                       └-> error(retryable?)
```

取消后服务端可能已收到某些 part，需要 abort upload/过期回收。

## 8. 下载：不要把错误 JSON 当 PDF

```ts
async function downloadReport(id: string, signal: AbortSignal) {
  const response = await fetch(`/api/reports/${encodeURIComponent(id)}`, {
    credentials: 'include', signal,
  })

  const contentType = response.headers.get('content-type') ?? ''
  if (!response.ok) {
    const problem = contentType.includes('application/json')
      ? await safeJson(response)
      : undefined
    throw normalizeHttpError(response, problem)
  }

  if (!contentType.includes('application/pdf')) {
    throw new ApiFailure({ kind: 'validation', issues: [
      { path: 'content-type', message: `expected PDF, got ${contentType}` },
    ], body: null })
  }

  const blob = await response.blob()
  const url = URL.createObjectURL(blob)
  try {
    const anchor = document.createElement('a')
    anchor.href = url
    anchor.download = safeFilenameFromHeader(response.headers) ?? 'report.pdf'
    anchor.click()
  } finally {
    URL.revokeObjectURL(url)
  }
}
```

`Content-Disposition` 文件名来自网络，不能当路径或 HTML；要移除控制字符、路径分隔符并给默认值。超大下载优先服务端签名 URL/流式处理，避免整个 Blob 占用内存。

## 9. Vue 集成边界

组件不应知道 401 恢复、DTO、schema、request id：

```text
Component
  -> useMutation/useQuery（loading/cache/cancel）
  -> TicketRepository（endpoint 语义、DTO/domain）
  -> ApiClient（transport、decode、error）
  -> fetch
```

表单错误映射：

- `problem.code` 决定全局提示/冲突 UI；
- `fields` 只映射到已知字段，未知字段记录协议漂移；
- 401 由认证协调层处理；
- 403 不等于重新登录；
- 422 不弹“系统异常”，应显示可行动反馈；
- validation error 属于工程告警，用户看到稳定降级文案。

错误边界不应吃掉 Abort；否则路由切换会弹“请求失败”。

## 10. 测试与排障

API 层至少需要：

- decoder 对合法/缺字段/null/超大/额外字段策略的测试；
- 204、JSON、非 JSON 错误、下载的 content-type 分支；
- caller abort、timeout、二者竞态与 listener cleanup；
- GET 重试预算、429 `Retry-After`、POST 不盲重试；
- N 个并发 401 只 refresh 一次且各最多 replay 一次；
- refresh 失败只 logout/通知一次；
- logout 与 refresh 竞态的 epoch 测试；
- 富文本 sanitizer 的攻击样本回归；
- redirect scheme/origin 测试；
- 上传取消、分片失败恢复、服务端拒绝伪造 MIME；
- 下载错误 JSON 不保存成文件、Object URL 被 revoke。

排障记录一个 `requestId/correlationId`，前端日志只记 endpoint 模板而非完整 URL。先分清：network、timeout、abort、HTTP、业务 problem、schema validation；否则“接口失败”永远无法定位。

## 11. 反例速查

| 反例 | 问题 | 正确方向 |
|---|---|---|
| `json() as T` | 零运行时证据 | unknown + decoder |
| 所有响应都 `.json()` | 204/文件/HTML 出错 | endpoint 解析契约 |
| 任意错误重试 3 次 | 重复副作用/风暴 | 幂等分类 + 有界预算 |
| 每个 401 各自 refresh | 惊群、token 竞态 | singleflight + replay once |
| refresh 也走同一 401 interceptor | 递归循环 | 独立裸请求路径 |
| token/敏感 state 放 localStorage | XSS 可读 | HttpOnly cookie 等整体设计 |
| 用户富文本直接 `v-html` | 存储型 XSS | 成熟 sanitizer + CSP |
| 正则删 `<script>` | 容易绕过 | 解析器型 sanitizer |
| CORS 当 CSRF 防护 | 威胁模型错误 | SameSite + token + Origin |
| 只信 MIME/扩展名 | 可伪造 | 服务端内容验证 |
| 不 revoke Object URL | 内存泄漏 | finally revoke |

## 12. 速记与自检

> 类型安全不是“我声明它是什么”，而是“不可信值通过运行时证据后，才进入领域系统”。

1. OpenAPI 生成类型与运行时 schema 验证分别解决什么？

4. timeout 为什么不能证明写操作没发生？
5. 哪些请求默认可重试，POST 何时可重放？
6. 401 singleflight 要防哪四类循环/竞态？
7. `v-html` 绕过了 Vue 的什么保护？
