# 版本策略与一手资料

> 本页是 2026-09-02 的快照。版本号会过期，分层原则不会：稳定版进入主线，稳定但场景化的能力按需使用，预发布能力隔离试验。

## 当前版本判断

Vue Core 官方 release 页在本次调研时显示：

- 最新稳定线为 Vue `3.5.42`；
- Vue `3.6.0-rc.6` 仍标记为 pre-release；
- 3.6 的重要方向包括基于 alien-signals 的响应式重构和 Vapor Mode；
- Vapor 是完全 opt-in，支持 Vue API 的一个子集；依赖 VNode 或组件公开实例代理的部分能力不可用；官方 RC 说明建议的场景也是局部性能敏感页面或小型新应用。

因此本课程的代码和毕业项目使用 3.5.x 稳定语义。第 14 章可以做 Vapor 隔离分支实验，但不得把它放到鉴权、支付、核心数据编辑或无法快速回滚的关键路径。

本次核对的官方生态稳定版本：Vue Router `5.3.0`、Pinia `4.0.3`、Vite `8.2.2`。课程源码章分别固定到 Vue `v3.5.42` commit `d63616c`、Router `v5.3.0` commit `0e91ac8`、Pinia `v4.0.3` commit `5d6ac5b`；不能用各仓库 `main` 分支代替固定阅读坐标。

核对入口：[Vue Core Releases](https://github.com/vuejs/core/releases)、[Vue 3.5 发布说明](https://blog.vuejs.org/posts/vue-3-5)。

## 三类技术清单

### 稳定必修

- Composition API 与 `<script setup lang="ts">`；
- `ref`、`reactive`、`computed`、watchers、effect scope；
- Vue 3.5 的响应式 props 解构、`useTemplateRef`、`onWatcherCleanup`；
- SFC 宏、组件契约、slots、provide/inject、custom directives 与 plugins；
- `Transition`、`TransitionGroup`、`KeepAlive`、`Teleport`；
- Vue Router 5.3 的导航守卫、数据加载、typed routes 与导航失败；
- Pinia 4.0 的 state/actions/plugins/testing/SSR；
- Vite 8.2 的 plugin、环境变量、构建诊断；
- Vue Test Utils 2、Vitest、MSW、Playwright；
- Vue SSR 基础、hydration 一致性与请求隔离；
- 性能、安全、可访问性和可观测性。

### 条件必修

- `Suspense`：官方文档仍把它标为 experimental；课程讲清协调异步依赖的模型，但生产使用必须做版本、错误与 fallback 验证；
- Nuxt 4：需要 SSR、SEO、hybrid rendering 或 server routes 时深学；纯后台 SPA 不必为了简历强上；
- Monorepo/library mode：多个可独立发布包或明确团队边界时使用；
- Design System：跨产品复用和演进成本真实存在时建设；
- microfrontend/custom elements：自治团队、独立发布或渐进迁移收益足以覆盖运行时与治理成本时使用。

### 前沿观察

- Vue 3.6 RC；
- Vapor Mode 与 VDOM/Vapor interop；
- 任何只在 pre-release、实验插件或尚未验证的编译模式中存在的行为。

前沿项的学习交付物是“实验报告”，不是“默认架构”：必须记录版本、支持 API、基准、兼容性、失败方式和删除开关。

## 季度维护流程

每三个月执行一次，控制在 60～90 分钟：

1. 打开 Vue Core Releases，记录稳定版和 pre-release 的变化；
2. 检查 Vue Router、Pinia、Vite、Nuxt、VTU 的 migration/release note；
3. 在练习项目创建升级分支，执行 typecheck、unit/component/E2E、SSR 和 production build；
4. 对性能敏感路径重跑固定数据和固定设备基准；
5. 只有稳定、收益明确、可回滚的变化才合并到主线；
6. 更新本页日期，并说明“为什么改”，不要只改版本号。

## 向 AI 追问时怎样提供上下文

一个高质量追问至少包含：

```text
Vue / Router / Pinia / Vite / Nuxt 的确切版本：
运行环境（SPA、SSR、Nuxt、测试、生产构建）：
最小代码：
期望行为：
实际行为与完整警告/堆栈：
触发顺序：
我目前对 track/queue/lifecycle/request scope 的理解：
已经排除的假设：
```

要求 AI 区分三件事：官方承诺的语义、根据源码/现象做出的推断、需要你在当前版本实测的结论。这样比问“为什么 watch 不生效”更容易得到可靠解释。
