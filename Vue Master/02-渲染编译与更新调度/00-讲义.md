# 第 02 章：渲染、编译与更新调度——解释每一次 DOM 变化

> 本章稳定基线为 Vue 3.5.x。目标不是背 diff 源码，而是能从模板、VNode、调度队列一直追到最终 DOM，并能设计正确的渲染边界。

## 0. 事故钩子：列表没丢数据，输入框却串行了

一个可编辑订单列表使用数组下标作 key：

```vue
<OrderRow
  v-for="(order, index) in orders"
  :key="index"
  :order="order"
/>
```

用户在第二行输入未保存备注，服务端推送把一条新订单插到顶部。订单数据正确，第二行组件内部草稿却“附着”到了另一张订单。

根因不是表单，也不是响应式，而是**身份错误**：key 告诉 renderer“位置 1 的旧组件就是位置 1 的新组件”。Vue 忠实复用了错误身份。

高级排障应沿着完整链路：

```text
SFC template
  ↓ compiler：静态分析、生成 render function 与优化提示
render function(state)
  ↓ 创建 VNode 树（本次期望的 UI 描述）
scheduler
  ↓ 批处理并运行组件 render effect
renderer.patch(oldVNode, newVNode)
  ↓ mount / update / move / unmount
真实 DOM 与组件实例
```

## 1. 术语与层次

| 术语 | 精确定义 |
| --- | --- |
| template compiler | 把模板转换成 render function，并注入静态信息 |
| render function | 输入当前响应式状态，返回 VNode 的函数 |
| VNode | 对元素、组件、文本、Fragment 等节点的 JavaScript 描述 |
| renderer | 把新旧 VNode 差异提交到宿主平台；浏览器 renderer 操作 DOM |
| patch | 让已挂载结果从旧 VNode 表达的状态变为新 VNode 状态 |
| patch flag | 编译器告诉运行时“这个节点哪些部分可能动态变化”的位标记 |
| block tree | 编译器组织的动态后代索引，帮助运行时跳过稳定子树 |
| component instance | 组件的一次挂载实例，持有 props、scope、subTree、生命周期等 |
| scheduler job | 延后、去重并按约束执行的更新任务 |
| key | 同一父节点下跨两次渲染识别 VNode 身份的业务标识 |

虚拟 DOM 不是“复制 DOM”，也不保证任何情况下都比手写 DOM 快。Vue 的关键优势是：模板可静态分析，编译器把大量“不会变”或“只变某一处”的知识传给运行时。

## 2. 模板如何成为 render function

模板：

```vue
<section class="profile">
  <h2>{{ user.name }}</h2>
  <p>Account overview</p>
</section>
```

概念化后的 render function：

```ts
function render(context: { user: { name: string } }) {
  return h('section', { class: 'profile' }, [
    h('h2', null, context.user.name),
    h('p', null, 'Account overview'),
  ])
}
```

实际编译结果会有更具体的 helper、block 和 patch flag。重要的是编译器知道：

```text
section.class       静态
p 及其文本          静态，可提升/跳过
h2 的文本           动态，只需更新 TEXT
```

### 2.1 三类典型优化

1. **静态提升**：不会随 render 变化的 VNode/props 可移出 render 热路径。
2. **patch flags**：运行时直接更新动态 class、style、props 或 text，而非逐项全比较。
3. **block tree**：block 记录动态后代；父层重跑时可遍历动态列表，跳过稳定节点。

简化图：

```text
Block <section>
├─ <h2> {{ user.name }}   ← dynamicChildren[0], TEXT flag
└─ <p> static            ← 不进入动态后代列表
```

这些是模板比任意手写 render 函数更容易优化的原因之一：编译器看得见结构。

### 2.2 patch flag 不是业务 API

你应能在编译产物或性能分析中识别它，但不要在业务代码里硬编码内部数字。位值、内部结构并非应用契约。

### 2.3 哪些写法让优化信息变弱

- 大量运行时动态组件和不透明的 render helper；
- 每次 render 创建语义变化不清的对象/函数并层层下传；
- 一个巨大组件读取大量状态，导致 render effect 依赖面过宽；
- 随机 key 强制整棵子树重建。

## 3. VNode 与组件 subTree

一个组件 VNode 描述“使用哪个组件、传什么 props/slots”；组件实例执行 render 后产生 `subTree`，它描述组件内部将挂载的内容。

```text
Parent subTree
└─ VNode(UserCard, { userId: '42' })
      ↓ 对应 component instance
      └─ instance.subTree
          └─ VNode(article)
              ├─ VNode(h2)
              └─ VNode(button)
```

父组件 render 重跑不等于所有 DOM 都重建。renderer 会比较 VNode 类型、key、props 和 children；组件还会判断是否需要更新。

### 3.1 props 稳定性决定跳过空间

低效：每一行都收到变化的 `activeId`。

```vue
<Row v-for="item in rows" :key="item.id" :item="item" :active-id="activeId" />
```

更稳定：多数行的 `active` 仍为 false，props 没变。

```vue
<Row
  v-for="item in rows"
  :key="item.id"
  :item="item"
  :active="item.id === activeId"
/>
```

不要因此机械 memo 所有值。先 profile，优先缩小依赖面、稳定业务契约。

## 4. `key` 是身份声明

正确 key 同时满足：

1. 同一 siblings 范围唯一；
2. 同一业务实体跨渲染稳定；
3. 不依赖当前数组位置；
4. 不在 render 时随机生成。

| key | 重排后的语义 | 评价 |
| --- | --- | --- |
| 数据库 `order.id` | 实例跟随订单 | 正确 |
| 数组 index | 实例跟随位置 | 仅真正静态、无状态列表才可能安全 |
| `Math.random()` | 每次都是新实例 | 强制卸载/挂载，状态和性能都坏 |
| 可修改标题 | 标题改变即换身份，且可能重复 | 通常错误 |

key 也可有意用来重置子树：例如 `:key="documentId"` 让编辑器切文档时重建。但这是明确的生命周期决策，不是默认刷新按钮。

## 5. keyed diff 与最长递增子序列（LIS）

假设旧 children：

```text
old: A B C D E
new: A C B E D
```

renderer 的目标是复用相同 type+key 的节点，并尽量少移动。概念步骤：

1. 从头同步相同节点；
2. 从尾同步相同节点；
3. 若一侧耗尽，批量 mount 或 unmount；
4. 中间未知区建立 `newKey → newIndex`；
5. 遍历旧区，找不到的卸载，找到的 patch；记录新位置对应旧位置；
6. 对旧位置序列求 LIS；LIS 中的节点相对顺序已正确，可留在原地；
7. 从后向前 mount 新节点或 move 不在 LIS 中的节点，锚点稳定。

示意：

```text
new 中间段：C B E D
对应 old 位置（加 1，0 留给“新节点”）：3 2 5 4
一个 LIS：2 4（B、D）
=> B、D 可作为稳定骨架；其余按算法移动到正确锚点前
```

为什么从后向前？右侧节点已经就位，可以作为 `insertBefore` 的 anchor。你无需背具体实现变量名，但要会手算：哪些 patch、哪些 unmount、哪些 mount、哪些 move。

### 5.1 key 相同还要比较 type

`<div key="x">` 与 `<UserCard key="x">` 不是同一个 VNode 类型；通常要卸载旧节点并挂载新节点。key 只在相同父级和可比较节点中定义身份。

## 6. scheduler、`nextTick` 与浏览器帧

状态写入先让组件 render effect 失效并排入 job queue。调度器要解决：

- 同一 job 在一轮去重；
- 父组件通常先于子组件更新，避免子组件更新后又被父组件卸载；
- 已卸载/失效 job 不应继续提交；
- pre、component、post 回调有明确阶段；
- 一轮中新增 job 仍以可预测方式处理。

```ts
count.value = 1
count.value = 2
await nextTick()
// Vue 已完成这轮相关 DOM patch；count 已是 2。
```

`nextTick` 不是：

- “等待 0ms”；
- 等网络、图片、字体；
- 保证浏览器 paint；
- 修复任意竞态的万能胶。

DOM 布局测量的常见意图：

```ts
watch(rows, async () => {
  await nextTick()
  const height = listElement.value?.getBoundingClientRect().height
  // 如果语义是“下一帧已绘制后”，再显式 await requestAnimationFrame。
}, { flush: 'post' })
```

这里 `post` 与 `nextTick` 可能重复，实际选一种清晰表达即可。不要通过连续两个 `nextTick` 猜时机。

## 7. 模板、render function 与 JSX 怎么选

模板是默认首选：可读、可静态分析、团队工具成熟。render/JSX 适合高度动态的结构生成、库级适配器、AST 驱动 UI。

一个严格类型的 render 组件：

```ts
import { defineComponent, h, type PropType } from 'vue'

interface Action {
  id: string
  label: string
  disabled?: boolean
}

export const ActionList = defineComponent({
  props: {
    actions: {
      type: Array as PropType<readonly Action[]>,
      required: true,
    },
  },
  emits: {
    select: (id: string) => id.length > 0,
  },
  setup(props, { emit }) {
    return () => h('ul', props.actions.map(action =>
      h('li', { key: action.id }, [
        h('button', {
          disabled: action.disabled,
          onClick: () => emit('select', action.id),
        }, action.label),
      ]),
    ))
  },
})
```

render 函数中的 VNode 必须保持唯一，不能把同一个 VNode 对象重复放入树。JSX 的属性/事件/v-model 语法与 React 不完全相同，必须以项目的 Vue JSX 插件约定为准。

## 8. 四个高级渲染边界

### 8.1 `KeepAlive`：缓存组件实例，而非缓存任意 DOM

```vue
<KeepAlive :max="5">
  <component :is="activePanel" :key="activePanelKey" />
</KeepAlive>
```

被移出当前树的组件不会正常 unmount，而是 deactivated；回来时 activated。对应资源应判断：

- 缓存期间仍需运行：例如未完成草稿状态；
- deactivated 时应暂停：动画、轮询、键盘快捷键；
- 真正淘汰时才释放：由 scope/unmount 最终处理。

```ts
onActivated(resumePolling)
onDeactivated(pausePolling)
onUnmounted(disposePolling)
```

`include/exclude` 常依赖组件 name；动态组件 key 决定缓存身份；`max` 表示容量与淘汰策略。KeepAlive 不是服务端数据缓存，不能代替 query cache。

### 8.2 `Teleport`：逻辑父子不变，DOM 位置改变

```vue
<Teleport to="#overlay-root">
  <ModalDialog />
</Teleport>
```

事件、provide/inject、组件层级仍按 Vue 逻辑树；CSS 包含块、堆叠上下文和 DOM 查询按实际 DOM。目标节点必须存在；Vue 3.5 的 deferred target 能处理同一更新周期稍后出现的目标，但仍要显式验证 SSR 与测试环境。

### 8.3 `Suspense`：协调异步依赖的 pending/fallback/resolve

```vue
<Suspense @pending="onPending" @resolve="onResolve" @fallback="onFallback">
  <DashboardPanel />
  <template #fallback><PanelSkeleton /></template>
</Suspense>
```

它可以等待异步 setup 和 suspensible async component。边界设计关注：fallback 放哪一级、旧内容是否保留、错误由谁处理。**Suspense 不等于 ErrorBoundary**；错误仍需 `onErrorCaptured` / app errorHandler 或路由框架机制。Vue 文档将 Suspense 标为实验能力时，应在项目升级策略中隔离使用。

### 8.4 `defineAsyncComponent`：代码加载状态机

```ts
const ReportDesigner = defineAsyncComponent({
  loader: () => import('./ReportDesigner.vue'),
  loadingComponent: LoadingPanel,
  errorComponent: LoadError,
  delay: 150,
  timeout: 15_000,
  suspensible: true,
  onError(error, retry, fail, attempts) {
    if (attempts <= 2 && /fetch|network/i.test(error.message)) retry()
    else fail()
  },
})
```

异步组件解决代码块加载，不自动解决业务数据请求。重试必须有上限，部署后旧 HTML 引用已删除 chunk 时还需要版本刷新/发布兼容策略。

## 9. 生命周期与错误边界

一次首次挂载的简化顺序：

```text
setup
beforeMount
render → mount child
mounted（子 mounted 通常先完成，再到父 mounted）
```

更新：state trigger → scheduler → beforeUpdate → render/patch → updated。卸载要停止 render effect 与组件 scope，并执行清理。

不要把业务初始化全部塞进 `onMounted`：

- 纯状态推导不需要 lifecycle；
- SSR 需要的数据应使用框架数据 API/可 SSR 的 setup 路径；
- DOM API 才明确需要 mounted；
- subscription 创建者必须配套清理。

错误处理层次：

```text
局部可恢复错误 → 组件状态与重试 UI
后代渲染/生命周期错误 → onErrorCaptured 边界
未捕获应用错误 → app.config.errorHandler + 监控
异步请求业务失败 → 请求状态机（不会自动变成渲染错误）
```

`onErrorCaptured` 返回 false 可阻止继续向上传播，但边界自身 fallback 也必须足够简单，避免二次报错。

## 10. 优化指令的使用边界

- `v-once`：此组件实例生命周期内只渲染一次；数据以后变化也不更新。
- `v-memo`：依赖数组不变时跳过子树更新；最常见于经 profile 证实的大列表。
- `v-if`：条件假时卸载，切换成本较高，初始可不渲染。
- `v-show`：总是渲染，仅切换 CSS display；适合频繁切换、内容可常驻。

优化顺序应是：

```text
测量 → 缩小依赖/组件边界 → 稳定 props/key → 虚拟化/分包
    → 最后才是 v-memo、手工 render 微调
```

随机 key、到处 `v-if="loaded"` 重建子树、盲加 KeepAlive 通常是在交换问题。

## 11. 测试与排障方法

### 11.1 列表身份测试

不要只断言文本顺序；给行组件内部输入草稿，插入/重排数据，再断言草稿仍跟随业务 id。

### 11.2 调度测试

- 写状态后立即断言 JavaScript 状态；
- `await nextTick()` 后断言 DOM；
- 异步组件用可控 loader Promise；
- 避免真实 sleep。

### 11.3 渲染性能排障

1. Vue Devtools performance / browser Performance 录制实际交互；
2. 找到反复更新的组件，而不是凭组件行数猜；
3. 检查 key、props 稳定性、slots/对象函数身份；
4. 区分 JavaScript render、DOM patch、layout、paint 哪段贵；
5. 大列表先考虑窗口化，而非让 diff 处理全部节点；
6. 用生产构建复测，开发模式成本不同。

### 11.4 编译视角排障

可用 Vue 官方 SFC/Template 编译器 playground 观察 render 产物：哪些节点有 patch flag、哪些静态提升、一个写法是否生成 block。目标是验证心智模型，不是让业务代码迎合某个内部产物。

## 12. 生产边界与反例

- “VNode diff 正确”不代表 UX 正确；焦点、选择区、滚动位置需要独立设计。
- key 只表达同级 VNode 身份，不是数据库缓存键或全局唯一证书。
- KeepAlive 会保留内存和 effects，容量必须有界；deactivated 不等于 unmounted。
- Teleport 解决 DOM 位置，不自动解决 focus trap、滚动锁、层级管理和 aria 隔离。
- Suspense 解决等待呈现，不自动捕获所有错误，也不定义业务重试。
- 异步组件的 chunk 失败可能来自部署版本漂移；无上限 retry 会制造请求风暴。
- `nextTick` 解决 Vue 刷新时序，不应掩盖状态所有权或请求竞态。
- 手写 render/JSX 会减少部分模板编译优化机会；仅在结构确实动态时采用。

## 13. 速记卡

```text
模板给编译器信息，render 产 VNode，renderer 提交差异。
patch flag 指“哪里可能变”，block tree 指“哪些动态节点值得看”。
key 是业务身份，不是 warning 消除器；随机 key 等于主动重建。
keyed diff：头尾同步 → key map → patch/unmount → LIS → 逆序 mount/move。
nextTick 等 Vue 本轮 patch，不等请求，不保证 paint。
KeepAlive 改变 mounted/unmounted 语义；Teleport 只改变 DOM 位置。
Suspense 是等待边界，不是完整错误边界。
```
