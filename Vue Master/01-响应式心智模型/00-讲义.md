# 第 01 章：响应式心智模型

## 目标

你要从“会用 `ref/reactive`”升级为能预测更新、解释失效、控制副作用。Vue 3 对对象使用 Proxy，对 `ref` 使用 getter/setter；读取时 `track`，写入时 `trigger`。依赖图可以抽象成 `WeakMap<target, Map<key, Set<effect>>>`，但真实实现还包含嵌套 effect、动态依赖清理、调度与 computed 脏值管理。

## 五个必须分开的概念

1. **值与代理身份**：`reactive(raw) !== raw`；把代理属性解构为局部原始值会断开追踪。跨边界比较时先明确使用 raw 还是 proxy，别随手 `toRaw` 逃逸。
2. **深浅响应式**：大型不可变数据或第三方实例可用 `shallowRef`；`markRaw` 是架构边界，不是性能偏方。深层响应式的成本取决于实际访问，但大数组频繁深读写仍会放大依赖数。
3. **派生与副作用**：能由现有状态纯计算出的值用 `computed`；I/O、日志、DOM、请求用 `watch/watchEffect`。不要用 watch 把 A 同步到 B，制造双份真相。
4. **依赖来源**：`watch(source, callback)` 显式，适合精确控制；`watchEffect` 自动收集同步执行期间读取的依赖，`await` 之后的读取不会成为本轮自动依赖。
5. **调度与清理**：更新不是每次赋值立刻重渲染。默认 watcher 在父更新后、组件 DOM 更新前执行；需要 DOM 后状态用 `flush: 'post'`。异步副作用必须取消旧任务，Vue 3.5 可用 `onWatcherCleanup`。

## 一个可靠的异步 watcher

```ts
const result = shallowRef<User | null>(null)

watch(userId, async id => {
  const controller = new AbortController()
  onWatcherCleanup(() => controller.abort())
  const response = await fetch(`/api/users/${id}`, { signal: controller.signal })
  result.value = await response.json()
}, { immediate: true })
```

取消不是“优化”，而是正确性：如果 id 从 1 快速变成 2，旧请求晚返回不能覆盖新结果。生产代码还应区分 abort 与真实错误，并在卸载时终止。

## Vue 3.5 需要知道的变化

`defineProps` 的解构变量默认保持响应式，但向 `watch` 或 composable 传递时仍应传 getter：`watch(() => count, ...)`。`useTemplateRef` 改善模板 ref 类型推导；`onWatcherCleanup` 让清理意图更靠近副作用。理解编译器转换比死记“能不能解构”更稳。

## 常见反模式

- 对整个路由对象或巨大 store 做 deep watch。
- 在 computed 内请求接口或修改其他状态。
- 用 `JSON.stringify` 强迫依赖收集。
- 把 socket、编辑器实例深度 reactive。
- 忘记 effect 的生命周期，在弹窗反复打开时叠加监听器。
