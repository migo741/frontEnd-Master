# 第 05 章：组件 API 与无头组件——把行为、结构与视觉分开

> 高级组件不是 props 多、抽象深，而是职责清楚、状态所有权明确、键盘/焦点/语义完整，并且调用方难以误用。

## 0. 事故钩子：鼠标能用的 Modal 上线后锁死键盘用户

一个 Modal 看起来正常：遮罩、白色卡片、右上角关闭。上线后出现：

- Tab 能移动到遮罩后的删除按钮；
- Escape 同时关闭两层弹窗；
- 打开后焦点仍留在背景；
- 关闭后焦点丢到 body；
- 屏幕阅读器不知道标题；
- iOS 背景仍滚动；
- Teleport 目标晚出现导致挂载失败。

这不是“补几个 aria 属性”就完成。组件设计至少跨三棵树和四类契约：

```text
Vue 逻辑树：provide/inject、事件、生命周期
DOM 树：Teleport 后的实际父子、CSS、querySelector
可访问性树：role/name/state/relationships

数据契约：props / model
事件契约：emits
结构契约：slots
命令契约：expose / template ref
```

---

## 1. 先分层：页面、feature、primitive、视觉组件

| 层 | 负责 | 不应负责 |
| --- | --- | --- |
| page/route | 数据加载、权限、路由编排 | 通用 focus trap 算法 |
| feature component | 领域规则、用例状态 | 复制一套通用 Dialog |
| headless primitive | 状态机、键盘、焦点、ARIA 协议 | 品牌颜色、业务请求 |
| styled design-system | tokens、视觉变体、文档示例 | 页面领域决策 |

一个组件的“变化原因”比行数更能判断是否该拆。订单页同时处理 fetch、权限、表格排序、弹窗焦点和 toast，就有多个变化轴。

合理组合：feature 使用 headless Dialog，在 slots 中渲染 design-system Button 和业务表单。

---

## 2. 六种组件通信契约

### 2.1 props：父拥有的输入

props 是只读快照/响应式输入。不要修改对象 prop 深层字段来偷渡双向绑定：

```ts
// 错误：子组件修改父拥有对象
props.user.name = input.value

// 正确：发领域事件或更新 model
emit('change', { ...props.user, name: input.value })
```

布尔 props 超过几个时检查是否产生冲突：`primary + danger + subtle + link`。用单一 variant 联合更明确：

```ts
type ButtonVariant = 'primary' | 'danger' | 'ghost' | 'link'
```

### 2.2 emits：已经发生的事件

```ts
const emit = defineEmits<{
  submit: [value: Draft]
  cancel: [reason: 'escape' | 'button' | 'backdrop']
}>()
```

事件名称表达用户/领域意图，不泄漏内部 DOM。组件事件不会像 DOM 事件一样自动向祖先冒泡。

必须声明 emits。未声明 listener 可能落到根元素成为 native listener；若组件又手动 emit 同名事件，可能双触发或在重构根节点后改变行为。

### 2.3 `v-model`：受控值协议

```ts
const open = defineModel<boolean>('open', { required: true })
```

受控组件的真相在父层：子只请求 `update:open`。适合 Dialog open、Tabs selected、Combobox value。

### 2.4 slots：结构由调用者拥有

```ts
defineSlots<{
  trigger(props: { open: () => void; expanded: boolean }): unknown
  default(props: { close: () => void }): unknown
}>()
```

slots 适合结构变化，props 适合数据/行为配置。不要用 `showIcon/showFooter/footerAlign/customHeader` 一路堆到 slot 才能解决的问题。

### 2.5 provide/inject：组件族上下文

Tabs→TabList→Tab、Form→Field、Menu→Item 适合局部上下文。用 `InjectionKey`、只读状态、动作和 fail-fast hook。它不是随手替代 props 的“隐形线缆”。

### 2.6 expose/template ref：最小命令

适合 `focus()`、`openPicker()`、`scrollToIndex()`。如果父组件需要读子组件十个字段再决定业务，应提升状态或建立 feature service。

## 3. Fallthrough attributes：`$attrs` 是公共 API 的一部分

单根组件未声明的 class/style/id/aria/listener 默认落到根节点。这有时方便，有时危险：

```vue
<!-- MyButton 根节点从 button 改成 div 后，调用方的 disabled/onClick 语义悄悄变化。 -->
```

基础组件通常显式控制：

```vue
<script setup lang="ts">
defineOptions({ inheritAttrs: false })
</script>

<template>
  <label class="field-shell">
    <span><slot name="label" /></span>
    <input v-bind="$attrs">
  </label>
</template>
```

要点：

- 多根组件不会自动决定 attrs 落哪里，必须显式绑定；
- `class/style` 合并有规则，但不要让内部与外部争夺关键布局；
- 已声明 props/emits 不在 `$attrs`；
- `$attrs` 对象本身不应被当普通响应式 source 深 watch；若 attrs 变化需要副作用，优先声明成 prop；
- 组件库要文档化 attrs 落点，否则 DOM 重构可能成为 breaking change。

## 4. 受控、非受控与草稿状态

### 4.1 受控

```ts
const selected = defineModel<string | null>({ required: true })
function choose(id: string) { selected.value = id }
```

优点：父层可持久化、路由同步、撤销；缺点：每次变化经过父层，API 必须清晰。

### 4.2 非受控

```ts
const props = withDefaults(defineProps<{ defaultOpen?: boolean }>(), {
  defaultOpen: false,
})
const open = ref(props.defaultOpen)
```

`defaultOpen` 只在初始化读取，后续变化不应自动同步，名称必须体现 default 语义。

### 4.3 不要在生命周期中切换模式

React 生态常用 `modelValue !== undefined` 判断受控；Vue 也能实现，但运行中从未传→传入会改变所有权，容易丢状态。组件库应：

- 只支持受控；或
- 分开 `modelValue` 与 `defaultValue`，开发期检测模式切换；
- 明确优先级与事件语义。

### 4.4 草稿是合法的第二份状态

编辑表单可以复制 prop，因为草稿有提交/取消边界，而非持续 watch 镜像：

```text
prop value ─open editor─> local draft
local edit ─────────────> draft only
Save ─emit commit───────> parent updates value
Cancel ─discard─────────> parent unchanged
```

关键是显式重置时机和外部值在编辑期间变化的冲突策略。

## 5. Headless 的本质：复用交互协议

无头组件负责：

- 合法状态及迁移；
- 键盘映射；
- 焦点与关闭恢复；
- ARIA role/state/relationship；
- disabled/read-only 规则；
- 为 slot 提供 prop getters 或状态/动作。

调用方负责：

- DOM 视觉结构（在不破坏语义契约的范围内）；
- class/token/动画；
- 领域数据和文案。

两种 API：

1. **renderless component + scoped slots**：模板友好，但 slot props 多。
2. **composable + prop getters/context**：组合灵活，但调用方更容易漏绑定必要属性。

一个完全自由的 slot 如果允许调用方把 `role=option` 放错节点，就不是“灵活”，而是把正确性外包。可考虑 compound components：`DialogRoot/DialogPanel/DialogTitle`，每个组件守住语义落点。

## 6. 可访问性不是 ARIA 清单

可访问交互至少包含：

```text
语义：原生元素优先、role 正确
名称：label / aria-labelledby / aria-label
状态：expanded/selected/disabled/checked
关系：controls/owns/describedby/activedescendant
键盘：与对应 WAI-ARIA pattern 一致
焦点：进入、移动、关闭恢复、不可逃逸区域
视觉：focus indicator、对比度、reduced motion
反馈：错误/status/live region 不滥报
```

“有 role=button 的 div”仍需 tabindex、Enter/Space 行为、disabled 语义；直接 `<button>` 已免费获得大部分正确行为。第一原则是优先原生语义。

自动化 axe 能发现缺 label/对比度等一部分问题，不能证明焦点顺序、读屏体验和业务语义正确。必须键盘走查与至少一种真实 screen reader 抽检。

## 7. Dialog：一个完整生命周期协议

### 7.1 最低语义

```html
<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">
  <h2 id="dialog-title">删除项目</h2>
  ...
</div>
```

如果是需要立即注意的中断性消息，可评估 `alertdialog`，不要所有弹窗都用。

### 7.2 打开

1. 保存触发元素；
2. 将 dialog 放入 overlay layer（通常 Teleport）；
3. 锁背景滚动，并让背景对交互/可访问性不可达；
4. 焦点进入：显式 initial focus，否则第一个适合元素，若无则 panel `tabindex=-1`；
5. 只让最上层 dialog 响应全局 Escape。

### 7.3 打开期间

- Tab/Shift+Tab 在 dialog 内循环；
- DOM 动态变化后重新取得可聚焦集合；
- 点击 backdrop 的判定用 `event.target === event.currentTarget`，避免点 panel 冒泡关闭；
- focus 被脚本移出时拉回 top dialog（需谨慎避免与浏览器/嵌套组件冲突）；
- nested dialog 用 stack 管理 topmost、锁计数和恢复顺序。

### 7.4 关闭

1. 发 `update:open=false` 和带 reason 的 close；
2. 释放当前层 listener/inert/scroll lock；
3. 等 DOM 更新后恢复到原触发元素；若已不存在，选择合理 fallback；
4. 嵌套时恢复到父 dialog 内，而不是背景 body。

### 7.5 Dialog 反例

- 只拦 keydown Tab，却没有考虑没有可聚焦元素；
- `document.querySelectorAll` 扫整个页面而非 panel；
- 所有 dialog 都监听 document Escape，一次关多层；
- `overflow:hidden` 关闭时无引用计数，关子弹窗就解锁父弹窗背景；
- Teleport 后用祖先 CSS selector 假设 DOM 仍在 feature 内；
- 关闭时立即 focus，触发元素尚未重新显示。

## 8. Combobox：焦点留在 input，活动项是“虚拟焦点”

常见 editable combobox 结构：

```html
<input
  role="combobox"
  aria-autocomplete="list"
  aria-expanded="true"
  aria-controls="city-listbox"
  aria-activedescendant="city-option-shanghai"
>
<ul id="city-listbox" role="listbox">
  <li id="city-option-shanghai" role="option" aria-selected="false">上海</li>
</ul>
```

DOM focus 通常始终在 input；ArrowDown 改变 `activeId`，通过 `aria-activedescendant` 告诉辅助技术当前活动 option。

### 8.1 状态不要混在一个 index

```ts
interface ComboboxState<TKey> {
  open: boolean
  query: string
  selectedKey: TKey | null
  activeKey: TKey | null
  composing: boolean
}
```

- selected：已提交值；
- active：键盘暂时指向；
- query：输入文本；
- composing：中文/日文 IME 尚未提交。

列表过滤/异步更新后，index 会指向另一项；active 应用稳定 key，并在 options 改变时修复为仍可用项或 null。

### 8.2 键盘基本协议

| 键 | 典型行为 |
| --- | --- |
| ArrowDown/Up | 打开并移动 active，跳过 disabled |
| Enter | 非 composing 且有 active 时选择 |
| Escape | 关闭；是否清 query 需契约定义 |
| Home/End | 依 pattern/产品在首尾移动；不要破坏输入编辑预期 |
| Tab | 通常正常离开，是否提交 active 要明确 |

IME 期间按 Enter 是“确认候选文字”，不能被误当选择 option：监听 compositionstart/end，或检查 `event.isComposing`。

### 8.3 异步与虚拟列表

远程搜索需：latest-wins、loading/error/empty 不混淆、结果更新后 active 修复。虚拟化时 active option 可能不在 DOM，`aria-activedescendant` 指向不存在 id 会失效；移动 active 时先滚动/渲染目标，或采用经过验证的虚拟可访问策略。

option id 必须 DOM 唯一且 SSR/hydration 稳定，可用 Vue 3.5 `useId()` 生成组件前缀，再编码稳定 key；不要用随机数。

## 9. API 设计例：避免 boolean soup

坏 Dialog：

```vue
<Modal
  show-close
  close-on-mask
  trap-focus
  center
  fullscreen-mobile
  danger
  has-footer
  no-padding
/>
```

更好的分层：

```vue
<DialogRoot v-model:open="open" :close-on-backdrop="false">
  <DialogPanel size="md">
    <DialogTitle>删除项目</DialogTitle>
    <DeleteProjectForm @success="open = false" />
  </DialogPanel>
</DialogRoot>
```

行为 props 少而明确；视觉 variant 在 Panel；结构用 compound children/slots；业务内容在 feature。

事件 reason 是诊断和策略输入：

```ts
type CloseReason = 'escape' | 'backdrop' | 'close-button' | 'programmatic'
```

“表单 dirty 时 Escape 是否关闭”应由调用层通过 beforeClose/受控 model 决定，或 primitive 提供 cancelable close request；不能让内部悄悄丢草稿。

## 10. 测试金字塔

### 10.1 纯状态机单测

Combobox 的 move/select/close、跳 disabled、options 改变、IME；Dialog stack push/pop/top。

### 10.2 组件行为测试

- props → DOM attributes；
- emit payload/reason；
- slot props；
- attrs 落点；
- Teleport attach；
- initial/restore focus；
- listener/scroll lock 清理；
- nested topmost。

jsdom 的 focus/layout 有局限，不能作为最终证据。

### 10.3 浏览器 E2E

Playwright 用真实 Tab/Shift+Tab/Arrow/Enter/Escape；断言 `document.activeElement`、可见性、滚动锁、DOM overlay 位置。结合 axe，但保留人工键盘与读屏检查表。

不要只测 snapshot；一个 aria 属性快照无法证明交互时序。

## 11. 排障路线

```text
事件双触发？→ emits 是否声明？listener 是否又 fallthrough 到根 DOM？
attrs 丢失？→ 多根？inheritAttrs=false 后是否绑定到正确交互元素？
model 不同步？→ 真相在父还是子？是否同时 default + controlled？
slot 难用？→ 暴露的是稳定能力，还是内部实现细节？
Dialog 焦点逃逸？→ topmost？动态 focusables？Teleport 后查询范围？
Escape 关两层？→ document listener 是否由 stack 仲裁？
Combobox 选错？→ active 用 index？过滤后是否修复？IME 是否被误判？
读屏无名称？→ labelledby 指向的 id 是否真实且唯一？
```

## 12. 生产边界

- 可访问 pattern 要以当前 WAI-ARIA Authoring Practices 与真实辅助技术验证；不要只凭记忆复制。
- 自研 Dialog/Combobox 的边角成本很高。业务团队应优先评估成熟、经过审计的 headless library；自研通常适合组件平台团队。
- headless 不等于无 DOM 约束；正确语义可能要求固定的 panel/option 落点。
- attrs 落点、slot props、provide context 和 expose 都是 public contract，重构需考虑版本兼容。
- Teleport 不解决 overlay z-index 管理；需要全局 layer/token/stack 协议。
- 浏览器、iOS、screen reader 组合行为不同；关键流程需定义支持矩阵。
- disabled 与 readonly 不同；ARIA disabled 也不自动阻止 JavaScript handler。
- 视觉隐藏、DOM 隐藏和可访问性树隐藏不是同一件事。

## 13. 速记卡

```text
props 输入，emits 事件，model 受控值，slots 结构，inject 上下文，expose 命令。
$attrs 落点是组件 API；基础组件常 inheritAttrs=false 后显式绑定。
受控与非受控要选定；default 只初始化，不能持续镜像。
Headless 复用行为协议，不是把所有正确性丢给 slot。
优先原生语义；ARIA 不能替代键盘和焦点。
Dialog：进入焦点、trap、topmost Escape、背景隔离、关闭恢复。
Combobox：DOM focus 留 input，active 用稳定 key，IME Enter 不等于选择。
axe 是检查器，不是可访问性证明。
```
