# 第 05 章：组件 API 与无头组件

## 组件设计首先是职责设计

坏组件的征兆不是行数，而是变化原因太多：请求、权限、布局、业务规则、弹窗状态全耦合。把业务 orchestration 留给页面/feature，把可复用交互抽成 headless primitive，把视觉落在 design system。

## 契约选择

- props：父到子配置；不要让子组件修改对象 prop 内部来偷渡双向绑定。
- emits：已经发生的用户/领域事件，名字表达意图，如 `submit`，而非 `clickButton`。
- `v-model`：受控值协议；区分 value 与 defaultValue，明确 controlled/uncontrolled。
- slots：调用方拥有结构；scoped slot 暴露能力和状态。
- provide/inject：跨深层组件的上下文协议，必须用 `InjectionKey<T>`，不要当隐形全局 store。
- expose/template ref：命令式能力的最后手段，如 focus，不用于读取任意内部状态。

## 无头组件

例如 Combobox 核心负责 open/highlight/selection、键盘和 ARIA，调用方 slot 决定 DOM 与样式。这样业务定制不再靠二十个 boolean props。代价是 API 设计难、slot props 多，必须配行为测试和示例。

## 受控状态

受控组件只发更新，由父组件决定新值；非受控组件持有内部状态。混合支持时在生命周期内不要随意切换模式。派生状态不要复制 prop 后再 watch 同步，优先 computed getter/setter 或明确草稿提交协议。
