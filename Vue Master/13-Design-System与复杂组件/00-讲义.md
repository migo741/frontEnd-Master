# 第 13 章：Design System 与复杂组件

> 本章目标：把“组件库”从一堆漂亮组件提升为可演进的产品基础设施。稳定基线为 Vue 3.5；无障碍行为以浏览器和辅助技术真实测试为准，而不是只看 ARIA 属性数量。

## 1. 生产事故：一个下拉框造成三类故障

公司有四条业务线，各自复制过一份 Select。新版品牌色上线时改了 137 个十六进制值；客服系统的 Select 在 Dialog 中被裁剪；键盘用户无法选择远程搜索结果；某业务升级组件库后，原来的 `value` prop 静默改成对象，保存接口收到 `[object Object]`。

表面是 CSS、Teleport、ARIA 和版本兼容四个问题，本质是系统缺少：

- 语义 token 与主题契约；
- primitive/headless/styled/业务组件分层；
- overlay、焦点、键盘和异步状态的统一状态机；
- 受控值和事件的稳定 API；
- 版本、弃用、迁移和视觉回归机制。

```text
Design System
├─ Foundations：颜色、排版、间距、motion、icon、a11y 原则
├─ Tokens：语义变量与主题映射
├─ Primitives：Portal/FocusTrap/VisuallyHidden/Presence
├─ Headless：Combobox/Dialog/Menu 的状态与交互
├─ Styled：品牌视觉、尺寸、密度、状态
├─ Patterns：表单、筛选器、DataGrid、导航
└─ Governance：版本、文档、测试、发布、废弃
```

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| design token | 有名称和语义的设计决策，不只是 CSS 常量 |
| primitive | 低层行为/结构能力，如 Teleport、focus scope、presence |
| headless component | 提供状态、事件、ARIA/键盘行为，不强制品牌样式 |
| styled component | 在稳定行为上施加视觉、尺寸、主题与密度 |
| controlled | 状态由调用方作为单一真相传入，组件发出意图 |
| uncontrolled | 组件内部拥有初始/当前状态，调用方只在必要时监听 |
| overlay | 脱离普通文档流的浮层，如 Dialog、Popover、Tooltip |
| roving tabindex | 集合中只有一个元素 `tabindex=0`，方向键移动活动项 |
| active descendant | 焦点留在 input，`aria-activedescendant` 指向活动 option |
| semantic versioning | 版本号表达兼容承诺；实际 breaking change 仍需迁移证据 |
| visual regression | 对稳定场景截图/像素或结构比较，发现非预期视觉变化 |

## 3. Token：从原始值到语义契约

### 3.1 三层 token

```text
primitive: blue.600 = #2563eb
      ↓ theme mapping
semantic: color.action.primary = blue.600
      ↓ component mapping
component: button.primary.background = color.action.primary
```

原始 token 表达调色板，语义 token 表达用途，组件 token 只在组件确实需要独立演进时添加。若业务模板直接用 `blue-600`，暗色/高对比主题无法表达“primary action”的真实意图。

```css
:root {
  --ds-color-surface: #ffffff;
  --ds-color-text: #111827;
  --ds-color-action-primary: #2563eb;
  --ds-color-action-primary-hover: #1d4ed8;
  --ds-focus-ring: #2563eb;
  --ds-space-2: 0.5rem;
  --ds-radius-md: 0.5rem;
}

[data-theme='dark'] {
  --ds-color-surface: #111827;
  --ds-color-text: #f9fafb;
  --ds-color-action-primary: #60a5fa;
  --ds-color-action-primary-hover: #93c5fd;
  --ds-focus-ring: #93c5fd;
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

Token pipeline 应验证名称、类型、引用环、主题完整性和对比度，并生成 CSS variables、TypeScript 类型与设计工具映射。不要把 Figma export 未审查地当源代码。

### 3.2 Token 变更也是 API 变更

删除或重命名一个被业务使用的 token 会 break。需要：

1. 搜索/遥测真实使用者；
2. 增加新 token 并保留旧 alias；
3. 在文档、lint/codemod 中给迁移路径；
4. 至少跨一个约定周期弃用；
5. 在 major 版本删除，并发布前后截图 diff。

## 4. 组件分层与依赖方向

推荐依赖：

```text
business feature
   ↓
patterns / styled components
   ↓
headless behavior
   ↓
primitives + tokens
   ↓
Vue / DOM platform
```

反向依赖会让 design system 知道订单、客户、权限，最终无法复用。业务组件可以组合通用 DataGrid，但 DataGrid 不导入 `OrderStore`。

### 4.1 一个稳定 API 的最小组成

- 值模型：primitive id 还是完整对象；比较 identity 是什么；
- controlled/uncontrolled：`modelValue`、`defaultValue`、更新事件的优先级；
- 事件语义：用户意图还是 DOM 原始事件；是否可取消；
- slot contract：暴露哪些状态/操作，是否保证稳定；
- DOM/ARIA contract：哪些节点/role 是兼容承诺；
- 状态：loading、empty、error、disabled、readonly、invalid；
- 表单：name、required、reset、validation；
- SSR：id 与首次结构是否确定；
- 可观测：开发期 warning、版本与使用统计（不得采业务敏感数据）。

不要既允许内部写值，又让外部受控值覆盖，却不规定优先级。这会产生“点一下又弹回”的双真相。

## 5. Overlay：Teleport 只解决 DOM 位置

```vue
<Teleport to="body">
  <div v-if="open" class="overlay-root">...</div>
</Teleport>
```

Teleport 可以绕过祖先 `overflow:hidden` 和 stacking context，但没有自动解决：

- z-index 分层；
- anchor 定位、碰撞、翻转和滚动更新；
- modal backdrop、外部点击和 Escape；
- 焦点初始位置、trap、恢复；
- 背景 inert/scroll lock；
- 嵌套 overlay 的关闭顺序；
- SSR target 不存在与 hydration；
- 事件虽然 DOM 移动，Vue 逻辑父子关系仍保留。

成熟系统通常有统一 OverlayManager：

```ts
interface OverlayEntry {
  id: string
  kind: 'tooltip' | 'popover' | 'modal' | 'toast'
  modal: boolean
  restoreFocusTo: HTMLElement | null
  close(reason: 'escape' | 'outside' | 'programmatic'): void
}
```

Manager 管 stack、Escape 只关顶层、scroll lock 引用计数与焦点恢复。不要让每个 Dialog 各自把 body overflow 设回空字符串；嵌套时第一个关闭会错误解锁。

## 6. 焦点、键盘与 ARIA：语义必须跟状态机一致

### 6.1 Dialog 基本协议

打开 modal dialog 时：

1. 记录触发元素；
2. Teleport 后把焦点移到合理初始元素；
3. Tab/Shift+Tab 留在 dialog；
4. Escape 关闭顶层（除非当前操作明确不可中断）；
5. 背景不可交互/不可被读屏误导航；
6. 关闭后焦点回触发元素；若触发元素已删除，回到合理上级。

`role="dialog"`、`aria-modal="true"`、`aria-labelledby`/`aria-describedby` 只是语义的一部分，不能替代焦点行为。

### 6.2 Combobox 的状态机

可编辑 combobox 常用焦点留在 input 的 active-descendant 模式：

```text
closed
  ├─ ArrowDown / input → open, active=first eligible
  └─ value stays committed

open
  ├─ ArrowUp/Down/Home/End → active changes, input keeps DOM focus
  ├─ Enter → commit active, close
  ├─ Escape → close, optionally restore query
  ├─ input → query changes, async request generation++
  └─ blur/outside → commit or close according to explicit policy
```

input 需要 `role="combobox"`、`aria-expanded`、`aria-controls`、活动时的 `aria-activedescendant`；popup 常为 `role="listbox"`，item 为 `role="option"` + `aria-selected`。DOM id 必须 SSR 稳定。

### 6.3 异步竞态

```ts
let generation = 0
let aborter: AbortController | undefined

async function search(query: string): Promise<void> {
  const own = ++generation
  aborter?.abort()
  aborter = new AbortController()
  status.value = 'loading'
  try {
    const next = await api.search(query, aborter.signal)
    if (own !== generation) return
    options.value = next
    status.value = next.length ? 'success' : 'empty'
  } catch (error: unknown) {
    if (own !== generation) return
    if (error instanceof DOMException && error.name === 'AbortError') return
    status.value = 'error'
  }
}
```

Abort 节省资源，generation 保证逻辑正确；二者都需要。结果变化后 active option 若不存在，要根据协议重置，`aria-activedescendant` 不能指向已卸载节点。

## 7. Headless + Styled：分离的是决策，不是复制两套状态

Headless 层可返回 prop getters/slot props：

```ts
interface ComboboxOption {
  id: string
  label: string
  disabled?: boolean
}

interface ComboboxBindings {
  input: {
    role: 'combobox'
    'aria-expanded': boolean
    'aria-controls': string
    'aria-activedescendant'?: string
  }
  option(option: ComboboxOption): {
    id: string
    role: 'option'
    'aria-selected': boolean
    'aria-disabled'?: true
  }
}
```

Styled 层只消费状态和绑定，不能偷偷再维护 `internalOpen`。否则键盘状态、视觉状态、ARIA 状态会分叉。

## 8. DataGrid：它是一个小型应用

生产 DataGrid 往往组合：

- 排序、过滤、分页、选择、编辑、列宽、固定列；
- 键盘二维导航、focus/selection/edit 三种不同状态；
- 服务端/客户端数据模式；
- 虚拟行/列、动态高度、滚动恢复；
- loading/empty/error/partial 数据；
- 行权限、乐观更新、冲突处理；
- 导出、复制、打印和可访问降级。

先定义模型，而不是先写 40 个 boolean props：

```ts
interface GridState {
  sort: readonly { columnId: string; direction: 'asc' | 'desc' }[]
  filters: Readonly<Record<string, unknown>>
  pagination: { page: number; pageSize: number }
  selection: ReadonlySet<string>
  focusedCell: { rowId: string; columnId: string } | null
  editingCell: { rowId: string; columnId: string } | null
}
```

### 8.1 表格还是 grid

只读数据优先原生 `<table>`，浏览器/读屏已经提供大量语义。只有需要 spreadsheet 式二维键盘交互时才采用 `role="grid"`，并承担完整键盘模型。加一个 `role=grid` 不会自动获得行为。

### 8.2 虚拟化与可访问性

窗口化后 DOM 中只存在部分行。需要：

- 稳定 row id/key；
- 正确 `aria-rowcount`/`aria-rowindex`（若采用 grid 模式）；
- active cell 滚入窗口后再聚焦/指向；
- overscan 避免焦点项瞬时卸载；
- 为读屏、打印、浏览器查找或导出提供分页/非虚拟化通道；
- 动态高度测量不产生反馈循环和 layout thrash。

不应承诺“任何 100 万行都在客户端可访问”。后端分页/查询与产品交互同样是系统边界。

## 9. 版本与废弃：兼容性不止 TypeScript 能否编译

Breaking change 包括：

- prop/event/slot/token 名称或类型；
- 默认值、事件时序、焦点与键盘行为；
- DOM 结构/selector（业务可能用于测试或样式）；
- CSS specificity、尺寸、布局和 z-index；
- SSR HTML/id；
- tree-shaking 或 side-effect 行为。

推荐发布流程：

```text
RFC / usage audit
 → 新旧 API 并存 + dev warning
 → migration guide + codemod
 → canary + consumer contract tests
 → minor 版本收集反馈
 → major 删除
 → 监测错误、视觉与关键业务指标
```

对未公开 DOM 不作永久承诺，但要通过文档和 lint 给业务正确扩展点，避免他们被迫 deep selector。

## 10. 测试金字塔

1. **状态机/纯逻辑单测**：键盘 action、受控协议、异步 generation、选择 reducer。
2. **组件交互测试**：按用户方式 type/tab/arrow/escape；断言可见行为和 role/name/state。
3. **浏览器 E2E + 辅助技术抽查**：真实 focus、Teleport、scroll、IME、移动端、读屏。
4. **视觉回归**：主题 × 密度 × viewport × 状态；稳定字体/动画/数据，审查 intentional diff。
5. **消费者契约测试**：典型业务在 canary 版本上构建并运行，发现 slot/DOM/event 兼容问题。

Snapshot 大段 HTML 往往噪声高；它不能证明键盘、焦点或读屏正确。视觉 diff 也不能证明语义正确，两者互补。

## 11. 常见反例

1. **token 等于变量重命名**：没有语义和主题映射，仍然全局搜颜色。
2. **Headless 就是不带 CSS**：若没有状态机、键盘、ARIA 和稳定契约，只是裸 DOM。
3. **Teleport 后提高 z-index 即完成**：忽略 focus、outside click、nested stack、scroll lock。
4. **用 keydown 模拟 click**：原生 button 已有正确语义，优先使用平台元素。
5. **给 div 加 role 就可访问**：role 同时创造必须实现的键盘与状态义务。
6. **DataGrid 一次做全功能**：先按产品场景切 vertical slice，并明确不支持项。
7. **SemVer 自动保证兼容**：行为、视觉和 DOM 变化仍需消费者测试与迁移。
8. **截图全绿即发布**：可能是错误基线被批量接受；diff 必须有人解释。

## 12. 速记卡与自检

### 速记卡

- token：primitive → semantic → component，业务优先用 semantic。
- 分层：业务 → pattern/styled → headless → primitive/token。
- Teleport 解决位置，不解决 overlay 行为。
- 焦点、键盘、ARIA 必须由同一状态机驱动。
- Combobox 用稳定 id、active-descendant、异步 generation/abort。
- DataGrid 先定义数据/交互模型，再考虑虚拟化。
- 版本兼容包含行为、视觉、DOM、SSR，不只类型。
- 单测、浏览器、a11y、视觉和消费者契约分别证明不同事情。

### 自检题

1. semantic token 为什么比 `blue-600` 更能支持主题演进？
2. controlled 与 uncontrolled 同时支持时必须规定什么优先级？
3. Teleport 后事件、焦点和 stacking context 分别发生了什么？
4. Combobox 为什么通常让 DOM focus 留在 input？
5. AbortController 为什么不能替代 generation guard？
6. 什么时候用原生 table，什么时候承担 `role=grid` 的完整义务？
7. 虚拟化如何影响焦点、ARIA row index、打印和查找？
8. 一个视觉不变但仍 breaking 的组件改动有哪些？
