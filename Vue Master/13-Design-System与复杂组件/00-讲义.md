# 第 13 章：Design System 与复杂组件

## 组件库不是一堆漂亮组件

Design System 包含 token、组件、交互规范、可访问性、文档、发布与治理。先定义语义 token（color.text.danger）再映射基础色，支持主题时只换 token；不要在业务里复制十六进制值。

组件 API 要区分 primitive 与业务 pattern。Button、Dialog、Combobox 是 primitive；“工单转派面板”是业务 pattern，可能组合多个 primitive。把所有业务需求塞进基础组件会使版本无法演进。

## 可访问性是正确性

优先原生语义；自定义控件实现键盘、焦点、ARIA、屏幕阅读器名称和状态。颜色不是唯一信息。自动 axe 只能发现一部分问题，仍需键盘和读屏器手测。

## 复杂表格

企业 DataGrid 涉及列配置、排序、选择、固定列、虚拟化、编辑、服务端分页。要明确 server/client ownership；虚拟化与动态行高、焦点、屏幕阅读器有冲突；不要一次造完整 Excel。用 headless state machine + 渲染层 + adapter 分层。

## 发布治理

SemVer 只是协议，必须有 changelog、迁移说明、视觉回归、弃用周期和 codemod。样式变更也可能是 breaking。组件文档应展示 happy path、空/错/loading/长文本、键盘操作与 API 取舍。
