# 第 14 章：SaaS 应用壳、表格与仪表盘

## 复杂界面先管理滚动和信息层级

App Shell 不是 header/sidebar/main 三块拼图。要明确 viewport、主要滚动区、sticky 区域、focus scroll、移动端工具栏和安全区。Grid 用于整体二维关系，组件内部 Flex/Grid 按内容选择。`minmax(0,1fr)` 与 `min-block-size:0` 常是滚动正确性的关键。

## 数据表格不是卡片集合的桌面版

真正的表格数据使用 `<table>` 保留行列语义。大量 div + Grid 模拟会失去原生导航/辅助技术关系。包裹容器可以横向滚动，sticky header/first column 要管理 background、z-index、focus 与阴影。320px 下不必强行展示全部列：可允许局部滚动、选择关键列，或提供独立详情视图，但不能复制一套数据 DOM 造成状态漂移。

## 状态画廊

每个数据区域都需 loading、empty、error、partial、stale、permission denied、live update。Skeleton 的几何应接近真实内容以减少 CLS；错误保留上下文和恢复操作；空状态区分“没有数据”和“筛选无结果”。实时更新不能让列表不断跳位、抢走焦点。

## 密度系统

compact/comfortable 用 spacing、control size、row height 等 token 改变，不复制组件规则。最小触摸目标和可读性仍是下限。密度不是把所有字号缩小。
