# 第 03 章：内在尺寸、溢出与现代单位

## 布局是约束求解

元素尺寸并非只有 width。浏览器综合 available space、min/max constraints、min-content、max-content、fit-content、aspect ratio 和内容贡献。Flex/Grid item 的自动最小尺寸是很多“明明写了 1fr 还溢出”的根因。

```css
.layout { grid-template-columns: minmax(0, 1fr) auto; }
.item { min-inline-size: 0; }
.url { overflow-wrap: anywhere; }
```

`min-width: 0` 不是万能咒语；它是在确认 item 的 automatic min-size 阻止收缩后，允许它低于 min-content。之后仍需决定内容是换行、局部滚动还是截断。关键 ID、金额和错误信息不应无提示省略。

## 单位表达意图

- `rem` 适合随用户根字号缩放的尺寸；`em` 适合相对组件文字的局部比例。
- `%` 的参照取决于属性和 containing block，不能笼统理解为父元素。
- `vw/vh` 代表视口，但移动浏览器动态工具栏使传统 `100vh` 常出问题；`svh/lvh/dvh` 分别表达小、大、动态视口。
- `ch` 可近似控制文本行宽，但并非字符数量保证。
- container query units（如 `cqi`）只在组件应相对容器连续变化时使用。

用 `min()`、`max()`、`clamp()` 表达范围，而不是堆很多断点。图片和媒体应有 `width/height` 或 `aspect-ratio` 预留空间；`object-fit` 决定框内适配，不等于内容裁切总是可接受。

## 溢出是产品决策

区分 wrap、clip、ellipsis、scroll 和 expand。`text-overflow: ellipsis` 只解决视觉，不自动提供完整内容，也不适合多行所有场景。页面级横向滚动通常是 bug，数据表或代码区的局部横向滚动可能是正确答案。
