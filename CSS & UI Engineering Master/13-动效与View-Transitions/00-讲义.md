# 第 13 章：动效与 View Transitions

## 动效要解释状态变化

有用的运动回答“什么出现了、从哪里来、与什么连续”。先定义状态与中断语义，再选择 transition/keyframes/View Transition。动画不是默认装饰；持续时间、距离和 easing 应与层级、距离和输入反馈匹配。

Transition 适合两个状态间插值；keyframes 适合多阶段或循环；`@starting-style` 与 `transition-behavior: allow-discrete` 能改善 display/top-layer 元素的进出场，但需能力检测与静态 fallback。不要为了动画把语义隐藏状态长期留在可交互树中。

## 性能模型

transform/opacity 常可在 composite 阶段处理，但“只动画这两个属性”不是绝对规则；先 profile。filter、大模糊、超大 layer 也会昂贵。`will-change` 只在即将动画的少量元素短期使用，到处添加会增加内存和合成成本。

动画必须处理快速重复、反向、组件卸载、页面后台、数据迟到。CSS end event 不应成为业务正确性的唯一开关。

## Reduced motion 与渐进增强

`prefers-reduced-motion: reduce` 不等于所有动画瞬间消失：保留必要状态反馈，移除大范围位移、视差和持续运动。内容默认可见，动画失败不能让它永远 opacity 0。

同文档 View Transitions 是新近可用能力；跨文档、复杂类型和 scroll-driven animations 在 2026 仍处互操作推进。使用 feature detection，核心导航与内容不依赖过渡。
