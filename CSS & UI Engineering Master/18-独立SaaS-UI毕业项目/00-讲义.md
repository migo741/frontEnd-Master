# 第 18 章：独立 SaaS UI 毕业项目

## 项目：NomadOps 运营工作台

你要交付一套真实 UI 系统，而不是 18 个互不相干的 Demo。范围控制在：登录/注册、App Shell、Dashboard、订单表、筛选工具栏、编辑表单、设置/Billing、Dialog/Popover、通知。数据可用 fixture，视觉和状态必须完整。

## 必交证据

1. Cascade/layer 图、token 三层表、组件公开样式契约。
2. 320/768/1280/1440 与 240/480/800 容器截图。
3. Light/dark、compact/comfortable、中文/英文/RTL、长文本状态。
4. 键盘路径、200%/400% zoom、forced-colors、reduced-motion 检查。
5. Chromium/Firefox/WebKit 视觉回归和 baseline 审批记录。
6. CSS/字体资源预算、CLS/INP/LCP 与一次 Performance trace。
7. 至少两个渐进增强：Container Query 必修；View Transition、Anchor、scroll-driven 中选一，关闭后功能完整。
8. 一份 ADR：为何选择当前 CSS 架构而不是另一方案；退出/迁移条件是什么。

## 评分（100）

- 机制正确与韧性 20；布局/响应式 15；视觉层级/主题 15；可访问性 20；架构/可维护性 15；性能/交付 10；说明与证据 5。
- 页面级意外横向滚动、键盘无法完成主流程、主题下关键信息不可辨、核心功能依赖实验 CSS，任一项都不能毕业。
- 80 分是高级 UI Engineering 线；90 分以上要求设计变化能由 token/container/稳定契约承受，而非复制 DOM/CSS。

## 答辩方法

每个决策按“内容/用户约束 → 浏览器模型 → 候选方案 → 失败模式 → 测量证据 → fallback”回答。不要说“Grid 比 Flex 高级”“transform 永远性能好”“现代浏览器都支持”。高级感来自准确边界。
