# 第 02 章：格式化上下文、定位与层叠上下文

## 先找到坐标系和滚动者

定位问题应依次回答：元素参与哪种 formatting context？它的 containing block 是谁？实际 scroll container 是谁？是否创建 stacking context？被谁裁切？

Normal flow 决定块与行内的基本排布。BFC 会隔离浮动并抑制外边距折叠，可由 `display: flow-root` 明确创建；不要为了“触发 BFC”随手加 `overflow: hidden`，那还会改变滚动和裁切语义。

绝对定位元素通常相对最近的已定位祖先，但 transform、contain 等也可能建立 containing block。`position: fixed` 遇到 transformed ancestor 时可能不再相对 viewport。`sticky` 在达到阈值前参与流，随后相对最近滚动机制祖先吸附；祖先 overflow、缺少 inset、空间不足都可能让它看似失效。

## z-index 不是全球排名

stacking context 像独立的牌组。子元素无论 `z-index` 多大，都不能跳出父牌组压过父级之外更高的 context。常见创建者包括 positioned + 非 auto z-index、opacity < 1、transform、filter、isolation、某些 contain。调试时找 context tree，而不是把数值继续加大。

真正的模态浮层优先使用 `<dialog>` 或 Popover 进入 top layer，避免困在应用局部 stacking context；但焦点、关闭协议属于组件行为，CSS 不能替代语义和脚本。

## 滚动是一种架构

一个应用壳应明确唯一主要滚动区，局部表格/代码块才建立嵌套滚动。过多 `overflow: auto` 会破坏 sticky、键盘焦点可见性、滚动恢复和移动端体验。`overflow: clip` 裁切但不建立可滚动区域，语义不同于 hidden。
