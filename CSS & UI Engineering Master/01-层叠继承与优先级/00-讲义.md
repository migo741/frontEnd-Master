# 第 01 章：层叠、继承与优先级

## CSS 的核心不是优先级数字

浏览器为同一属性选择声明时，先比较相关性，再依次考虑来源与重要性、上下文、cascade layer、specificity、作用域接近度，最后才是出现顺序。只背 `ID > class > element` 会在 animation、用户样式、`!important`、layer 和 scoped rules 出现时失效。

普通 author declarations 中，未分层样式会胜过同来源的 layer 样式；layer 内部按预先声明顺序决定，后层胜前层。`!important` 会反转 layer 优先次序，这正是它不适合作为常规覆盖手段的原因。

```css
@layer reset, vendor, base, components, utilities, overrides;

@layer components {
  :where(.button) { color: var(--button-fg); }
  .button[data-tone="danger"] { --button-fg: white; }
}
```

`:where()` 的 specificity 永远为零，适合可覆盖的基础规则；`:is()`、`:not()`、`:has()` 本身不加权，但参数中最高权重会参与计算。嵌套也可能把高权重参数传播给一组规则，不能因为写法短就认为权重低。

## 继承和初始值

文本相关属性多会继承，盒模型属性通常不会。`inherit` 强制继承，`initial` 回到规范初始值，`unset` 按属性是否自然继承选择，`revert` 回退到较早来源，`revert-layer` 回退当前 layer。组件 reset 常用 `font: inherit`，但全局 `all: unset` 会同时移除重要的原生可用性表现，必须逐项恢复。

## 工程策略

- 用 layer 表达组织决策，而不是靠文件加载偶然性。
- 组件基础选择器保持低权重；状态用 `data-*` 或语义 pseudo-class。
- 为第三方 CSS 单独建 vendor layer；不要复制它的 DOM 细节制造更长选择器。
- 把 `!important` 限制在用户强制偏好、原子 utility 的明确契约或无法控制的外部边界，并记录原因。
- DevTools 中沿 Styles → Computed → Matched CSS Rules 查 winner，不要继续加选择器试错。
