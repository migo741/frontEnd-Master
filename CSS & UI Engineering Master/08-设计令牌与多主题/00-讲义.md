# 第 08 章：自定义属性、设计令牌与多主题

## Token 是决策接口

设计令牌不等于把每个数值改成变量。合理分三层：primitive 描述原始尺度，semantic 描述用途，component token 描述组件契约。

```css
:root {
  --blue-600: oklch(52% .18 255);
  --color-action: var(--blue-600);
  --button-bg: var(--color-action);
}
```

业务组件依赖 semantic/component token，不直接依赖 `--blue-600`，这样换品牌/主题时语义不变。不是所有一次性尺寸都值得 token 化；token 应有命名、owner、使用范围和弃用策略。

## Custom property 的运行时特性

自定义属性参与 cascade、默认继承，值在使用处解析。fallback `var(--x, value)` 只在变量未定义或无效时生效，不会在变量值“业务上不合理”时自动回退。循环引用会使值无效。`@property` 可声明语法、继承和初始值，并让数值/颜色更可靠地动画，但应提供普通 custom property fallback。

## 主题策略

基础主题放 `:root`，系统暗色用 `@media (prefers-color-scheme: dark)`，用户显式选择用 `data-theme` 覆盖。设置 `color-scheme` 让原生控件、滚动条和表单适配。SSR 页面应在首个 paint 前确定主题，避免 FOUC；脚本只设置属性，组件 CSS 不复制两套。

forced-colors 下浏览器可能替换作者颜色。使用系统颜色、可见 border 和 `forced-color-adjust` 的克制例外，不能把整页锁死在自定义颜色。
