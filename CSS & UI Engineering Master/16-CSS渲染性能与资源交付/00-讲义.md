# 第 16 章：CSS 渲染性能与资源交付

## 从关键渲染路径定位

CSS 通常 render-blocking：HTML → CSSOM → render tree → style → layout → paint → composite。优化要指出瓶颈属于网络、style recalculation、layout、paint 还是 composite。缩短 CSS 文件不等于用户一定更快；关键 CSS、缓存、压缩、优先级和字体/图片共同决定首屏。

## Style 与 Layout

复杂 selector 本身往往不是最大问题，巨大 DOM + 高频 state change 才会放大匹配。用 Performance 的 Recalculate Style、Layout 和 invalidation tracking 取证。containment 可限制影响范围；`content-visibility:auto` 能跳过离屏渲染，但需配 `contain-intrinsic-size` 减少滚动条/CLS，并检查查找、焦点和辅助技术表现。

## Paint 与 Composite

大面积 blur、filter、阴影、fixed background 和 overdraw 会增加绘制。提升 compositor layer 可能减少 repaint，也会占显存；`will-change` 不是默认优化。动画前后使用 Layers/Rendering 面板验证。

## 资源交付

删除未使用 CSS 要防动态 class 被误删；utility 构建需静态可发现或 safelist。按路由拆 CSS 避免重复和加载瀑布。图片声明尺寸、使用响应式资源；字体 subset/preload/font-display/metrics 联合管理。SSR 主题初始化要避免 FOUC，同时 CSP 方案要明确。
