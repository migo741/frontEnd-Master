# CSS & UI Engineering Master

> 调研与编写基线：2026-08-30。适合已经会写普通页面、具备 JavaScript / Vue 3 中级基础，希望独立交付高质量 SaaS 界面并达到高级前端 UI Engineering 水平的学习者。

这不是 CSS 属性字典，也不是照设计稿堆像素。课程目标是建立一套能预测布局、控制层叠、适应未知内容、兼顾无障碍与性能、可以长期演进的界面工程能力。

## 固定学习顺序

每章只有三个入口：

```text
章节/
├── 00-讲义.md
├── 01-练习/
│   └── README.md
└── 02-答案/
    └── README.md
```

1. 先读 `00-讲义.md`，在浏览器中验证讲义中的反例。
2. 再做 `01-练习/README.md`。每章只有两题：一题经典机制，一题生产场景。
3. 卡住 45～60 分钟后再看 `02-答案/README.md`；看完关闭答案，从空文件复写关键部分。

答案展示的是判断过程，不是唯一视觉风格。布局题必须在内容变化、缩放和多个 viewport 下验收；动效与新特性必须提供降级路径。

## 推荐节奏

- 标准路线：20～24 周，每周 7～10 小时。
- 第 01～09 章解决“布局为什么这样”；第 10～15 章解决“产品是否真的可用”；第 16～18 章解决“上线后是否可靠”。
- 每完成三章，用同一组件做一次无框架复写；如果只能在组件库里拼出效果，还没有掌握 CSS。

## 毕业标准

- 能用 DevTools 解释最终样式来自哪个 origin、layer、selector 和继承链。
- 不使用随机 `z-index: 99999`、到处 `!important`、无依据固定高度解决问题。
- 页面在 320px 到宽屏、200% 文本缩放、键盘、强制色与 reduced motion 下可用。
- 能从 intrinsic sizing、min-size、containing block、stacking context 定位布局故障。
- 使用 Grid/Flex/Container Query 的选择有明确依据，并有合理 fallback。
- 提供 visual regression、浏览器矩阵、性能 trace 和可访问性验收证据。
- 毕业项目总评至少 80/100，其中韧性、可访问性、工程边界任一项不得低于 12/20。
