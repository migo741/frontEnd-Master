# 2026 CSS 与 UI Engineering 市场调研和能力地图

## 结论

现代岗位依然把 HTML/CSS、Flex/Grid、响应式与跨浏览器作为前端基本盘；更高级的 UI Engineering 则要求复杂组件、设计系统、可访问性、动效、性能、视觉还原和质量保障。框架不能替代这些能力：Vue/React 负责描述状态，浏览器最终仍通过 CSS 的层叠、布局、绘制与合成生成界面。

近期企业岗位样本明确出现语义化 HTML、CSS Flex/Grid、复杂业务组件、H5/响应式、Web Vitals 与多端维护；设计系统岗位进一步要求 token、DOM 标准、组件文档和可访问的复杂交互。课程因此不从颜色和选择器语法入门，而是聚焦可证明的高级交付能力。

## 2026 平台基线

已经成熟、应作为生产必修的能力包括 Cascade Layers、`:is()` / `:where()` / `:has()`、CSS Nesting、Grid/Subgrid、size container queries、逻辑属性、现代视口单位、`color-scheme`、`prefers-*`、`content-visibility` 等。

Anchor Positioning、container style queries、Dialog/Popover 新行为、scroll-driven animations、跨文档 View Transitions 等仍是 Interop 2026 的重点。它们非常值得学习，但课程按“能力检测 + 渐进增强 + fallback”使用，而不是假设所有目标浏览器行为完全一致。

浏览器支持不是一句“现代浏览器都支持”。项目应维护真实 browser matrix，结合 Baseline、MDN compatibility、Web Platform Tests 和真机验证决定是否启用。对新特性使用 `@supports`，但也要注意：语法被识别不代表每个边界行为都一致。

## 高级能力分层

| 层级 | 表现 | 本课程证据 |
|---|---|---|
| 能写页面 | 能照图实现固定页面 | 不作为课程终点 |
| 机制熟练 | 能预测层叠、尺寸、布局和定位 | 01～07 章反例实验 |
| UI 工程 | 能做 token、主题、复杂组件和无障碍 | 08～15 章组件资产 |
| 生产负责 | 能控制性能、兼容、回归和演进 | 16～18 章报告与门禁 |

## 与现有 Master 的关系

- `JavaScript 与浏览器高级学习问题` 负责渲染流水线和 DOM 机制；本课负责把机制落实为 CSS 决策。
- `Vue Master`、`React Master` 负责组件状态和框架更新；本课负责样式边界、视觉状态和浏览器布局。
- `Frontend Architecture Master` 负责设计系统治理；本课负责 token、组件样式和视觉回归的实际实现。
- 不重复教学 Vue scoped CSS、React 组件 API 的基础用法，只审查它们如何影响层叠、SSR 和复用。

## 资料依据

- [Interop 2026 官方说明](https://web.dev/blog/interop-2026)：列出 Anchor Positioning、style queries、Dialog/Popover、scroll-driven animations、View Transitions 等互操作重点。
- [MDN CSS 指南](https://developer.mozilla.org/en-US/docs/Web/CSS)：语法、模块、浏览器兼容与无障碍入口。
- [Web Platform Baseline](https://web-platform-dx.github.io/web-features/)：判断能力是否跨主流浏览器形成稳定基线。
- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)：可访问性验收基线。
- [Web Vitals](https://web.dev/articles/vitals)：用户体验指标及测量方法。
- [2026 企业前端岗位样本](https://www.oumeng.com.cn/frontend/recruiting/detail.html?id=111)：Flex/Grid、复杂组件、H5/SSR、多端与 Web Vitals。

## 维护规则

每季度只做三类更新：检查 Baseline/Interop 状态；用项目的真实浏览器数据调整 matrix；复跑毕业项目 visual、a11y 和 performance 回归。不要为了追新属性改写稳定组件，也不要因旧浏览器传闻永远停用已经成熟的 Web 平台能力。
