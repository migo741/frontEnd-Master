# 第 04 章：Flexbox 一维布局

## Flex 是分配一条主轴上的剩余空间

Flex 算法从 flex base size 出发，计算 free space，再按 grow 或 scaled shrink factor 分配，同时受 min/max 限制。`flex: 1` 常展开为零 basis 的可增长项，`flex: auto` 保留内容基础尺寸；它们在内容不等长时结果不同。

默认 `min-width:auto` 让 item 至少维持内容最小宽度，因此可伸缩搜索框常需 `min-inline-size:0`。`flex-shrink:0` 应只给确实不能压缩的操作，不要给所有项，否则容器只能溢出。

## 对齐的三个误区

- `justify-content` 分配主轴剩余空间，若没有剩余空间就看不出效果。
- `align-items` 作用交叉轴；baseline 对齐对文字/控件工具栏通常比 center 更自然。
- `margin-inline-start:auto` 能吸收剩余空间，但换行后行为必须验证。

Flex 的 visual order 不应通过 `order` 与 DOM 大幅分离。键盘和读屏顺序仍主要跟 DOM，窄屏重排应优先改变 wrapping 和布局，而非颠倒任务顺序。

## 何时不用 Flex

需要行列共同对齐、跨行共享轨道时用 Grid；纯文本自然流不要强行 Flex；只有单项定位不值得创建复杂 flex contract。选择布局模型应来自关系，而不是熟悉程度。
