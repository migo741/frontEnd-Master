# 第 13 章：拓扑排序与依赖调度

## 1. 生产动机：依赖顺序不是简单排序字段

Monorepo 构建、数据库迁移、CI 工作流、课程先修关系都要求“先完成依赖，再执行当前项”。这不是按 priority 或名称排序，而是一个**偏序**：有些节点必须先于另一些，彼此无依赖的节点顺序不唯一且可并行。

若依赖形成环：A 等 B，B 等 C，C 又等 A，就不存在合法执行顺序。高级实现不能只返回 `false`，还要给出一条真实 cycle witness，让工程师能修配置。

本章目标：

- 区分 DAG、偏序和拓扑序；
- 用 Kahn 算法维护入度不变量；
- 用稳定 ready 集合得到确定输出；
- 在失败时恢复一条真实环路径；
- 从拓扑序推导关键路径；
- 模拟受并发限制的依赖执行，并传播失败阻断。

## 2. 图方向必须先冻结

课程任务输入采用：

```ts
interface Task {
  readonly id: string;
  readonly dependencies: readonly string[];
}
```

`A.dependencies=[B]` 表示 A 依赖 B，执行顺序 `B -> A`。内部建立：

- `dependencies[A]`：A 等谁；
- `dependents[B]`：B 完成后可能解锁谁；
- `indegree[A]`：A 尚未满足的依赖数。

很多 topo bug 来自一会儿把边读作 `A->B`，一会儿又按 `B->A` 减入度。画一条具体边并写成中文，是编码前必须做的动作。

## 3. DAG、偏序与拓扑序

**DAG** 是有向无环图。拓扑序是节点的线性排列，使每条先行边 `u -> v` 中 u 都出现在 v 前。

```text
tokens -> ui -> app
   \             ^
    -> docs ------|
```

可能顺序：tokens,ui,docs,app；也可能 tokens,docs,ui,app。没有依赖的 ui/docs 互换仍合法。因此测试不应只接受一个硬编码数组，除非契约明确稳定 tie-break。

拓扑序存在当且仅当图无环。环内每个节点至少还等一个环内前驱，永远不会变成 ready。

## 4. Kahn 算法

1. 计算每个节点 indegree；
2. 所有 indegree=0 节点进入 ready；
3. 反复取一个 ready 节点 u 输出；
4. 对每个 dependent v，`indegree[v]--`；变成 0 时加入 ready；
5. 输出数若小于 V，剩余图有环。

```text
依赖：A<-B, A<-C, B<-D
即 B依赖D，A依赖B/C

初始 indegree: A=2 B=1 C=0 D=0
ready={C,D}
取 C: A=1
取 D: B=0 -> ready B
取 B: A=0 -> ready A
取 A: 完成
```

### 核心不变量

- 已输出节点组成合法拓扑前缀；
- 对每个未输出节点，当前 indegree 恰好等于来自未输出节点的依赖边数；
- ready 恰好包含未输出且当前 indegree=0 的节点。

取 ready 不会违反依赖；删去 u 的出边后只影响其 dependents。若最终没有 ready 却仍有节点，每个剩余节点至少有一个剩余依赖，沿依赖不断走，在有限节点中必重复，形成环。

## 5. 稳定输出需要有序 ready

ready 用普通数组 FIFO，会受到输入 rows 与邻接表插入顺序影响。构建缓存 key、快照测试和调试通常希望确定性：可用按 ID 的最小堆，或有序集合。

稳定不等于唯一数学拓扑序，而是我们在多个合法候选中定义 tie-break。复杂度从 O(V+E) 变为 O((V+E)+V log V)，通常值得换可复现结果。

若 priority 参与 ready 顺序，必须强调它只能在“当前依赖已满足”的候选中比较，不能让高优先级越过未完成依赖。

## 6. cycle witness：不能从 Kahn 剩余集合随便拼

Kahn 能告诉你有环，但剩余集合还可能包含“依赖环的下游”而不在环内。要返回真实路径，可在原 dependency 边上做 DFS 三色标记：

- white：未访问；
- gray：在当前 DFS 路径；
- black：已完整结束。

从 current 遇到指向 gray ancestor 的边，就是 back edge。沿 parent 从 current 回到 ancestor，重建：

```text
A -> B -> C -> A
```

路径首尾相同，每相邻 pair 必须确实是输入中的依赖边。深图在 JS 中用显式 frame 栈，避免递归溢出。

## 7. 拓扑序不是执行计划的全部

一个 topo 数组把可并行节点也线性化了。真实计划器还需要：

- 并发上限；
- ready tie-break/资源需求；
- 实际或估算 duration；
- 失败是否重试、阻断哪些下游；
- 取消、公平、资源池与可观测事件。

单机模拟器维护两个优先队列：

- ready：依赖已满足，按 priority/ID 选下一项；
- running：按 endTime/ID 找下一批完成任务。

同一时刻完成的任务应先全部 settle，再启动新任务，否则输入迭代顺序可能改变 ready 集合和结果。

## 8. 失败传播

若任务 X failed，它的直接 dependent 不能立刻都标 blocked；有的还在等待其他依赖。但当某任务所有依赖都 settled 时：

- 全部 success -> ready；
- 至少一个 failed/blocked -> 当前任务 blocked，并把这个结果继续传播给下游；

无关分支继续运行。blocked 是“未执行，因为前置失败”，不能混成 failed（自己运行后失败），否则重试与诊断错误。

## 9. 关键路径

在 DAG 且 duration 已知时，无限并发下最短完工时间由最长依赖链决定：

```text
earliestFinish[v] = duration[v] + max(earliestFinish[d] for d in dependencies[v])
```

按拓扑序计算，依赖结果已就绪。保存产生最大值的 predecessor 可重建关键路径。关键路径是无限资源下界；并发受限时，资源竞争可让实际 makespan 更长。

若 duration 只是估算、任务共享 CPU/IO，结果只是模型，不应冒充 SLA 保证。

## 10. 复杂度与边界

- Kahn（普通队列）O(V+E)，空间 O(V+E)；稳定堆 ready 增加 O(V log V)。
- cycle DFS O(V+E)。
- 模拟每任务/边常数处理，堆操作约 O((V+E) log V)。
- 关键路径 O(V+E)。

重复依赖边会把 indegree 多算，必须拒绝或去重并记录。未知节点、自依赖、空 ID 在建图阶段失败。百万边时字符串/Set 对象开销显著，可先把 ID 映射整数、用紧凑邻接数组。

## 11. TypeScript/生产边界

- 外部 JSON 先运行时验证，再建图；失败不发布半个索引。
- duration/priority 必须是有限、安全范围，累加检查溢出。
- topo 只处理显式边；遗漏动态 import、环境、生成物会得到“算法正确但模型错误”的缓存事故。
- 单进程模拟器不执行 shell、不持久化、不提供跨进程 lease；真实 CI/工作流是另一层系统。

## 12. 测试

对 topo 断言每条 dependency 的 position 更小，不只比整个数组。随机小 DAG 可从一个随机顺序只添加向后边，保证无环；再人工加回边并验证 witness 每条边存在。

模拟器覆盖菱形、完全独立、长链、同时完成、并发 1/大于 V、失败阻断与无关分支。并发 1 的 makespan 应为所有实际运行任务 duration 之和；无限并发无失败时应等于关键路径长度。
