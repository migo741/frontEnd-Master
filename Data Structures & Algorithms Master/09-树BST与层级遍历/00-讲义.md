# 第 09 章：树、BST 与层级遍历

## 1. 生产动机：层级数据不是“多套一层数组”

组织架构、评论、文件目录、AST、DOM、权限继承和配置覆盖都具有父子层级。真实问题不止是渲染缩进：输入可能无序、有孤儿或环；树可能深到递归栈溢出；移动子树必须防止把父节点挂到自己的后代；缓存的 subtreeSize 要与结构同步。

另一类树用于索引。二叉搜索树让每次比较排除一侧，但若不维护形状，升序插入会退化成链。平衡树训练的是“在局部修改后恢复全局不变量”。

本章目标：

- 准确定义根、父、子、叶、深度、高度、子树与森林；
- 使用前序、中序、后序和层序遍历，并选择递归/显式栈；
- 维护 BST 有序不变量；
- 理解退化与 AVL 旋转，不把平衡当魔法；
- 从无序 flat rows 构建可验证的组织树；
- 原子移动子树并维护祖先聚合值。

## 2. 术语与表示

```text
          A             depth(A)=0
        /   \
       B     C           depth(B)=1
      / \     \
     D   E     F         leaves D,E,F
```

- 根 root：没有父节点；
- 边 edge：父子连接；
- 深度 depth：根到节点的边数；
- 高度 height：节点到最深叶的边数（也可定义节点数，必须统一）；
- 子树 subtree：某节点及其全部后代；
- 森林 forest：若干互不相交的树。

通用树可用 `children: Node[]`，也可用 flat rows：

```ts
interface OrgRow { readonly id: string; readonly parentId: string | null }
```

flat 形式适合传输与数据库；内存 children 索引适合遍历。两者同时保存时就是多索引一致性问题。

## 3. 四种遍历回答不同问题

### 前序：先节点，再子树

顺序 A,B,D,E,C,F。适合复制树、输出目录、从父向子传播配置。

### 后序：先子树，再节点

顺序 D,E,B,F,C,A。适合计算目录大小、subtreeSize、删除子树，因为父依赖子结果。

### 中序：左、节点、右

主要用于二叉树。BST 中序得到有序键。

### 层序：按深度

BFS 队列得到 A,B,C,D,E,F。适合最近层级、最浅匹配。

递归代码与数学定义接近，但 JavaScript 不应假设深度 100,000 仍安全。显式栈把调用帧状态放到堆上：

```ts
const stack = [root];
while (stack.length > 0) {
  const node = stack.pop()!;
  visit(node);
  // 为保持从左到右，逆序压栈。
  for (let i = node.children.length - 1; i >= 0; i -= 1) stack.push(node.children[i]!);
}
```

后序迭代要区分“第一次进入”和“子树已经完成”：stack 元素可为 `{node, exiting}`，进入时压入 exiting 标记和子节点，退出时聚合。

## 4. 二叉搜索树（BST）

对每个节点：

```text
左子树所有 key < node.key < 右子树所有 key
```

重复键策略必须明确：Set 可忽略重复；Map 可更新 value；多重集合可保存 count。不能有时放左、有时放右。

查找 7：

```text
        8
      /   \
     3     10
      \
       6
        \
         7
```

7<8 向左；7>3 向右；7>6 向右。成本 O(height)。平衡时 height O(log n)，升序插入普通 BST：

```text
1
 \
  2
   \
    3
     \
      4
```

高度 n-1，操作退化 O(n)。因此“BST 查找 O(log n)”必须附带平衡/随机形状前提。

## 5. AVL 平衡与旋转

本章定义空节点高度 0、叶节点高度 1：

```text
height(node)=1+max(height(left),height(right))
balance=node.leftHeight-node.rightHeight
```

AVL 不变量要求每个节点 balance ∈ {-1,0,1}。插入沿搜索路径返回时更新高度；第一个失衡点有四种形态：LL、RR、LR、RL。

右旋修复 LL：

```text
        y                 x
       / \               / \
      x   C   right      A   y
     / \      ---->         / \
    A   B                  B   C
```

旋转只改变 y、x、B 三处连接。中序仍是 A,x,B,y,C，所以 BST 顺序不变；重新计算 y 再计算 x 的高度，恢复局部聚合。LR 先对左子节点左旋，再对 y 右旋；RL 对称。

旋转的核心不是背图，而是验证：中序不变、无节点丢失、父子连接正确、高度重算顺序正确。

## 6. 为什么不要求手写红黑树删除

AVL/红黑树代表“有序动态集合保持对数高度”的思想。生产中应优先使用成熟库或数据库索引；手写完整删除与并发版本容易出错。本章实现 AVL insert/search 用来练不变量和旋转，删除作为加餐。

数据库 B-tree/B+tree 不是把内存 BST 换个名字。它让一个页节点包含很多 key/child，降低磁盘/缓存页 I/O 高度，并处理分裂、合并、并发和恢复。理解 BST 是索引基础，不等于已经会数据库内部原理。

## 7. 从 flat rows 构树：验证顺序很重要

安全流程：

1. 第一遍创建 `id -> internal node`，拒绝空/重复 ID；
2. 第二遍验证 parent 存在且不是自己，再建立 children；
3. 确认根数量符合契约；
4. 从根迭代遍历，维护 visited；重复进入说明环/多父，最终 visited 数不足说明有断开环；
5. 迭代后序计算 subtreeSize；全部成功后才发布索引。

不要边读边挂载并返回半棵树；输入无序意味着 child 可能先于 parent。

## 8. 移动子树的不变量

把 X 从 oldParent 移到 newParent：

```text
oldParent -X-> subtree(size=s)
newParent +X-> subtree
```

先从 newParent 沿 parent 链向根走。如果途中遇到 X，newParent 是 X 的后代，移动会成环，必须在修改前拒绝。

验证通过后：

- oldParent.children 删除 X；newParent.children 加入 X；X.parentId 更新；
- oldParent 及祖先 subtreeSize 全减 s；
- newParent 及祖先全加 s。

两条祖先链在 LCA 以上重合，先减再加会自然抵消。所有错误检查要在第一处 mutation 前完成，失败保持旧树。

## 9. 复杂度

| 操作 | 普通树/索引 | AVL |
|---|---:|---:|
| 构建与全遍历 | O(V+E)，树中 E=V-1 | — |
| 祖先链 | O(height) | — |
| move + 聚合更新 | O(oldHeight+newHeight) | — |
| 查找/插入 | — | O(log n) |
| 中序输出 | — | O(n) |

children 若用 Set，按 ID 删除在常见实现期望高效；数组删除需 O(childCount)。Set 的迭代顺序是插入顺序，不一定是产品想要的业务顺序；需要 `position` 字段或显式排序。

## 10. TypeScript/JavaScript 陷阱

- 外部 JSON 即使标注 OrgRow[] 也需运行时验证。
- 递归 DFS 会因外部深度栈溢出；构建验证和遍历用显式栈。
- 对象引用 children 暴露后，调用方可绕过索引 mutation；内部节点必须私有，查询返回 ID/快照。
- comparator 不一致会让 BST 搜不到已插入键。
- 缓存 height/subtreeSize 是性能优化，也是新的正确性负担；必须有慢速重算 oracle。

## 11. 测试

AVL 对随机插入序列，在每次 insert 后全树验证 BST 上下界、height 公式、balance<=1、节点数；中序与原生 Set 排序比较。升序插入 1..10000，根高度应为 O(log n)，不能成链。

组织树覆盖无序输入、重复、孤儿、自环、多节点环、多根、10 万深链、移动到自身/后代、同父 no-op、跨分支移动。每次 move 后用 O(n) 后序重新计算 size，与缓存比较。
