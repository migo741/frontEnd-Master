# 第 01 章：算法思维、复杂度与不变量

> 学习顺序：先完整阅读本讲义，再进入 `01-练习`，最后用 `02-答案` 做复盘。主语言为 TypeScript。

## 1. 为什么高级工程师仍然要学算法分析

生产系统很少直接问“这段代码的大 O 是多少”，但每天都在用另一种方式问同一个问题：

- 数据从 100 条增长到 100 万条，响应时间会怎样变化？
- Vue 页面卡顿来自 DOM、网络，还是在 computed 中反复做了平方级计算？
- 一个批处理为什么平时很快，却偶尔拖垮 Node.js 事件循环？
- 为了把时间从 `O(n²)` 降到 `O(n log n)`，多用一份 `O(n)` 内存是否值得？
- 代码“看起来能跑”之外，如何证明它不会遗漏边界条件？

算法思维不是背题型，而是建立四步工作流：

1. 明确输入、输出和约束。
2. 找到决定正确性的核心不变量。
3. 估算时间、空间以及隐藏成本。
4. 用测试和生产约束验证推导，而不是只相信样例。

高级工程师的价值往往不在于写出第一版，而在于能解释：为什么正确、在多大规模下仍然可用、何时应该换方案。

## 2. 基本术语

### 2.1 输入规模 `n`

`n` 必须对应问题中真正增长的量。数组问题里通常是元素数；图问题可能同时有顶点数 `V` 和边数 `E`；字符串问题要分清 JavaScript 的 UTF-16 code unit 数量和用户看到的字符数量。

不要把所有问题机械写成一个 `n`。例如合并两个数组的合理复杂度是 `O(n + m)`，而不是含糊写成 `O(n)`。

### 2.2 渐进记号

- `O(f(n))`：增长上界。工程讨论中通常指最坏情况下的渐进上界。
- `Ω(f(n))`：增长下界。
- `Θ(f(n))`：上下界同阶，能更精确地描述增长速度。
- 最坏复杂度：所有规模为 `n` 的输入中最差的情况。
- 平均复杂度：依赖输入分布；没有分布模型时不要随意声称“平均”。
- 摊还复杂度：把偶尔昂贵的操作摊到一串操作上。例如动态数组扩容单次可能是 `O(n)`，连续追加的摊还成本通常是 `O(1)`。

常见增长顺序：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
```

常数仍然重要，但它回答的是另一个层次的问题。渐进分析先判断增长曲线，基准测试再比较同一数量级里的常数、缓存、运行时优化和 I/O。

### 2.3 空间复杂度

必须说明统计口径：

- 总空间：包含输入本身。
- 辅助空间：算法额外申请的空间。
- 调用栈：递归每层的栈帧也属于辅助空间。

说“原地算法”通常表示辅助空间为 `O(1)`，不表示它一定不修改输入，也不表示绝对没有任何分配。API 契约必须另外说明 mutation 行为。

## 3. 如何逐步推导复杂度

### 3.1 顺序语句相加，保留主导项

```ts
function summarize(values: readonly number[]): number {
  let total = 0;                     // O(1)
  for (const value of values) {      // n 次
    total += value;                  // 每次 O(1)
  }
  return total;                      // O(1)
}
```

总时间 `T(n) = c1 + c2*n + c3`，渐进结果为 `Θ(n)`，辅助空间 `Θ(1)`。

### 3.2 嵌套循环不一定都是 `O(n²)`

先数“内层语句总共执行几次”。

```ts
for (let i = 0; i < n; i += 1) {
  for (let j = i + 1; j < n; j += 1) {
    // 常数工作
  }
}
```

次数为 `(n-1) + (n-2) + ... + 1 = n(n-1)/2`，所以是 `Θ(n²)`。

而下面两个指针虽然写在一个循环里，指针各自最多前进 `n` 次，总成本仍是 `Θ(n)`：

```text
left  ---> 最多 n 步
right ---> 最多 n 步
总步数 <= 2n
```

这类“总移动次数”分析会在双指针、滑动窗口和单调队列中反复出现。

### 3.3 每次按比例缩小通常产生对数

如果规模从 `n` 变成 `n/2`，经过 `k` 次后为 `n / 2^k`。当它降到 1：

```text
n / 2^k <= 1
2^k >= n
k >= log₂n
```

所以二分搜索需要 `Θ(log n)` 次比较。对数底数只带来常数倍，渐进记号中通常省略。

### 3.4 递归要同时计算调用次数和栈深度

```ts
function factorial(n: number): number {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

调用次数 `Θ(n)`，最大递归深度也是 `Θ(n)`，因此辅助空间为 `Θ(n)`。在 JavaScript 中，大输入还可能触发 `RangeError: Maximum call stack size exceeded`；尾递归优化不能当作通用生产保证。

## 4. 不变量：把“我觉得对”变成可证明

不变量是在算法某个重复位置始终成立的命题。证明通常分三步：

1. 初始化：第一次进入循环前成立。
2. 保持：假设本轮开始时成立，执行一轮后仍成立。
3. 终止：循环结束时，不变量与终止条件共同推出结果正确。

### 4.1 用半开区间推导 lower bound

目标：在升序数组中找到第一个 `>= target` 的位置；如果不存在，返回 `values.length`。

我们维护未确定区间 `[left, right)`：

```text
已确定 < target       未确定             已确定 >= target
[0 ........ left) [left ........ right) [right ........ n)
```

核心不变量：

- `[0, left)` 中所有元素都 `< target`。
- `[right, n)` 中所有元素都 `>= target`。
- 正确答案始终在 `[left, right]` 中；`right` 可以等于 `n`。

初始 `left = 0, right = n`，左右已确定区域都为空，因此命题自然成立。

取 `mid = left + Math.floor((right - left) / 2)`：

- 若 `values[mid] < target`，则 `[0, mid]` 都可排除，令 `left = mid + 1`。
- 否则 `mid` 可能就是答案，不能丢掉，令 `right = mid`。

每轮区间严格缩小。终止时 `left === right`，未确定区间为空，左右不变量共同说明该位置就是第一个 `>= target` 的位置。

```ts
export function lowerBound(
  values: readonly number[],
  target: number,
): number {
  let left = 0;
  let right = values.length;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (values[mid]! < target) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return left;
}
```

时间 `Θ(log n)`，辅助空间 `Θ(1)`。

## 5. 从约束反推算法

算法选择不是从“我会哪种结构”开始，而是从规模和服务等级目标开始。

粗略经验不是性能承诺，但能帮你提前排除明显错误：

| 输入规模 | 通常可优先考虑 |
| --- | --- |
| `n <= 20` | 指数搜索、回溯，但仍需剪枝 |
| `n <= 10³` | `O(n²)` 可能可接受，需要基准测试 |
| `n <= 10⁵` | 常见目标是 `O(n log n)` 或 `O(n)` |
| `n >= 10⁶` | 关注线性扫描的常数、内存、流式处理和 I/O |

生产上还必须加入：请求并发数、数据表示的字节量、垃圾回收压力、主线程预算、是否能预处理、是否需要增量更新。

一个 `O(n)` 算法如果每轮都创建大对象，可能输给稳定的 `O(n log n)` 原地实现。复杂度是筛选器，不是基准测试的替代品。

## 6. TypeScript / JavaScript 特有陷阱

### 6.1 `Array.prototype.shift()` 不是队列的免费午餐

普通数组头部删除通常要移动后续元素，单次为 `O(n)`。循环 `shift()` 可能退化为 `O(n²)`。后续章节会实现带 head 指针的队列。

### 6.2 `sort()` 默认按字符串比较且会修改原数组

```ts
[2, 10, 3].sort(); // [10, 2, 3]
```

数值排序要传比较函数，并明确是否允许 mutation：

```ts
const sorted = [...values].sort((a, b) => a - b);
```

复制本身需要 `Θ(n)` 时间与空间，不能在复杂度说明中漏掉。

### 6.3 `number` 的安全整数边界

JavaScript `number` 是 IEEE 754 双精度浮点数。整数精确范围受 `Number.MAX_SAFE_INTEGER` 限制。计数、时间戳相减、前缀和可能越界时，要校验、改用 `bigint`，或调整数据契约。`number` 与 `bigint` 不能直接混算。

### 6.4 字符串索引不等于用户字符

`text.length` 统计 UTF-16 code units；某些 emoji 占两个以上 code units。`[...text]` 更接近 Unicode code point，但组合字符仍可能是多个 code point。涉及光标、截断和字数限制时，应考虑 `Intl.Segmenter`。

### 6.5 类型安全不等于运行时安全

`readonly number[]` 可以阻止本函数在类型层面修改输入，却不能保证外部数据真的是数字数组。来自网络、localStorage 或 JSON 的值必须先做运行时校验。

## 7. 常见错误

- 只看循环嵌套层数，不计算指针的总移动次数。
- 忽略排序、切片、扩展运算符、JSON 序列化等隐藏的线性成本。
- 把哈希表操作无条件写成最坏 `O(1)`；更严谨的表述通常是期望或摊还 `O(1)`。
- 只写时间复杂度，不写辅助空间和是否修改输入。
- 用几个示例代替正确性证明。
- 二分时混用闭区间与半开区间，导致死循环或越界。
- 未定义空输入、重复值、非法值和数值溢出的行为。

## 8. 何时不要自行实现复杂算法

- 标准库或成熟库已提供经过审计的实现。
- 数据量很小，清晰的线性代码比复杂优化更安全。
- 瓶颈实际是数据库、网络或渲染，算法优化不会改变用户体验。
- 需求尚未稳定，复杂索引结构会提高维护成本。
- 正确性涉及密码学、压缩、金融舍入等专业领域，应优先使用专业实现。

先测量，再优化；但在架构评审阶段仍要能识别必然会爆炸的增长曲线。
