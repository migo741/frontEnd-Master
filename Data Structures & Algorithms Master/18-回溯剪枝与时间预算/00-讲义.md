# 第 18 章：回溯、剪枝与时间预算

## 1. 当所有组合都可能需要考虑

一个 SaaS 套餐配置器有几十个功能：A 依赖 B，C 与 D 冲突，某组必须且只能选一个，企业策略又强制开启 E。用户问“有没有一组合法配置？”这不再是简单筛选。某个早期选择可能到很深才暴露冲突，需要撤销并尝试另一条路。

**回溯（backtracking）**把候选方案看成决策树，按以下循环搜索：

```text
选择一个决策 -> 应用选择 -> 深入探索 -> 不成立就撤销 -> 尝试下一选择
```

它本质上仍可能是指数级。高级工程能力不是把指数复杂度说成“优化后很快”，而是：用约束尽早排除不可能分支；优先选择最可能暴露冲突的变量；设置节点/时间/内存预算；取消时返回明确状态；对找到的结果进行独立验证。

本章完成后，你应该能：

- 把组合问题画成决策树；
- 写出 choose/explore/unchoose 的状态不变量；
- 区分可行性剪枝、上界剪枝与记忆化；
- 使用 MRV/高约束优先等启发式改变搜索顺序；
- 让搜索支持 `AbortSignal` 和节点预算；
- 区分 `unsatisfiable` 与 `budgetExceeded`，不能把“没搜完”谎报成“无解”。

## 2. 用 N 皇后理解决策树

在 `n × n` 棋盘上放 `n` 个皇后，使任意两个不共享行、列或对角线。若按行放置，第 `row` 层决定这一行选哪一列：

```text
row 0: col 0 / col 1 / ... / col n-1
          |
row 1: 过滤与上一行冲突的列
          |
...
```

已经按行放置，所以无需再记录占用行。需要三个集合：

- `columns`：已占用列 `col`；
- `diagDown`：主对角线标识 `row - col`；
- `diagUp`：副对角线标识 `row + col`。

两个格子在同一主对角线，当且仅当 `row-col` 相同；在同一副对角线，当且仅当 `row+col` 相同。

### 搜索不变量

进入 `search(row)` 时：

1. `0..row-1` 每行恰有一个皇后；
2. 这些皇后两两不冲突；
3. 三个占用集合与棋盘中已放皇后精确对应。

尝试 `(row,col)` 时，先检查三个集合；可行才加入，递归到下一行，返回后必须删除。**撤销必须与选择完全对称**，否则兄弟分支会读到污染状态。

```text
选择前: columns={1}, diagDown={-1}, diagUp={1}
在 row=1 尝试 col=3
选择后: columns={1,3}, diagDown={-1,-2}, diagUp={1,4}
递归返回
撤销后: 必须精确恢复第一行状态
```

当 `row === n`，不变量推出已经合法放置 `n` 个皇后，得到一个解。

## 3. 剪枝究竟剪掉什么

### 可行性剪枝

一旦部分方案已经违反硬约束，它的任何扩展都不可能合法，立即返回。例如两个皇后同列、功能 A 已选但其依赖 B 被禁止。

这种剪枝不丢解，因为被剪分支无法修复既有冲突。

### 上界剪枝（branch and bound）

用于优化问题。若当前价值加上“剩余部分最乐观的价值上界”仍不超过已知最好值，就无需深入。上界必须乐观，即不能低估该分支可能达到的最好值，否则可能错误剪掉真正最优解。

### 对称性剪枝

若多个分支只是等价重命名，可只搜代表。例如 N 皇后第一行左右镜像。但在加入位置权重或固定棋子后，对称性可能消失，不能机械套用。

### 记忆化

若不同路径到达完全相同的未来状态，可以缓存“此状态无解/最优值”。关键是状态键必须包含影响未来的一切。把不同的部分配置错误合并，会产生漏解。

## 4. 搜索顺序不改变正确性，却决定能否及时返回

约束满足问题常用：

- **MRV（Minimum Remaining Values）**：先选合法取值最少的变量，尽快暴露死路；
- **degree heuristic**：平局时先选与其他未定变量约束最多者；
- **least constraining value**：先尝试对其他变量限制最少的值；
- 业务偏好：先尝试更可能满足用户意图的值，以便更早得到可用解。

这些启发式通常只改变分支顺序，不改变解集合。若启发式直接删除候选，就必须有正确性依据。

## 5. 功能配置是布尔 CSP

每个功能变量取 `true/false`。常见约束：

- `required(A)`：A 必须为真；
- `forbidden(B)`：B 必须为假；
- `A implies B`：若 A 为真，B 必须为真；等价地，B 为假会迫使 A 为假；
- `conflicts(A,B)`：两者不能同时为真；
- `exactlyOne(A,B,C)`：三者中恰有一个为真。

每次赋值后可以做**约束传播**：

```text
A=true 且 A=>B  -> B=true
A=true 且 A 冲突 C -> C=false
exactlyOne 中已有一个 true -> 其余全部 false
exactlyOne 中无 true 且只剩一个 unknown -> 它必须 true
```

传播直到没有新赋值；若同一变量同时被迫 true/false，或 exactlyOne 不可能满足，当前分支失败。

这比先给所有变量赋值、最后才验证快得多，因为冲突越早出现，整棵后代子树越早被剪掉。

## 6. 克隆状态还是原地撤销

两种实现方式：

1. 每个分支克隆状态。代码简单、较不易污染，代价是 `O(numberOfVariables)` 的复制与 GC。
2. 原地修改并记录 trail，回溯时反向撤销。更高效，但每种写入都必须进入日志，容易出错。

课程答案对生产配置器优先用克隆，先保证正确性；profile 证明复制成为瓶颈后再改 trail。N 皇后状态很小，使用对称 add/delete 足够清晰。

## 7. 预算、取消与结果语义

搜索 API 至少区分：

```ts
type SolveResult<T> =
  | { status: "solved"; value: T; visitedNodes: number }
  | { status: "unsatisfiable"; visitedNodes: number; reason?: string }
  | { status: "budgetExceeded"; visitedNodes: number; bestEffort?: T }
  | { status: "aborted"; visitedNodes: number };
```

只有完整穷尽搜索空间后才能返回 `unsatisfiable`。节点预算耗尽只说明“在预算内没找到/没证明”，不能缓存成永久无解。

检查取消不能只放最外层。可每访问一定数量节点检查 `signal.aborted`，降低开销又保持响应性。长 CPU 搜索仍不应阻塞浏览器或 Node 主事件循环；需要 Worker、任务切片或专用求解服务。

## 8. 复杂度

若有 `m` 个布尔变量，朴素搜索最多 `2^m` 个叶；N 皇后粗略上界接近 `n!` 个按行列排列。剪枝改变实际访问节点数，但不自动改变最坏指数级事实。

空间通常是 `O(depth + state)`；克隆状态时同时存活的是一条递归路径上的若干副本，可能达到 `O(depth × variables)`。结果计数可能超过安全整数，N 皇后解数建议用 `bigint`。

## 9. 测试与独立验证

搜索器很容易因为撤销或传播 bug 返回“看起来像解”的数据。因此不要让求解器自己充当唯一裁判。写一个简单、无剪枝、只负责检查完整配置的 validator；每个 `solved` 结果都再验证。

测试至少包含：直接矛盾、传播后矛盾、恰有一解、多解、无约束、未知 feature、预算为 0、取消、确定性与随机小规模对照。记录 `visitedNodes`，它既帮助观察剪枝效果，也能发现版本退化。

## 10. 何时换专业求解器

当约束不断增长、需要优化多个目标、生成最小冲突核心、保证求解性能或由非算法专家维护规则时，应评估 SAT/SMT、CP-SAT 或 ILP 求解器。手写回溯适合学习、边界清晰的小模型和可控核心，不应因“没有依赖”就重复制造一个脆弱求解平台。

## 11. 速记、自检与 AI 追问

速记：**回溯 = 维护合法部分解；剪枝必须证明不会删掉需要的解；预算耗尽不等于无解。**

自检：

1. N 皇后 `row-col` 为什么能标识一条主对角线？
2. choose 与 unchoose 不对称会怎样污染搜索？
3. MRV 改变的是结果还是访问顺序？
4. 什么条件下能安全缓存“这个状态无解”？
5. 为什么求解结果还要独立 validator？

交给 AI 时请附上变量域、全部硬约束、目标是“找一个/找所有/计数/求最优”、预算与取消语义、是否允许近似。否则 AI 很可能把启发式当成正确性规则。
