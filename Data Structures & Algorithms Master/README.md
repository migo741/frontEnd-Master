# Data Structures & Algorithms Master

> 编写与调研基线：2026-08-30。面向已经具备 JavaScript 与 Vue 3 中级能力，希望从“能完成功能”进阶到“能分析、设计并交付可靠系统”的学习者。

这不是 LeetCode 题单，也不是为了背诵模板。课程的核心目标是：面对一个真实问题，你能把模糊需求抽象成数据、状态和约束；选择合适的数据结构；写出可解释的算法；证明关键性质；估算时间与空间；最后处理生产环境中的容量、并发、失败、取消和可观测性。

课程以严格 TypeScript 作为可执行表达语言，但知识本身跨语言。以后切换 Java、Go、Python 或 Rust 时，数组、堆、图、动态规划与复杂度分析仍然成立；改变的只是内存模型、标准库和工程习惯。

## 每章固定结构

```text
章节/
├── 00-讲义.md
├── 01-练习/
│   └── README.md
└── 02-答案/
    └── README.md
```

学习顺序不能颠倒：

1. 先读 `00-讲义.md`，亲手追踪至少一个例子，并回答章末自检。
2. 再做 `01-练习/README.md`。每章恰好两题：第一题校准核心机制，第二题接近生产或允许开放设计。
3. 独立思考 45～90 分钟后再看答案。不会做不等于失败；照答案复写一次、关掉答案再复写一次，依然能建立能力。
4. `02-答案/README.md` 不是只有代码。你需要阅读建模、不变量、复杂度、失败边界、测试和替代方案。

## 推荐节奏

- 标准路线：24～30 周，每周 7～10 小时。
- 第 01～05 章必须打牢；如果键、边界和复杂度说不清，不要急着做动态规划。
- 每完成四章，从自己的真实项目里找一个数据处理问题重写：缓存、筛选、权限树、请求队列、构建依赖都可以。
- 不要求默写所有算法，但要求能在没有模板时重新推导核心不变量。

## 毕业标准

- 能用输入规模、操作频率、数据分布和内存预算解释结构选择，而不是说“这个更快”。
- 能为关键循环、递归、堆、图遍历写出不变量，并用它解释正确性。
- 能区分最坏、平均、期望、摊还复杂度；不会用一次小样本 benchmark 代替复杂度分析。
- 能识别 JavaScript/TypeScript 的 Unicode、数字精度、递归深度、`Array.shift()`、`Map` 相等语义等陷阱。
- 面对环、重复输入、超大输入、取消、超时、内存上限和部分失败时，程序有明确行为。
- 毕业项目能在固定数据集上给出正确性测试、性质测试、性能数据和设计说明。
