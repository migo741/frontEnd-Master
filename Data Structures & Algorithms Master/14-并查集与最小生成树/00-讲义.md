# 第 14 章：并查集与最小生成树

## 1. 生产动机：不断合并“属于同一组”的关系

账号与设备实体归并、网络连通分组、图片像素连通域、Kruskal 最小生成树都反复询问：

- x 和 y 当前是否属于同一集合？
- 若不是，把两组永久合并。

如果每次合并都遍历整组改 groupId，最坏会重复移动大量元素。**并查集（Disjoint Set Union，DSU / Union-Find）**用一片父指针森林表示互不相交的集合，并通过路径压缩与按规模合并，让大量 find/union 的摊还成本接近常数。

本章目标：

- 理解 parent forest、root representative、find 和 union；
- 推导路径压缩与 union-by-size 的不变量；
- 知道“近常数”是摊还 `O(α(n))`，不是单次严格 O(1)；
- 用 Kruskal 构建最小生成森林；
- 识别 DSU 不能撤销、不能删除边、不能解释业务真相的边界；
- 把身份归并输出成可审查计划，而不是直接破坏性合并。

## 2. 父指针森林

每个元素有 parent。根满足 `parent[root]===root`，作为该集合 representative：

```text
0       3
|\      |\
1 2     4 5

parent=[0,0,0,3,3,3]
```

`find(x)` 沿 parent 到根。`connected(a,b)` 等价于 `find(a)===find(b)`。

representative 只是内部代表，不自动是业务 canonical ID。路径压缩/合并顺序会改变根；若业务要求最小 ID，应该在输出分组后显式选择，不把 DSU root 当业务承诺。

## 3. union 的错误做法与按规模合并

若总把第二棵根挂到第一棵，恶意顺序可形成长链：

```text
0 <- 1 <- 2 <- 3 <- 4
```

find(4) O(n)。union-by-size 把较小树根挂到较大树根：小树所有节点深度最多加 1；一个节点每次深度增加时，所在集合规模至少翻倍，所以仅靠此策略高度 O(log n)。rank 是高度上界的另一种策略；size 与 rank 不要混用含义。

```ts
if (size[rootA] < size[rootB]) swap(rootA, rootB);
parent[rootB] = rootA;
size[rootA] += size[rootB];
```

只有 root 的 size 有效，非 root 槽位可保留旧值但不能读取为集合规模。

## 4. 路径压缩

find 时把沿途节点直接挂到根：

```text
压缩前: x -> p -> q -> root
压缩后: x -----> root
        p ------> root
        q ------> root
```

递归版简短，但外部/未平衡旧数据可能深；迭代两趟更安全：第一趟找到 root，第二趟把路径节点 parent 改为 root。

核心不变量：parent 关系始终是若干以自父根结束的树；find 只把节点改挂到同一棵树的根，不改变集合成员关系。union 只连接两个不同根，所以不会产生有向环。

两种优化合用，一串 m 次操作的总复杂度为 `O(m α(n))`；α 是反 Ackermann 函数，在现实规模极小。它是摊还结论，仍不要说“每次必然严格 O(1)”。

## 5. DSU 能回答什么，不能回答什么

适合：只增加等价/连通边，询问当前是否连通或最终分组。

不适合：

- 删除边后是否仍连通；
- 撤销一次错误 union；
- 输出两点之间具体路径；
- 处理有方向的可达性；
- 保存“为何合并”的全部证据（需另外存边）；
- 在线跨进程一致合并（需要持久事务/日志）。

离线删除可倒序处理，复杂动态连通可用 rollback DSU、segment tree over time 或其他结构，但不是基础 DSU 自动具备。

## 6. 最小生成树（MST）

给定无向加权连通图，生成树连接全部 V 个节点、无环且恰有 V-1 条边。MST 是总权重最小的生成树。图不连通时得到每个连通分量的**最小生成森林**。

它不同于最短路径树：MST 最小化所有选边总和，不保证某个源到每点路径最短。

## 7. Kruskal 算法

1. 所有边按 weight 和确定 tie-break 升序；
2. 初始每节点独立 DSU；
3. 扫描边 `(u,v)`：若 u/v 已连通，加入会成环，跳过；否则 union 并选边；
4. 连通图选到 V-1 边即可停止。

```text
边: AB=1, BC=2, AC=3, CD=4
选 AB -> {A,B}
选 BC -> {A,B,C}
AC 两端已连通，跳过
选 CD -> 全连接，总权 7
```

### cut property 直觉

把当前森林任一分量与其余节点切开。按权重扫描到第一条跨越这个 cut 且能连接两个分量的边时，存在一棵 MST 包含它：若某 MST 用了另一条跨 cut 边，可用当前不更重的边替换，保持连通且不增加总权。反复安全选择得到 MST/forest。

权重相同可能有多个 MST；稳定 edge ID tie-break 只保证输出可复现，不改变最小总权。

## 8. 身份归并：数学等价不等于业务真相

证据边说“两个记录可能是同一客户”。等价关系具有传递性：A~B、B~C 推出 A~C，DSU 正适合闭包。但真实证据可能错误；一次 union 很难撤销并会放大传递影响。

安全离线流程：

1. 只接受已验证格式和来源的候选 evidence edge；
2. DSU 形成 connected components；
3. 每组收集全部成员与证据；
4. 检查硬冲突：跨租户、多个不同 verified email、法规边界等；
5. 无冲突组输出 merge proposal；有冲突组输出 review case，不修改主数据；
6. canonical ID 用明确稳定规则选，例如字典序最小/最早创建，而不是 DSU root；
7. 真正合并由事务、审计、重定向与可逆计划执行。

算法只说明“按给定边连通”，不能证明证据本身正确。

## 9. 复杂度与内存

DSU 初始化 O(V)；m 次 union/find 总 `O(m α(V))`；空间 O(V)。Kruskal 排序 O(E log E)，DSU 部分近 O(E α(V))，总由排序主导；空间 O(V+E)（若边已外部排序，可流式降低内存）。

大图边无法装内存时可外部排序；若图稠密或已有邻接矩阵，Prim 可能更自然。选算法要看输入表示。

## 10. TypeScript/JavaScript 陷阱

- 数组下标 DSU 要验证 0<=x<n 与整数；负下标会变对象属性，不是元素。
- 递归 find 不应假定任意历史 parent 深度安全；答案用迭代。
- totalWeight 浮点累加有精度；金额/精确成本用最小整数单位并检查安全范围，或 BigInt 版本。
- 业务 ID 先映射连续整数能显著减少大规模 Map/对象开销。
- union 后 root 可能变化，外部不得缓存 root 当永久 ID。

## 11. 测试

DSU 与慢 oracle 对比：oracle 保存组件 label，union 时扫描改 label；随机操作比较 connected 与 component size。每次验证 parent 最终可到自父 root、无越界环、root size 总和为 n。

Kruskal 小图可枚举边子集，过滤每分量的生成树/森林并比较最小权；通用性质检查选边无环、在原图每个连通分量内连通、边数 V-components。
