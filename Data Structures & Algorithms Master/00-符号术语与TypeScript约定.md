# 符号、术语与 TypeScript 约定

## 复杂度符号

- `n`：主要输入规模。它可能是元素数、节点数或字符数；每题必须重新定义。
- `V`、`E`：图的顶点数与边数。
- `k`：需要的结果数、窗口大小或较小的第二维规模。
- `O(f(n))`：渐进上界；增长最终不会比某个常数倍的 `f(n)` 更快。
- `Ω(f(n))`：渐进下界。
- `Θ(f(n))`：上下界同阶。
- **最坏复杂度**：所有合法输入中最差的代价。
- **期望复杂度**：对随机性或输入分布取期望，必须说明随机来源和假设。
- **摊还复杂度**：一串操作的总成本除以操作数；不是概率意义的平均。

Big-O 忽略常数和低阶项，但工程决策不能因此忽略常数、缓存局部性、分配、GC、网络与磁盘。`O(n)` 的顺序数组扫描可能比 `O(log n)` 但频繁随机访问/远程调用更快；先比较数量级，再测真实 workload。

## 正确性语言

- **前置条件**：调用者在执行前必须保证的事实。
- **后置条件**：成功返回时函数保证的事实。
- **不变量**：初始化后为真，并在每一步操作后继续为真的事实。
- **终止度量**：每一步都严格接近终止、且不能无限下降的量，例如未处理区间长度。
- **稳定性**：排序键相等的元素是否保留原相对顺序。
- **幂等**：同一操作重复执行，产生的可观察结果与执行一次相同。

讲义中的“证明”以工程级论证为主：说明初始化为何成立、一次迭代为何保持、终止时为何推出后置条件。它不替代形式化验证，但比“样例跑通”可靠得多。

## 数据与索引约定

- 区间默认使用半开区间 `[start, end)`：包含 `start`，不包含 `end`，长度恰为 `end - start`。
- 下标从 `0` 开始。
- 函数默认不修改调用方传入的数据；原地算法会在签名和文字中明确说明。
- 除非题目另说，相等使用 `Object.is`/`Map` 的 SameValueZero 语义所对应的实际 API；对象键按引用相等，而不是深度相等。
- 有序结果若需要稳定同序，会使用显式 `sequence` 作为最终 tie-breaker，不能依赖未声明的偶然顺序。

## TypeScript 基线

示例默认：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true
  }
}
```

代码片段强调算法核心，不会每次重复参数解析、日志和完整工程脚手架。生产题需要你补充运行时验证，因为 TypeScript 类型在运行时会被擦除，外部 JSON 不会因写了接口就自动可信。

## JavaScript/TypeScript 必记陷阱

### 数字

`number` 是 IEEE-754 双精度浮点数。整数绝对值超过 `Number.MAX_SAFE_INTEGER` 后不能保证逐个精确表示。计数、时间戳差值和 ID 运算要先确认范围；必要时使用 `bigint`，但 `number` 与 `bigint` 不能直接混算，JSON 也不原生支持 BigInt。

### 字符串

字符串索引和 `length` 基于 UTF-16 code unit，不等于用户看到的字符数。`[...text]` 按 Unicode code point 迭代，仍可能拆开由多个 code point 组成的 grapheme cluster（例如带肤色修饰或组合音标的 emoji）。面向用户可见字符时考虑 `Intl.Segmenter`。

### 数组

索引读写与尾部 `push/pop` 常见实现通常高效；头部 `shift/unshift` 需要移动/重排后续元素，不能把它当稳定 O(1) 队列。稀疏数组、不同元素类型和超大分配还会影响引擎表示。

### Map 与 Set

它们适合表达键值与集合，但 ECMAScript 只要求平均访问时间“次线性”一类的性能特征，并不承诺你的程序在所有实现、所有输入上严格 O(1)。课程分析会注明“常见哈希实现下的期望/摊还”而不是伪造规范保证。

### 递归

JavaScript 运行环境普遍不应假定尾调用优化或无限调用栈。输入深度来自外部时，递归 DFS、树遍历和分治必须评估栈溢出，必要时改成显式栈。

### 时间与基准

测量使用单调时钟（浏览器 `performance.now()` 或 Node 的性能 API），但必须预热、重复、记录环境并防止无效工作被优化。微基准不能自动推导生产延迟；复杂度、profile 和真实数据回放需要结合。
