# 第 08 章：二分查找与单调谓词

## 1. 二分不是“猜中某个值”

日志按时间排序，产品要找 `[start,end)` 的事件；灰度系统要找第一个达到错误阈值的版本；容量规划要找“最小可行并发度”。这些问题的共同点不是“数组里恰好有 target”，而是搜索空间被一个**单调边界**分成两部分：

```text
false false false | true true true
                  ^ 第一个 true
```

二分每次用中点判断边界在哪一半，把候选区间缩小约一半。它的核心是：定义谓词、边界与循环不变量。背 `while (left <= right)` 模板却说不清区间含义，是 off-by-one 的主要来源。

本章完成后，你应能：

- 用半开区间 `[lo,hi)` 推导 lower/upper bound；
- 在重复元素、空数组和不存在目标时返回稳定插入位置；
- 把“找值”改写为“找第一个满足单调谓词的位置”；
- 在答案空间上二分最小可行值；
- 识别谓词不单调、浮点不收敛、昂贵远程 predicate 等边界。

## 2. 三个不同问题

给定有序数组 `[1,2,2,2,5]`，target=2：

- 任意等值位置：1、2、3 都可；
- `lowerBound`：第一个 `>= target` 的位置，答案 1；
- `upperBound`：第一个 `> target` 的位置，答案 4。

于是等值范围是 `[lowerBound, upperBound)`，出现次数为两者之差。target 不存在也自然返回插入位置：target=4 时 lower=upper=4。

稳定工程 API 通常更需要 lower/upper bound，而不是随机命中一个重复值。

## 3. lowerBound 的半开区间推导

目标：返回最小下标 `i`，使 `array[i] >= target`；若没有，返回 `n`。

维护搜索区间 `[lo,hi)`，循环不变量：

1. 所有下标 `< lo` 的元素都严格 `< target`，不可能是答案；
2. 所有下标 `>= hi` 的元素都 `>= target`（或是数组末端哨兵），答案不会在 hi 右侧；
3. 真正边界一定在闭合意义的 `[lo,hi]` 中；代码待搜索元素位于 `[lo,hi)`。

初始化 `lo=0, hi=n`：左侧和右侧已排除区域都为空，成立。

```text
while (lo < hi) {
  const mid = lo + Math.floor((hi - lo) / 2);
  if (array[mid] < target) lo = mid + 1;
  else hi = mid;
}
return lo;
```

若 `array[mid] < target`，mid 及其左侧都不是答案，所以 `lo=mid+1`；否则 mid 可能就是第一个满足者，不能丢掉，令 `hi=mid`。

每轮 `[lo,hi)` 长度严格减小，最终 `lo===hi`。根据不变量，lo 左边都不满足，lo 起都满足，所以 lo 是第一个满足位置。

```text
array = [1,2,2,2,5], target=2

[lo,hi)=[0,5), mid=2, a[2]>=2 -> hi=2
[0,2),       mid=1, a[1]>=2 -> hi=1
[0,1),       mid=0, a[0]< 2 -> lo=1
lo=hi=1
```

## 4. upperBound 只改谓词，不换一套模板

upperBound 找第一个 `> target`，所以“不满足区”是 `<= target`：

```ts
if (array[mid] <= target) lo = mid + 1;
else hi = mid;
```

不要靠记忆“小于号有没有等于”；先写目标谓词 `P(i)`，lower bound 本质上找 first true：

```text
P(i) = array[i] >= target   -> lowerBound
P(i) = array[i] > target    -> upperBound
```

## 5. 泛型比较器与全序

对象数组需要比较器 `compare(a,b)`：负数表示 a<b，0 表示等价，正数表示 a>b。它应满足：

- 反对称/符号对称：`sign(cmp(a,b)) = -sign(cmp(b,a))`；
- 传递：a<b 且 b<c，则 a<c；
- 与排序数组使用的是同一顺序定义。

若排序按 `(timestamp,sequence)`，二分也必须按同一复合键。只比较 timestamp 会把同刻事件视为相等，分页可能重复或漏项。

```ts
interface OrderedEvent { readonly timestamp: number; readonly sequence: number }
const compareEvent = (a: OrderedEvent, b: OrderedEvent): number =>
  a.timestamp < b.timestamp ? -1 :
  a.timestamp > b.timestamp ? 1 :
  a.sequence < b.sequence ? -1 :
  a.sequence > b.sequence ? 1 : 0;
```

避免 `a.timestamp - b.timestamp` 用于可能超过安全范围的整数；明确分支更稳妥。

## 6. 答案空间二分

有时没有数组，只有一个候选整数范围和可行性函数：

```text
canHandle(concurrency) = 服务是否能在目标延迟内处理给定负载
```

若并发容量越大就越可行（这里要谨慎定义），可找最小可行值。整数 first-true：

```ts
function firstTrue(lo: number, hiExclusive: number, predicate: (x: number) => boolean): number {
  while (lo < hiExclusive) {
    const mid = lo + Math.floor((hiExclusive - lo) / 2);
    if (predicate(mid)) hiExclusive = mid;
    else lo = mid + 1;
  }
  return lo;
}
```

但现实性能指标常有噪声，并发提高可能因缓存、抖动产生非单调结果；一次远程压测也很昂贵。必须先证明/验证单调假设，缓存 predicate 结果，重复采样并定义统计判定。不能因为代码能二分就把随机实验变成单调数学函数。

## 7. 浮点二分不是整数模板

浮点数不能用“mid+1”。通常按误差或固定迭代次数停止：

```text
while (hi-lo > epsilon) ...
```

要说明绝对/相对误差、NaN/Infinity、数值范围。若要找精确离散业务值，先把单位变成整数（分、毫秒、字节块）往往更安全。

## 8. 复杂度与隐藏成本

二分比较次数 `O(log n)`，额外空间 O(1)。但返回 `array.slice(lo,hi)` 需要 O(k) 时间和空间；比较器若解析日期、做网络请求，实际成本乘上 predicate 成本。

插入有序数组虽然找到位置 O(log n)，移动后续元素仍 O(n)。二分优化的是定位，不自动优化更新。高频中间插入可能要树、分块数组、数据库索引或批量归并。

## 9. JavaScript/TypeScript 陷阱

- `mid = (lo+hi)>>1` 会把数转成 32-bit 有符号整数，大数组/大答案范围会溢出；用 `lo + Math.floor((hi-lo)/2)`。
- `Date.parse` 可因格式/时区产生歧义；边界层解析后传数值 Instant。
- `NaN` 与任何 `<`/`>=` 比较都为 false，会破坏全序；输入必须拒绝或定义排序位置。
- 数组必须在比较器意义下有序。二分不会检测“基本有序”。
- `sort()` 会修改原数组；索引快照要明确可变性和版本。

## 10. 测试方法

定向覆盖：空、单项、全小于、全大于、全部等于、目标在首尾、重复块。性质测试：

- `0 <= lower <= upper <= n`；
- lower 左边全 `< target`，右边全 `>= target`；
- upper 左边全 `<= target`，右边全 `> target`；
- 与线性 firstIndex oracle 相等；
- equalRange 长度等于 filter 计数。

## 11. 何时不用二分

- 数据无序且只查一次：线性扫描可能更便宜。
- predicate 不单调或无法可靠判断。
- 数据很小，复杂模板增加错误风险。
- 查找在远程数据库：让索引和查询优化器工作，不要先拉全量到内存。
