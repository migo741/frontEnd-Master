# 第 17 章：动态规划与方案重建

## 1. 动态规划不是填表口诀

离线同步前，客户端有许多待上传任务：每项消耗网络字节和 CPU 时间，带来不同业务价值；一次后台窗口的预算有限。按“价值最高”选，可能先拿走一个昂贵任务，错过多个合计价值更高的小任务；按“价值/字节”选，在任务不可拆分时也可能失败。

这类问题的共同特征是：一个大问题能拆成较小问题；不同决策会反复遇到同一个较小状态；最优解由较小状态的最优解组成。**动态规划（Dynamic Programming，DP）**把重复子问题的答案保存下来，以空间换时间。

本章目标不是背二维数组，而是掌握六个问题：

1. 状态代表什么？
2. 状态是否包含影响未来答案的全部信息，又没有多余信息？
3. 当前决策如何转移到新状态？
4. 基础状态是什么？
5. 以什么顺序计算，才能保证依赖已经就绪？
6. 除了最优值，怎样恢复实际方案？

## 2. 从暴力递归推导 0/1 背包

有 `n` 个物品，每项只能选 0 次或 1 次。物品 `i` 的重量为 `w[i]`、价值为 `v[i]`，容量为 `C`，目标最大化总价值。

先不要想表格。站在物品 `i` 前，未来只需要知道两个信息：

- 还要考虑哪一段物品；
- 剩余容量是多少。

因此定义：

```text
F(i, c) = 只考虑 i..n-1，剩余容量 c 时能得到的最大价值
```

对物品 `i` 有两个选择：

```text
不选：F(i + 1, c)
选：  v[i] + F(i + 1, c - w[i])，前提 w[i] <= c
```

所以：

```text
F(i,c) = max(F(i+1,c), v[i] + F(i+1,c-w[i]))
F(n,c) = 0
```

直接递归形成二叉决策树，最坏约 `2^n` 个分支：

```text
                 F(0,C)
              /           \
        不选0               选0
       F(1,C)          v0 + F(1,C-w0)
       /   \                 /   \
     ...   ...              ...  ...
```

不同路径会到达相同的 `(i,c)`，这就是**重叠子问题**。使用 Map/二维数组缓存递归结果称为记忆化；按依赖顺序主动填表称为自底向上 DP。

## 3. 正确状态与最优子结构

状态必须是“未来做正确决定所需的最小充分信息”。如果价格还取决于已选类别，而状态只有 `(i,c)`，两个看似相同的状态未来价值可能不同，DP 会错误合并它们。此时必须加入类别状态，或改变模型。

**最优子结构**表示：一个最优方案作出当前选择后，剩余部分也必须是对应子问题的最优方案。否则可以用更好的子问题方案替换它，得到更好的整体方案，与整体最优矛盾。

这不是所有问题都成立。若当前选择改变后续规则、产生路径相关折扣，状态必须记录这些影响；状态维度往往就是从这里长出来的。

## 4. 二维表如何对应定义

也可定义：

```text
dp[i][c] = 只使用前 i 个物品、容量上限 c 的最大价值
```

第 `i` 个物品（数组下标 `i-1`）的转移：

```text
dp[i][c] = dp[i-1][c]                                      不选
dp[i][c] = max(dp[i][c], dp[i-1][c-w] + v)                能选时
```

示例物品 `(w,v) = (2,3),(3,4),(4,5)`，容量 5：

```text
容量 c       0 1 2 3 4 5
0 个物品     0 0 0 0 0 0
加入(2,3)    0 0 3 3 3 3
加入(3,4)    0 0 3 4 4 7
加入(4,5)    0 0 3 4 5 7
```

右下角 7 对应前两项，总重量 5。

### 表格不变量

完成第 `i` 行后，对每个 `0 <= c <= C`，`dp[i][c]` 恰好等于只使用前 `i` 项且总重量不超过 `c` 的最大价值。

初始化第 0 行为 0，因为没有物品时只能得到 0。转移穷尽“选/不选”且两者互斥；每个候选都引用上一行已经正确的答案，所以保持不变量。

## 5. 为什么一维压缩必须倒序

第 `i` 行只依赖第 `i-1` 行，可把二维表压成 `dp[c]`：

```ts
for (const item of items) {
  for (let c = capacity; c >= item.weight; c -= 1) {
    dp[c] = Math.max(dp[c], dp[c - item.weight] + item.value);
  }
}
```

容量倒序意味着读取 `dp[c-weight]` 时，它仍是处理当前物品之前的旧值，所以同一物品不会被重复使用。

若容量正序，更新较小容量后，较大容量可能再次读取刚加入当前物品的新值，相当于允许无限次使用，问题偷偷变成完全背包。最小反例：一个重量 2、价值 3 的物品，容量 4；正序会得到 6，但 0/1 背包正确答案是 3。

这就是遍历顺序的语义，不是记忆口诀。

## 6. 最优值不等于可执行方案

业务通常要知道“选了哪些任务”，而不是只有价值 137。常见重建方法：

- 保留完整二维表，从 `dp[n][C]` 逆推；
- 为每个状态保存选择与前驱；
- 再跑一次受最优值约束的重建；
- 若只需值，使用滚动数组节省空间。

二维逆推时，若 `dp[i][c] !== dp[i-1][c]`，说明第 `i` 项被选择，然后令 `c -= weight`。平局时必须有契约：偏向不选、较早输入、较少资源或字典序。没有 tie-break 的“任意最优解”在测试和缓存中可能造成不稳定输出。

## 7. 双预算让状态膨胀

若任务同时消耗字节 `b` 和 CPU 单位 `t`，状态变成 `dp[b][t]`，时间约 `O(nBT)`，空间 `O(BT)`。这叫**伪多项式复杂度**：它对预算数值大小敏感，而不只是数字的位数。

若 `B=10^9` 字节，不能开十亿格数组。可选策略包括：

- 把字节按 4 KiB/64 KiB 量化，接受保守误差；
- 只保存实际可达状态，并删除被支配状态（Pareto frontier）；
- 使用贪心/近似算法并声明质量边界；
- 通过业务规则先分组、设上限或分批处理；
- 改写目标，例如优先满足必须任务，再对剩余任务优化。

DP 不是看到“最优”就无条件使用。状态数量是设计预算的一部分。

## 8. 复杂度、数值与 TypeScript 陷阱

| 方法 | 时间 | 空间 | 适用 |
|---|---:|---:|---|
| 枚举子集 | `O(2^n)` | `O(n)` 栈 | 小规模 oracle |
| 二维 0/1 背包 | `O(nC)` | `O(nC)` | 需清晰重建 |
| 一维 0/1 背包 | `O(nC)` | `O(C)` | 主要需要最优值 |
| 双预算 DP | `O(nBT)` | `O(BT)` | 两个预算都较小 |

- 数组索引必须是非负整数，浮点重量需要先定义离散化单位。
- 价值累加可能超过安全整数；超出时需 BigInt 或业务大数方案，但 BigInt 无法直接与 `Math.max` 混用。
- `Array(rows).fill(sameArray)` 会让所有行引用同一数组；二维表应为每行单独创建。
- 不要用 `-1` 同时表达“不可达”和合法负价值；可用 `Number.NEGATIVE_INFINITY` 或显式 union。
- Node/浏览器主线程上的大 DP 会阻塞事件循环；应有状态数上限、取消检查，必要时交给 Worker。

## 9. 测试策略

先写指数级 oracle，只用于 `n <= 20` 的随机小样本；它虽慢但直接，适合做差分测试。再验证以下性质：输出索引唯一；总重量不超预算；报告价值等于所选价值之和；结果不差于任何单项；增加容量不会使最优值下降。

性能测试必须覆盖多个 `n` 与预算，记录状态数、运行时间和峰值内存。一次 `n=10` 的快结果不能证明 `n=1000,C=10^7` 可用。

## 10. 何时不用 DP

- 子问题没有重复：分治或直接递归可能更自然。
- 没有最优子结构：需要更完整状态或其他模型。
- 状态空间超过预算：近似、贪心、搜索、优化求解器或业务拆分。
- 约束频繁在线变化：每次重算表可能不合适。
- 需要通用复杂约束与可解释无解原因：CP-SAT/ILP 求解器可能比手写 DP 更可靠。

## 11. 速记、自检与 AI 追问

速记：**先写暴力递归的参数，再问哪些参数影响未来；那才是状态。先定义状态含义，再写转移。**

自检：

1. 0/1 背包一维容量为何倒序？
2. `dp[i][c]` 中 `i` 和 `c` 各自代表什么？换定义会怎样改变转移？
3. 为什么 `O(nC)` 叫伪多项式？
4. 只保存最优值后，为什么不一定能恢复稳定方案？
5. 双预算过大时，至少列出三种退路。

交给 AI 时请附上完整状态定义、每一维范围、是否允许重复选、平局规则、预算单位和是否需要方案重建。只粘贴转移公式，AI 也可能把 0/1 背包误讲成完全背包。
