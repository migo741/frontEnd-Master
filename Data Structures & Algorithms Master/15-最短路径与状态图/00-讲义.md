# 第 15 章：最短路径与状态图

## 1. 生产动机：所谓“最近”必须先定义成本

服务调用路径、工作流转换、地图路线、版本迁移都在问从 source 到 target 的最低代价。但代价可能是跳数、延迟、费用、风险或它们的组合。先选算法、后想权重，会把业务问题悄悄改掉。

本章目标：

- 区分无权 BFS、Dijkstra、Bellman-Ford 与 A* 的适用前提；
- 用 relaxation 推导最短距离；
- 证明 Dijkstra 为何要求非负权；
- 使用 heap + stale entry 避免 decrease-key；
- 保存 predecessor 重建路径；
- 把“已用风险预算”加入节点状态，解决带约束路径；
- 拒绝用随意加权和掩盖多目标取舍。

## 2. 先选对图

一个节点不一定只是地名/版本。节点应表示“未来决策所需的完整状态”。若到达版本 V 时，剩余可用风险预算不同，未来选择集合不同，`V` 不能把它们合并为一个状态；要使用 `(version, riskUsed)`。

边表示一次合法转换，weight 表示可加的代价。最短路径算法通常依赖**路径代价等于边权之和**。若存在一次性折扣、最大边风险、非线性拥塞，必须扩展状态或换模型。

## 3. 无权图：BFS 已经是最短路

每条边成本相同（可视为 1）时，BFS 按跳数分层：source 距离 0；其邻居 1；再下一层 2。节点第一次入队时已经找到最少边数路径。

用 Dijkstra 也能得到答案，但堆增加不必要的 log 因子。权重只有 0/1 时还有 0-1 BFS（deque）。算法选择应反映权重结构。

## 4. relaxation：已知路径能否改善邻居

维护 `dist[v]`，初始 source=0，其他 Infinity。对边 `u -> v` 权重 w：

```text
candidate = dist[u] + w
if candidate < dist[v]:
  dist[v] = candidate
  predecessor[v] = u/edge
```

这叫松弛。它表达：先走已知到 u 的最好路径，再走一条边，是否比目前到 v 更好。

松弛本身不是 Dijkstra 专属；不同最短路算法的关键差别是以什么顺序反复松弛，以及何时能确认一个距离不会再变。

## 5. Dijkstra

前提：所有边权 `w >= 0`。用最小堆按 tentative distance 取下一个节点。

```text
S --2--> A --2--> T
 \              ^
  --5--> B --1--|

dist S=0
取 S: A=2,B=5
取 A: T=4
取 T: 4 已是最短
取 B: 经B到T=6，不改善
```

### settled 不变量与正确性

当堆中最小 tentative distance 的节点 u 被取出且 entry 是当前值时，`dist[u]` 已等于真实最短距离。

反证直觉：若还有一条更短的未知路径到 u，沿该路径从已 settled 区走向未 settled 区的第一条边，那个边界节点的 tentative distance 不会大于整条更短路径（因为后续边非负），它应比 u 更早被取出，矛盾。

负权会破坏“路径继续延伸不会变小”：

```text
S -> A cost 2
S -> B cost 5
B -> A cost -10
```

Dijkstra 可能先确认 A=2，但经 B 后得到 -5。遇到负权要拒绝或使用 Bellman-Ford/Johnson 等适用算法；存在可达负环时最短距离甚至无定义（可无限变小）。

## 6. 没有 decrease-key 时的 lazy entry

标准库常没有可按 handle 更新的堆。每次 dist 改善时直接 push 新 `(distance,node)`；旧 entry 留在堆里。pop 时：

```text
if (entry.distance !== dist.get(entry.node)) continue; // stale
```

这样可能有多份 entry，但逻辑简单。严格改善次数最多与边松弛相关，常见邻接表实现时间 O((V+E) log V/E)，通常写 O((V+E) log V) 或 O(E log V)（使用支持 decrease-key 的经典界）；lazy heap 的堆大小可到 O(E)，保守写 O(E log E)。空间 O(V+E)。

浮点距离比较 `!==` 在这里比较的是我们原样存入 Map 的同一个计算结果，作为 stale 版本判断通常可用；不要用它判断两个独立浮点路径“数学上相等”。精确业务权重应使用整数单位。

## 7. 路径重建

每次严格改善 dist[v] 时保存：

```text
prev[v] = { node: u, edgeId }
```

从 target 反向沿 prev 到 source，再 reverse。source 到自身路径为 `[source]`、边为空、距离 0。unreachable 的 dist 为 Infinity、path=null。必须防御 prev 链不终止（实现 bug/腐败数据），重建最多 V 步。

等成本路径的 tie-break 要定义。最简单是 adjacency/heap 稳定排序且只在 `<` 更新，保留先发现方案；若要求字典序最小完整路径，不能只比较最后一条边，可能需要更昂贵路径比较或二阶段处理。

## 8. 带风险预算的迁移：扩展状态图

迁移边有 `cost` 和整数 `riskUnits`，要求总风险不超过 R，目标最小 cost。不能简单定义 `weight=cost+λ*risk`：λ 是业务取舍，且某条加权最优路径仍可能超硬风险上限。

扩展状态：

```text
(version, usedRisk)
```

从 `(u,r)` 经过边 `(u->v,cost,wRisk)` 到 `(v,r+wRisk)`，前提不超过 R；新边权仍是 cost，非负，可运行 Dijkstra。最终在 `(target,0..R)` 中选 cost 最小，平局风险更小。

状态数量 O(VR)，边状态 O(ER)，这是伪多项式。R 若是百万/连续风险分数，不能直接开表；可维护每个版本的 Pareto frontier（没有另一个状态同时 cost<=且risk<=）、使用约束优化求解器，或把预算合理量化。

## 9. A* 与启发式边界

A* 按 `g(n)+h(n)` 取节点，h 是到目标剩余成本估计。若 h 可采纳（不高估）并满足一致性，可保持最优且减少探索。地图欧氏距离是常见启发式；版本迁移通常没有可靠几何启发，h=0 就退化为 Dijkstra。

不经证明使用“看起来接近目标”的 h，可能更快地返回错误非最优路径。

## 10. 多目标不是一个随意分数

同时最小化成本、风险、停机时间可能没有唯一最优：路径 A 更便宜但更危险，B 更安全但更慢，互不支配。选择包括：

- 一个指标作硬约束，另一个优化（本章做法）；
- 输出 Pareto frontier 给策略层；
- 用经业务审批的权重与版本化 ADR；
- 按优先级字典序优化。

不要把不同单位直接相加并隐藏权重。

## 11. 复杂度、输入与安全

普通 Dijkstra 邻接表+lazy heap：保守 O((V+E) log E)，空间 O(V+E)。扩展风险状态约 O((VR+ER) log(VR))，空间 O(VR+ER 的按需部分)。

外部图必须限制 V/E、字符串长度、权重和 R；否则攻击者可制造内存/CPU 拒绝服务。distance 累加检查 finite/安全范围。Node 主线程上大图计算需要 Worker/任务预算。

## 12. 测试

小图使用 Bellman-Ford 作 oracle（即使测试只生成非负权）；比较所有 dist。验证返回路径每条边存在、代价和等于 dist、起止正确。覆盖 unreachable、零权、平行边、自环、同成本、多分量、负权拒绝。

迁移 planner 对很小图枚举所有不重复路径（限制深度）或 Bellman-Ford 扩展状态 oracle，验证风险<=R 与 cost 最小。测试禁用边、刚好风险上限、只有超风险路径、状态预算拒绝。
