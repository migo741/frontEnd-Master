# 02 · 机制导读

事件模块表面上是 Map 加 Set，真正决定可靠性的往往是回调执行期间发生了什么：订阅者再发事件、删除另一订阅者、主动销毁、抛出异常。

先选政策，再写容器：本题采用**同步分发、重入事件排队、每个事件开始时截取订阅快照**。它使 `A1 → B1 → A2 → B2` 成为可验证顺序，不让回调递归造成不受控栈深度。

一个订阅是一份独立资源，unsubscribe 和 abort 都应该到达同一个释放入口。once 要在执行回调前移除，防止回调重入时再次遇到自己。错误属于 onError 通道，不能阻止其他订阅者。

对照 [DOM 规范](https://dom.spec.whatwg.org/#interface-eventtarget) 可以理解平台监听器的概念；本题是自定义业务事件模块，并不承诺复制 EventTarget 的全部语义。
