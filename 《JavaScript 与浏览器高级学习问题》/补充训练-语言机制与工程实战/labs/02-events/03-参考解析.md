# 02 · 参考解析

参考实现使用 Map(type → Set(record)) 加一个队列。emit 取 snapshot，执行前再次检查 active。once 先 off 再 callback，重入时已经看不到该项。

一个回调销毁整个 hub 后，内层循环立即停止；外层队列循环也检查 disposed。finally 清空 payload 引用，避免异常路径把队列永久留住。

读源码任务：从 emit('x',1) 开始，跟到回调内 emit('x',2)，标出何处“只入队”、何处开始第二个事件；再跟一次 once 的移除路径和 abort 的移除路径，比较它们如何汇合。

复杂度：注册/取消期望 O(1)；分发成本与本次参与检查的订阅数及新事件数成正比；每个事件复制一份订阅快照。容量与无限生产保护没有纳入基本题，必须在迁移题另定策略。

最常见错误：直接迭代实时 Set 导致新订阅本轮执行；once 在 callback 后移除导致重入重复；只删除 Map 但忘记取消 AbortSignal 上的监听器；吞掉异常却没有错误归属。
