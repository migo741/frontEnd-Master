# 01 · 机制导读

复杂业务题会同时使用很多规则。只看最终功能是否正常，容易漏掉规则理解上的空洞。本单元把每次观察压缩到一个机制。

分析一段 JS 时，按以下顺序记录：

1. **环境与调用点**：本包是 ESM，默认严格模式。普通函数的 this 看调用表达式；箭头函数读取创建位置外层 this。
2. **求值与访问**：读取一个属性可能运行 getter。对象转原始值先考虑 `Symbol.toPrimitive`；`+` 的 hint 与 `String()` 不同。
3. **对象协议**：getter 里的 this 由 receiver 决定。Proxy 转发时省略 receiver 会改变继承对象访问的行为。
4. **约束**：Proxy 不能任意谎报冻结目标的数据属性；函数也是对象，可以用作另一个对象的原型。
5. **延续与关闭**：Promise.resolve 的 getter 读取与 then 方法调用处于不同阶段；for-of 提前退出可能触发迭代器关闭。

可以查 [ECMAScript 抽象操作](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-toprimitive) 追溯步骤。该链接是持续更新的规范草案；本单元只使用已长期存在的稳定语义，不把页面年号等同于目标运行时支持范围。

每次先写预测，再运行。预测错了应保留原记录，写出是哪一步推导出了偏差。
