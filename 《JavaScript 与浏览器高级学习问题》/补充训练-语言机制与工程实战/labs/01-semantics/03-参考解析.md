# 01 · 参考解析

精确结果在 reference/predictions.json。下面解释结果的来源。

1. conversion：`+` 使用 default hint，得到7再加1；String 使用 string hint得到S。存在 Symbol.toPrimitive 时这两次都不再调用 valueOf。
2. tdz：块内 x 遮蔽外部 x；typeof 访问未初始化词法绑定仍抛 ReferenceError。块外仍是8。
3. binding：成员调用读到2；提取后的严格普通调用 this 为 undefined；call 显式传入9。箭头由严格模式普通函数空调用创建，捕获 undefined，call 无法改写。
4. bound-constructor：new 忽略绑定的 this，采用新的实例；预置参数4仍保留，后续9成为第二参数。实例同时满足两个 instanceof。
5. receiver：Reflect.get 的第三参数保留 child，getter 从 child 读取 y=6。
6. invariant：不可配置且不可写的数据属性不能被 get trap 谎报成不同值，因此抛 TypeError。
7. thenable：then getter 同步读取，then 方法在后续作业中执行；先 resolve(3) 后的 resolve(4) 不会再次改变结果；await 最后恢复。
8. iterator-close：break 导致关闭生成器，finally 写入 close。
9. sparse：map 跳过 hole，但访问显式 undefined；JSON 把两者都序列化为 null；展开通过迭代把 hole 变为实际 undefined 元素。
10. home-object：复制函数引用不会改变原方法的 HomeObject，因此 super 仍从 a 的原型取1。
11. function-prototype：函数对象也是对象，new F 的原型可以就是该函数。
12. then-getter-error：Promise.resolve 返回拒绝的 Promise；包住该调用的同步 try/catch 没捕获到异常，await 时进入 catch。

源码阅读训练：在规范里定位 ToPrimitive、OrdinaryGet（Receiver）、Proxy [[Get]]、NewPromiseResolveThenableJob、IteratorClose。每次只跟一条路径，记录输入、分支、返回和异常，不要求从头阅读规范。
