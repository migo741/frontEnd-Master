# 04 · 有界消费与可取消计算

编辑 src/index.js，实现两个函数。现成 browser harness 会把它们连接成真实数据流水线。

## A. consumeBatches

```js
await consumeBatches(source,handleBatch,{batchSize=128,signal})
// source 为 AsyncIterable，handleBatch 可同步或异步；返回成功处理的元素总数。
```

要求：batchSize为正整数；顺序不变；尾批不丢；空输入不调用下游；每批交给下游后等待它完成，期间不继续 next；传出的数组不再修改或复用。预取消不得取得iterator。

检查取消时抛原 signal.reason。下游失败、取消或上游读取失败时尝试调用 iterator.return 一次；正常读到done时不再调用return。若清理又失败，已有主异常优先。

本API依赖 source.next、handleBatch 和 return 最终结算，signal本身无法抢断任意pending Promise。浏览器source通过fetch的signal支持中止；若自行替换为不合作源，需要另定取消政策。

## B. summarize

```js
await summarize(rows,{signal,chunkSize=64,yieldTask})
// 返回 {count:rows.length,sum:所有row.value之和}
```

chunkSize为正整数，row.value必须为有限数字。每处理完一片且仍有剩余数据，调用并await yieldTask，再检查取消。默认yieldTask必须让事件循环执行其他task。空输入和预取消也要有明确结果。

本题使用固定的小整数，不讨论任意大数据集的浮点精度或总和溢出；若扩展输入域，需要增补数值契约。

## 验收

运行 `node scripts/test.mjs 04`。9项公开测试包含慢下游不预读、提前关闭、异常优先、task取消。另补“source.next拒绝时return被调用”的测试。

启动服务器，进入 `/web/stream.html`：完整处理应得到count=5000、sum=247500、maxBatch≤128、maxPending=1；中途取消后能重新开始；取消探针应显示Worker在计算中确认取消。

提供的web/stream.js负责fetch/NDJSON适配、单个在途Worker job和页面清理。其NDJSON解码只服务固定受控fixture，不声称替代原第06章对任意字节源的完整安全解码器；你可换成原作业实现并加恶意输入测试。取消探针会特意一次性构造大数组，它只测试调度，不是流式内存示范。
