# 04 · 机制导读

流的价值来自消费过程有界。读取很快、处理很慢时，如果先把每个 handleBatch Promise 全部创建出来，仍会把数据堆在内存里。

本题一次只等待一个下游批次。应用缓存上限是 batchSize；这不代表网络栈、浏览器 ReadableStream 或其他适配层没有自己的缓冲。应分别画出每一层的队列。

Worker 有自己的事件循环。主线程 postMessage(cancel) 只是在 Worker 排入消息任务，不能中断当前紧循环。每隔若干数据检查 signal 前，要先给消息任务运行机会；await Promise.resolve 只让出到微任务，不能据此保证消息任务得到执行。

本练习使用 setTimeout(0) 形成 task 层让出，并有真实 Worker 取消探针。[HTML Worker 规范](https://html.spec.whatwg.org/multipage/workers.html) 提供运行模型；背压与上下游关系可对照 [Streams 标准](https://streams.spec.whatwg.org/)。
