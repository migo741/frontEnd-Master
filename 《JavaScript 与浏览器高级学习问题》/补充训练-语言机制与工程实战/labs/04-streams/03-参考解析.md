# 04 · 参考解析

consumeBatches 手动取得异步iterator，依次next，把当前批交给下游并await。没有后台producer，所以下游停住时上游拉取次数也停住。每次使用新batch，避免消费者保存引用后内容被后续处理修改。

finally在未自然done时调用return；catch记录主失败，若清理也抛错则保留主因。本政策是一项明确工程选择，调用者若需要同时审查清理错误，可在扩展中使用AggregateError或诊断回调。

summarize 每片最多chunkSize项，片间await task层让出。Worker onmessage能在这段间隙收到cancel并abort对应controller；下一片开始前throwIfAborted。取消响应时间受单片耗时、任务调度和设备影响，本版不把固定毫秒阈值当作跨设备保证。

Web流水线：HTTP流 → 解码器 → 最多128行batch → 一个Worker job → ACK → 下一个batch。UI统计maxPending和maxBatch只能证明这两处应用队列的上限；实际总内存仍需DevTools测量。

源码阅读任务：从主线程job的cancel监听器跟到Worker的controller.abort，再跟到summarize的throwIfAborted，标出每个任务/微任务边界。

### Worker启动握手

浏览器验证中曾复现首个任务丢失：入口等待动态import时尚未安装onmessage，而主线程已经提交job。适配层现在等待Worker安装处理器后发出的ready消息，再提交首任务；同时提供启动超时和取消清理。这是基础函数的Node测试覆盖不到、需要真实浏览器验证的边界。
