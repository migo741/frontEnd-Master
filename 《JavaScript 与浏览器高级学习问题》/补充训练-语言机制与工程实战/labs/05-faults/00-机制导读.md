# 05 · 机制导读

这一单元从现象开始。先进入故障页面并收集证据，再看src。题目页不直接给出每个故障的修复代码。

可靠排障包含四步：稳定复现 → 提出至少两个假设 → 找能区分假设的证据 → 用最小修复与回归验证因果。

Node测试中资源计数和布局模拟是回归装置；它们不能代替浏览器真实Heap与Performance记录。内存要关注从根对象到被保留对象的路径，而非只看某个数字瞬时变大。[Chrome DevTools 内存排查](https://developer.chrome.com/docs/devtools/memory-problems)

性能实验把数据、设备、操作和构建条件固定。本工程直接运行原生ESM，没有开发框架和热更新插件；无需打包才能形成有效的最小机制实验。
