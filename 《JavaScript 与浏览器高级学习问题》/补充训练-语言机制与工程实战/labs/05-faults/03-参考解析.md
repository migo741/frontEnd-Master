# 05 · 参考解析

**A根因：**每个请求完成后都直接render，迟到的旧结果可以覆盖新意图。参考实现递增generation，每次请求拥有自己的id；只有当前代次且未disposed时允许render/onError。abort用于减少资源，generation用于结果归属。旧错误也必须被观察并忽略。

**B根因：**面板移除后，外部EventTarget仍拥有update回调，回调闭包保留panel。参考dispose移除同一个update引用，再移除DOM并清空局部panel。闭包本身不等于泄漏，超出预期生命周期的强引用才是本例问题。页面的订阅追踪Set也会记录相同回调，因此正确remove同时解除两处保留。

**C根因：**逐行写width后立即读几何信息，下一行又写，反复制造脏布局与同步测量。参考先批量写所有width，再遍历读取新高度。仍有N次JS读取，但浏览器有机会在首次读完成布局后复用结果。不能声称所有浏览器只会进行恰好一次布局，应以trace为证。

源码阅读任务：画createSearch中每次调用创建的代次与controller；画EventTarget→update→panel保持链；在resizeRows中为每次读写标注W/R，比较WRWR与WWRR。

性能数字不可跨设备直接对比。若优化后瓶颈转移到DOM规模或文本布局，这表示第一处瓶颈被解除，下一步才考虑虚拟化或减少内容。

**D根因：**历史会话的Service Worker从实验Cache Storage返回schema1，新发布app-v2直接按schema2读取嵌套字段，抛错使页面没有完成渲染；新会话访问网络schema2则正常。readFeature显式归一化两个受支持协议，并拒绝未知形状。兼容层支持灰度存活窗口，但不能长期替代SW升级与缓存迁移。

服务端路由当前始终返回schema2；历史缓存由安装流程稳定种下，因此故障可重复。产物app-v2.js带source map，release/releases.json列出版本和样本；web/release.js只接收同源、当前iframe来源的实验日志。清理按钮只删除本实验SW与缓存。
