# 05 · 分层提示

## 第一层：缩小范围

- A：把最后一次“发起”与最后一次“完成”分别标出来，它们是否必然是同一个请求？
- B：DOM移除后，哪些外部对象仍可能拥有回调？看保持链，不要直接换成WeakMap。
- C：检查尺寸读取前最近发生的写操作。事件只触发一次，并不代表循环只布局一次。

## 第二层：验证边界

- A：把transport改成完全忽略AbortSignal，修复是否仍正确？
- B：让dispose连调用两次，计数是否稳定；另一处事件源是否真正移除了同一个函数引用？
- C：把所有写与所有读分开，既保持新高度计算，又降低强制同步布局机会。

## 第三层：修复策略

需要请求代次与生命周期守卫、对称资源释放、批量DOM读写。具体实现放在reference中，先依据这些策略独立修改src。

## 场景D提示

第一层：比较两种会话的请求来源，而不只是比较相同URL。第二层：检查新前端读取配置时假设的形状是否与实际响应一致。第三层：在灰度窗口维护明确的协议兼容层，拒绝未知形状；再讨论Service Worker升级和缓存迁移。
