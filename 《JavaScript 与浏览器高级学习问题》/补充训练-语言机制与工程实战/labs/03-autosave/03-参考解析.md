# 03 · 参考解析

参考 createEditor 用三个层次组织：纯 state.js、拥有生命周期的 runner、页面提供的可控 transport。页面自己的300ms防抖不进入 reducer。

save 同步安装 owner，随后 Promise.resolve().then 启动循环，确保同栈第二次 save 看见现有 flight。while 每次先读取最新状态并生成快照 command；await 后先检查 disposed/epoch，再更新 serverVersion 和 SAVE_SUCCEEDED。成功但仍 dirty 时继续下一次。

open 先增加 epoch、解除当前 flight 并 abort 旧 controller，再安装新文档状态。旧任务尚可在后台结算，但它失去了提交当前状态的资格。finally 使用 `flight===owner` 防止旧任务清理掉新任务。

失败分两类：当前会话失败进入 state.error 并拒绝 save；旧会话失败被捕获后直接退出，避免污染新文档。调用方仍应接住当前 save 的拒绝，页面已经通过 try/catch 处理。

复杂度：一次编辑O(1)，每次保存使用一份文本引用和快照；默认不保存所有历史版本。活动会话只有一个在途请求；跨会话取消被忽略时，传输层可能暂时仍有多个旧请求，不能把它描述成全局并发永远为1。

参考 state.js 是原04接口的等价整理，可替换成你已经完成的原实现，只要接口和语义一致。回归测试用 deferred 明确安排回包，没有靠真实网络睡眠碰运气。
