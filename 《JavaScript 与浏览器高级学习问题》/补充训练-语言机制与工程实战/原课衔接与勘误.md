## 1. 稀疏数组编码

原01答案用`value.map(visit)`编码数组，hole被保留到中间数组，再被JSON.stringify变为null；原解码器把该null当坏标签，无法往返。

最小明确政策是“拒绝稀疏数组”，在map之前验证：

```js
for(let i=0;i<value.length;i++){
  if(!Object.hasOwn(value,i))throw new TypeError(`Sparse array at ${path}[${i}]`);
}
```

同时修改契约说明支持dense arrays；如果业务要保留hole，必须增加独立hole标签并用delete恢复，不能拿undefined标签代替。

## 2. 构造原型也可以是函数对象

原03答案只接受typeof object作为Constructor.prototype。应读取一次并同时允许function：

```js
const candidate=Constructor.prototype;
const objectLike=candidate!==null &&
  (typeof candidate==='object'||typeof candidate==='function');
const prototype=objectLike?candidate:Object.prototype;
```

这只修正原练习所限定的普通用户函数范围，不能使手写实现完全替代Reflect.construct。01单元已有function-prototype反例。

## 3. 方法观测器读取then也会改变行为

原02答案在业务调用try/catch外读取output.then；getter失败可把原本正常的返回变成同步抛错，随后Promise.resolve还可能重复读取getter。

修订时先限定契约：是否支持任意thenable、是否保留原返回对象身份、是否允许影响拒绝的观察状态。不能简单把所有调用改成async，因为这会改变同步返回/抛错语义。01单元的thenable与then-getter-error实验用于建立这部分直觉，迁移题再实现有限契约的包装器。

## 4. Worker检查标记前需要消息执行机会

原13讲义循环只检查cancelled.has(id)，没有让message handler运行。本章原答案后段已有setTimeout(0)让出；讲义应与其保持一致。

04单元参考summarize给出可运行分片，浏览器“正在计算时取消”探针实际用postMessage验证。await Promise.resolve不能作为task层让出的替代。
