# 第 02 章：执行上下文、闭包与 this

> 高级前端不是记住“this 指向调用者”，而是能从创建位置和调用形式稳定推导行为。

## 学习目标

- 用词法环境解释声明提升、TDZ、遮蔽和闭包。
- 区分函数创建时捕获的词法环境与调用时确定的 `this`。
- 能推导普通调用、方法调用、构造调用、显式绑定和箭头函数。
- 能设计可释放资源的闭包，而不是制造隐蔽的长期引用。
- 能定位 React 闭包快照与 Vue 解构失去响应性背后的语言原因。

## 1. 执行上下文是一次运行的容器

每次进入脚本、模块或函数，都会建立执行所需的上下文。 上下文关联词法环境、变量环境、`this` 绑定等信息。 作用域是源码的静态结构；调用栈是运行时的动态结构。 同一个函数递归三次，会有三个执行上下文，却共享同一段函数代码。 不要把“作用域链”画成调用者链；它由函数定义位置决定。

## 2. 创建阶段与执行阶段

进入作用域时，声明对应的绑定先被建立，然后代码才逐句执行。 函数声明可在声明前调用，因为绑定在执行前已初始化为函数对象。

`var` 绑定提前建立并初始化为 `undefined`。

`let`、`const`、`class` 的绑定已存在，但初始化前处于 TDZ。

TDZ 的意义是暴露“过早访问”，而不是把错误静默变成 undefined。

```js
const value = "outer";
{
  // console.log(value); // ReferenceError，不会读取 outer
  const value = "inner";
}
```

内层绑定从块开始就遮蔽外层绑定，即使还没有执行到声明行。

## 3. 闭包不是“函数套函数”的语法题

函数对象会记录创建时的外部词法环境。 只要函数仍可达，它所需要的环境也仍可达。 闭包让私有状态、工厂函数、柯里化和回调成为可能。 闭包也可能让大对象、DOM、缓存和订阅比预期活得更久。

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
```

捕获的是绑定，不是创建瞬间强制复制出的值。 但每次函数调用会创建新的绑定集合，因此不同调用的闭包可以相互独立。

## 4. 循环中的绑定

`var` 在函数作用域中只有一个共享绑定。

`let` 在 `for` 循环中会为每次迭代建立新的绑定。

因此异步回调读取循环变量时，两者表现不同。 工程上优先使用块级作用域，不要用 IIFE 修补本可直接表达的意图。 当回调需要大对象的一小部分时，只捕获必要字段，减少保留路径。

## 5. this 与词法作用域是两条轴

普通函数的 `this` 主要由调用形式确定，而不是定义位置。

`fn()` 是普通调用；严格模式下 `this` 为 undefined。

`obj.fn()` 是方法调用；引用的 base object 成为 `this`。

`fn.call(x)`、`apply`、`bind` 提供显式绑定。

`new Fn()` 创建对象并进行构造绑定；它的优先级高于普通绑定。

箭头函数没有自己的 `this`、`arguments`、`super` 和构造能力。 它从定义处读取外层 `this`，因此不能用 call/apply 改写。

```js
const user = {
  name: "Ada",
  show() { return this.name; },
}; const show = user.show;
// show(); // 严格模式下 this 为 undefined
```

把成员访问结果传给另一个函数时，base object 已经丢失。 这类错误常出现在事件监听、Promise 回调和解构方法中。

## 6. bind 的真实代价与用途

`bind` 创建一个新的函数对象，并固定 this 与可选的前置参数。

每次渲染或循环中重复 bind 会制造新身份，影响移除监听和缓存比较。

`removeEventListener` 必须收到与注册时相同的函数对象。

因此要保存绑定后的函数，或使用稳定的包装器与显式清理。 被绑定函数仍可被 `new` 调用；构造调用时绑定的 this 会被忽略。 不要尝试只靠手写 `(...args) => fn.apply(obj, args)` 完整模拟 bind 的构造语义。

## 7. arguments、剩余参数与转发

普通函数拥有自己的 `arguments`，箭头函数读取外层的 arguments。 现代代码优先用剩余参数，它是真数组且语义明确。 包装函数必须同时考虑 `this`、参数、返回值和异常。 只转发参数却漏掉返回值，会破坏调用协议。 把同步函数包装成 `async` 会强制改变返回类型，也是一种破坏。 高质量装饰器要保持同步仍同步、异常仍可观察、接收者不丢失。

## 8. 生产失败案例：无法移除的监听器

组件挂载时执行 `window.addEventListener("resize", this.onResize.bind(this))`。 卸载时又执行一次 `this.onResize.bind(this)` 传给 remove。 两次 bind 产生不同函数对象，旧监听器继续引用实例与 DOM。 用户多次进入页面后，处理器成倍执行，内存也持续增长。 因果链是：错误理解函数身份 → 清理时引用不一致 → 闭包保留实例 → 重复副作用。 修复是提前保存稳定函数，并让资源获取与释放成对出现。

## 9. 生产失败案例：陈旧闭包覆盖新结果

回调捕获了某次调用的查询条件，较慢请求最后完成。 如果提交结果前不验证请求版本，旧结果会覆盖新界面。 闭包准确保存了当时环境；错误在于业务误以为“回调总会看到最新意图”。 正确设计是版本令牌、取消信号或只接受最后一次结果。 该问题会在异步章节进一步解决。

## 10. 常见反例

```js
const service = {
  token: "secret",
  request() { return this.token; },
};
const { request } = service;
request(); // 接收者丢失
```

```js
function register(node) {
  const hugeModel = loadHugeModel();
  node.onclick = () => console.log(hugeModel.id);
  // 若 node 长期存活，hugeModel 也可能长期存活
}
```

不要为“私有”自动使用闭包；先决定状态应活多久、由谁释放。

## 11. DevTools 与验证

在 Sources 面板断点处查看 Scope 区域，区分 Local、Closure、Global。 在 Console 使用 `fn.name`、函数引用相等比较验证包装器身份。 用 Event Listeners 面板检查重复监听。 用 Memory 的 Retainers 路径确认对象是否被闭包或监听器保留。 在异步回调入口记录创建版本和当前版本，验证陈旧任务。 不要依赖 DevTools 展开对象后的“当前值”推断日志产生时的快照。

## 12. React/Vue 迁移

React 函数组件每次渲染都是一次新的函数调用。 事件处理器会捕获那次渲染的 props/state 绑定，这就是状态快照。 不要把陈旧闭包误称为 React bug；应使用函数式更新、正确依赖或明确的 ref 通道。 Vue 3 的 `setup` 同样使用闭包组织逻辑，但 ref 的 `.value` 提供了可变容器。 直接解构 reactive 对象可能得到普通值，后续读取不再经过 Proxy。 从 Vue 到 React，要从“读取可变容器”切换到“每次渲染获得新快照”。 从 React 到 Vue，也要区分闭包绑定与响应式容器，而不是盲目解构。

## 13. 速记

- 作用域看定义位置，调用栈看运行顺序。
- 闭包捕获绑定，并延长所需环境的可达时间。
- 普通函数 this 看调用形式；箭头函数 this 看定义位置。
- 包装函数要保留接收者、参数、返回值、异常和同步性。
- 订阅、定时器、绑定函数必须有稳定身份和对称清理。
