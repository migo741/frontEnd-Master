# 第 16 章练习

## 练习一：偶发回滚的自动保存

编辑器在输入后 500ms 自动保存，同时允许手动保存和切换文档。线上偶尔出现“新内容保存成功后又被旧响应覆盖”，测试靠 `sleep(1000)`，本地几乎不失败。

任务：

1. 把系统写成事件/状态时间线，列出至少三种竞态；
2. 用可注入 clock、transport 和 id generator 重构，明确 debounce、in-flight、取消、generation 和服务端版本冲突语义；
3. 写确定性测试，主动控制 A/B 请求完成顺序，不使用真实等待；
4. 对“用户取消”“网络失败”“409 冲突”“旧响应迟到”分别定义 UI 与遥测；
5. 保留错误 `cause`，日志能按一次编辑会话关联且不记录正文。

验收：随机事件序列下，“较旧 revision 永不覆盖较新 revision”“每次保存最多 settle 一次”始终成立。

## 练习二：只在部分用户出现的白屏（高难）

给定事实：新版本发布后约 0.7% 用户白屏；刷新有时恢复；错误平台只有压缩栈 `t is not a function`；问题集中在开启某 flag、装过旧 Service Worker 的 Safari 用户；后端同时灰度了新字段。

请提交一份事故处理包：

- 前 30 分钟的止损/验证顺序；
- 版本、flag、浏览器、缓存、SW、API schema 的复现矩阵；
- 如何用 release artifact + 私有 Source Map 还原堆栈；
- 最小新增遥测（不能上报敏感响应正文）；
- 根因候选的证伪实验；
- 修复、灰度、回滚与缓存/SW 兼容方案；
- 回归测试和事故复盘模板。

答案不是猜一个根因，而是给出能最快把 0.7% 缩小到确定故障链的证据计划。
