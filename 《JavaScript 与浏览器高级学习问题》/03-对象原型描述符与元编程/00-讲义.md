# 第 03 章：对象、原型、描述符与元编程

> 对象不是“键值字典”这么简单；高级代码必须同时看到身份、原型和属性描述符。

## 学习目标

- 能从 `[[Prototype]]` 链解释属性读取、遮蔽和方法共享。
- 能说明 `new`、class、`instanceof` 的机制与边界。
- 能正确处理数据属性、访问器属性、Symbol 和不可枚举属性。
- 能用 Reflect/Proxy 做可验证的元编程，并尊重 Proxy invariant。
- 能判断组合、继承、委托和复制各自适用的边界。

## 1. 对象有身份、属性和内部槽

普通对象拥有自身属性，也有一个 `[[Prototype]]` 内部链接。 属性读取先查自身，再沿原型链向上查找。 属性写入并不只是“在对象上放值”，还要考虑继承的 setter 和 descriptor。 Map、Set、Date 等内建对象还依赖内部槽。 把原生方法借给长得相似的普通对象，通常会因缺少内部槽而失败。

```js
const fakeMap = { size: 0 };
// Map.prototype.get.call(fakeMap, "x"); // TypeError
```

结构相似不代表运行时品牌相同。

## 2. 原型链是委托，不是复制

实例不会复制 prototype 上的方法。 读取 `instance.method` 时，查找过程委托给原型链。 在实例上赋同名数据属性会遮蔽原型成员，而不是修改原型。 修改共享原型会影响所有尚未被实例属性遮蔽的对象。 使用 `Object.create(proto)` 可以明确建立委托关系。 使用 `Object.getPrototypeOf` 和 `Object.setPrototypeOf` 操作原型；不要依赖 `__proto__`。 频繁动态修改原型会破坏引擎优化，也会让行为难以推理。

## 3. new 实际做了什么

构造调用大致包含四步：

1. 创建一个以 `Constructor.prototype` 为原型的新对象。
2. 以新对象作为 this 调用构造器。
3. 构造器若显式返回对象，则采用该对象。
4. 否则返回步骤一创建的对象。

class 构造器必须用 new 调用，并默认运行在严格模式。 派生 class 在访问 this 前必须先执行 `super()`。 真正完整的构造语义还涉及 `new.target`、内建 subclass 和 Reflect.construct。 所以手写 new 是理解题，不应替代生产环境的语言能力。

## 4. instanceof 不是类型认证

默认 `instanceof` 检查构造器的 prototype 是否出现在对象原型链上。 构造器可以通过 `Symbol.hasInstance` 自定义结果。 跨 realm 的数组拥有另一个 `Array.prototype`，因此 `instanceof Array` 可失败。 原型也可在对象创建后被更改，使判断结果变化。 安全边界不应只依赖 instanceof；外部输入仍需字段级运行时校验。

## 5. 属性描述符

数据属性 descriptor 含 `value`、`writable`、`enumerable`、`configurable`。 访问器 descriptor 含 `get`、`set`、`enumerable`、`configurable`。 同一个 descriptor 不能同时是数据属性和访问器属性。 普通赋值创建的属性通常可写、可枚举、可配置。

`Object.defineProperty` 省略的布尔标记默认是 false。

这一区别是大量“属性明明存在却遍历不到”的来源。

```js
const user = {};
Object.defineProperty(user, "id", { value: 1 });
console.log(Object.keys(user)); // []
```

读取 `source[key]` 会执行 getter；读取 descriptor 不会。 元编程工具若只用展开语法，会丢失 getter、setter 和访问控制。

## 6. 自有键与遍历协议

`Object.keys` 返回可枚举的自有字符串键。

`Object.getOwnPropertyNames` 包含不可枚举字符串键。

`Object.getOwnPropertySymbols` 返回 Symbol 键。

`Reflect.ownKeys` 返回全部自有字符串键和 Symbol 键。

`for...in` 还会遍历原型链上的可枚举字符串属性，常不适合对象协议复制。

选择 API 前先写清楚“自有/继承、字符串/Symbol、可枚举/全部”。

## 7. class 是语法层，不是另一套对象系统

实例方法位于 prototype，静态方法位于构造器对象。 class 字段则在每个实例上初始化。 私有字段使用品牌检查，不是普通字符串属性，Proxy 也不能伪造该内部品牌。 提取依赖私有字段的方法后，必须用正确实例作为接收者调用。 方法定义拥有 `[[HomeObject]]`，`super` 按定义所在对象解析，不按借用位置重新绑定。 这使“复制带 super 的方法”成为 trait 组合中的重要边界。

## 8. Reflect 让内部操作显式化

Reflect 方法通常与 Proxy trap 一一对应。

`Reflect.get(target, key, receiver)` 会保留访问器中的接收者语义。

`Reflect.set` 返回布尔结果，适合在 trap 中继续默认行为。

在 Proxy 中优先通过 Reflect 转发，而不是重新发明属性算法。 但“转发所有 trap”并不自动让 Proxy 对 Map、Date、私有字段透明。 这些能力依赖原目标的内部槽或品牌。

## 9. Proxy invariant

Proxy 可以拦截 get、set、defineProperty、ownKeys 等内部操作。 但 trap 不能任意撒谎。 例如目标的不可配置属性不能从 ownKeys 结果中消失。 不可配置且不可写的数据属性，get trap 不能返回与真实 value 不同的值。 目标不可扩展时，报告出的键集合必须与真实键集合一致。 违反 invariant 会抛 TypeError，而不是获得一个“更强”的虚拟对象。 透明深只读 Proxy 因此比几行 set trap 复杂得多。

## 10. 生产失败案例：配置 getter 被提前执行

工具用 `{ ...defaults, ...plugin }` 合并插件对象。 plugin 的某个 getter 会读取尚未初始化的环境并带有副作用。 展开操作读取属性值，getter 在安装阶段提前执行。 合并结果还把 getter 变成普通数据属性，后续配置不再动态计算。 根因链：把对象当字典 → 忽略 descriptor → 提前执行访问器 → 行为与时序被改变。 正确做法是先明确合并协议，必要时复制 descriptor 并检测冲突。

## 11. 常见反例

```js
// 反例：误以为冻结是递归的
const config = Object.freeze({ nested: { enabled: true } });
config.nested.enabled = false; // nested 仍可变
```

```js
// 反例：在不可信输入上直接赋值特殊键
target[inputKey] = inputValue;
```

对普通对象处理 `__proto__` 等键时可能引入原型污染风险。 字典数据可使用 `Object.create(null)`、Map 和明确白名单。

## 12. DevTools 与验证

在 Console 使用 `Object.getOwnPropertyDescriptors(value)` 一次查看完整协议。 用 `Reflect.ownKeys` 检查遗漏的 Symbol 与不可枚举键。 用 `Object.getPrototypeOf` 逐层验证委托关系。 在 getter 中断点，确认它是安装时还是读取时执行。 为 Proxy 的每个 trap 建立最小验证，特别测试 sealed/frozen target。 不要用 console 展开的视觉效果代替 descriptor 断言。

## 13. React/Vue 迁移

React 元素和状态对象应当被视为值快照，不应通过 Proxy 偷偷改变。 组件库 API 更适合显式组合，而不是运行时修改组件原型。 Vue 3 的 reactive 以 Proxy 实现，但框架必须处理身份缓存、嵌套包装和数组集合语义。

`toRaw`、`markRaw` 等逃生口说明 Proxy 并不等同于原对象。

从 Vue 到 React，要把 Proxy 追踪思维转换为显式状态更新与身份变化。 从 React 到 Vue，也要避免对带内部槽或私有品牌的对象盲目 reactive。

## 14. 速记与自检

- 原型链是读取委托，不是实例复制。
- descriptor 决定属性如何读写和枚举，值只是其中一部分。
- 元编程优先 Reflect 转发，同时尊重 invariant。
- instanceof 可被 realm、原型修改和 hasInstance 改变。
- 组合器必须明确键集合、冲突、访问器、super 与安全边界。

自检：展开语法为何会执行 getter？Proxy 为何不能透明代理所有对象？复制方法后 super 指向哪里？
