# 第 07 章：ESM 包边界与构建语义

## 本章目标

理解 ESM 从解析、链接到求值的真实过程，能解释 live binding、循环依赖、动态导入与顶层 await；能用构建产物和浏览器证据排查重复模块、加载瀑布与 tree-shaking 失效，而不是把 bundler 当成黑盒。

## 1. 模块先组成图，再开始执行

静态 `import` 不等于“运行到这一行再加载”。引擎先解析入口，递归解析依赖说明符，创建模块记录并链接导入导出，最后才按依赖关系求值。

可以把过程压缩为：

```text
resolve -> fetch/load -> parse -> link/instantiate -> evaluate
```

链接阶段会检查“导入名是否真的存在”。因此拼错 named export 常在任何业务代码执行前失败。构建器会改变文件数量，却不能改变这些 ESM 核心语义。

## 2. import 是只读的 live binding

```js
// counter.js
export let count = 0
export function increment() {
  count += 1
}

// app.js
import {count, increment} from './counter.js'
console.log(count) // 0
increment()
console.log(count) // 1
```

导入方看到的是导出绑定的当前值，不是导入时复制的快照。导入方不能给 `count` 重新赋值，但如果导出的是可变对象，仍可修改对象内部；“binding 只读”不等于“值深度不可变”。

这也是测试替换模块变量很别扭的原因。需要替换的依赖应通过函数参数、工厂或 composition root 注入，而不是依赖改写 import。

## 3. 循环依赖不是必然错误，顶层读取才危险

模块 A 导入 B，B 又导入 A，链接器可以建立这个环；问题常发生在求值时：

```js
// a.js
import {b} from './b.js'
export const a = b + 1

// b.js
import {a} from './a.js'
export const b = a + 1
```

`a` 仍处于暂时性死区时，B 就在顶层读取它，通常得到 `ReferenceError`。若读取被推迟到函数调用，环可能暂时“可用”，但初始化顺序仍脆弱。

生产修复优先重画依赖方向：把共享常量下沉到无上游依赖的叶子模块，或由唯一 bootstrap 显式组装。不要用 `setTimeout` 掩盖初始化环。

## 4. 模块身份由解析后的说明符决定

浏览器原生 ESM 以 URL 解析模块。不同 URL 即可能是不同模块实例：

```js
import './analytics.js'
import './analytics.js?tenant=a'
```

即使响应字节相同，查询串不同也会产生不同身份，顶层初始化可能执行两次。bundler alias、大小写差异、monorepo 中重复版本，也可能在产物中制造两个“单例”。

判断单例是否唯一，要检查最终解析身份和构建图，不要只看源文件名相同。

## 5. 浏览器不认识你的源码 alias

浏览器能直接解析绝对 URL、相对 URL和由 import map 映射的 bare specifier。`@/config`、`~lib` 之类通常只是编辑器或 bundler 约定。

开发服务器能运行不代表部署后原生 ESM 能运行。验证必须覆盖 production build 和真实静态服务器；直接双击 HTML 还会遇到 `file:`、MIME 和跨源限制，不能代表线上协议。

## 6. 动态 import 是异步边界，不自动等于好性能

`import('./editor.js')` 返回 Promise，并在第一次需要时加载和求值模块。bundler 常把它变成独立 chunk，但切块策略是构建行为，不是 ECMAScript 保证。

过度切分会增加请求、压缩字典损失和调度开销；切分太少又让首屏下载无关代码。边界通常放在路由、重型编辑器、低频管理能力，而不是每个小组件。

动态导入也要处理失败：部署期间旧 HTML 请求已被清理的 hash chunk、网络离线、CSP 拦截，都可能 reject。恢复策略可以是提示刷新、保留旧资源一段时间和可靠的版本发布。

## 7. 顶层 await 会把异步性向上传播

依赖模块存在 top-level await 时，所有等待它求值的上游模块都会暂停。若多个模块各自在顶层串行取配置，首屏可能在第一行 UI 代码执行前就形成瀑布。

```js
// 不推荐把远程启动条件藏在任意叶子模块
export const config = await fetch('/config').then(r => r.json())
```

更清晰的方案是入口显式并行准备，定义超时、降级和错误 UI，再调用 `startApp(dependencies)`。顶层 await 适合边界明确的启动模块，不适合到处散落。

## 8. tree-shaking 是构建器的可证明删除

tree-shaking 依赖静态 ESM 结构和副作用分析。动态属性访问、CommonJS 包装、顶层注册、未知副作用都可能让构建器保守保留代码。

```js
// 隐式副作用让模块“导入即注册”
registry.set('markdown', createMarkdownPlugin())
```

更可审计的设计是导出值或注册函数，由入口显式选择。`package.json` 的 `sideEffects` 是给工具的承诺；错误标记为无副作用会让必要 CSS 或初始化在生产被删掉。

tree-shaking 只能移除未使用且可安全删除的代码，不能修复庞大依赖、运行时算法或重复数据。

## 9. 构建不是一个动作

现代流水线可能包含解析、语法转换、宏/环境替换、依赖预构建、打包、切块、压缩、hash、source map 和资源清单。开发模式常按需转换并带 HMR，生产模式才做完整优化。

因此以下结论必须在生产产物验证：

- 某模块真的被删除；
- 某路由真的独立切块；
- source map 能还原线上栈；
- 动态资源 URL 在部署基路径下正确；
- 旧页面在滚动发布期间仍能拿到旧 chunk。

## 10. 包边界由公开入口定义

应用代码不应深引入另一个包的 `src/internal/*` 或构建目录。深引入绕过公开契约，会把目录布局、构建策略和内部单例变成隐式 API。

在纯 ESM 课程里只需坚持：公开入口少而清楚、内部路径不可达、入口没有意外副作用。ESM/CJS 双格式、声明文件与 TypeScript 模块配置请交给 TS Master 第 13–14 章，不在这里重复。

## 11. 用证据分析模块图

1. Network 看首屏请求、Initiator、优先级、缓存和失败 chunk。
2. Coverage 找已下载但未执行的大块代码；它是线索，不是删除清单。
3. 构建 manifest 或 bundle visualizer 看“谁把依赖带进来”和重复版本。
4. Sources 检查 source map、实际模块 URL和部署基路径。
5. Performance 记录解析/编译/执行，而不只比较 gzip 大小。

对比前后要固定设备、网络、缓存状态和入口路径，并保存构建产物摘要。

## 12. React 与 Vue 迁移提示

React 的 `lazy`、路由懒加载和 Vue 的异步组件最终都落到动态 import 与 chunk 加载。组件边界漂亮，不代表网络边界合理；要同时看数据请求是否与代码串行。

模块级可变状态会被所有组件实例共享，SSR 时还可能跨请求共享。React StrictMode 或 Vue HMR 暴露的重复初始化，往往是顶层副作用没有幂等或清理，而不是框架“执行错了”。

## 13. 评审清单

- 依赖图是否单向，循环中的顶层读取能否消除？
- 同一逻辑是否因 URL、alias、版本或入口不同被实例化两次？
- 首屏必需、可预取和低频代码边界是否明确？
- 顶层 await 是否有超时、并行、降级和可见错误？
- 包是否只通过公开入口消费？
- 生产构建、部署基路径、旧 chunk 保留和 source map 是否验证？
- tree-shaking 结论是否来自产物，而不是来自配置愿望？

## 本章速记

- ESM 先建图和链接，再按依赖关系求值。
- import 是 live binding；循环依赖的危险常是求值时过早读取。
- 动态 import 提供异步边界，chunk 形态由构建器决定。
- 顶层 await 会阻塞上游求值；启动工作应显式组装。
- tree-shaking 是静态可证明删除，顶层副作用会限制它。
- 开发可运行不算交付，生产产物和真实部署才是证据。
