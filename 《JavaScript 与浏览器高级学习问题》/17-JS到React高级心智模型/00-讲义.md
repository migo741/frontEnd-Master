# 第 17 章：从 JavaScript 到 React 高级心智模型

## 本章目标

学完后，你应能把 React 中的旧值、重复订阅、撕裂、卡顿、状态串号和 DOM 时序问题，分别追溯到闭包、身份、事件循环、外部系统协议与浏览器渲染；能判断 React API 是在表达什么约束，而不是靠改依赖数组试错。

> 本章是桥，不重复完整 React 课程。系统学习请进入 [React Master](../../React%20Master/课程总索引.md)。

## 1. 组件函数只执行一次？

函数组件每次 render 都重新调用。局部变量、事件处理器和 Effect setup 都属于某次调用形成的词法环境：

```jsx
function Counter() {
  const [count, setCount] = useState(0)
  const logLater = () => setTimeout(() => console.log(count), 1000)
  return <button onClick={logLater}>{count}</button>
}
```

定时器读取创建它那次 render 的 `count`。这不是 React “缓存了旧值”，是 JavaScript 闭包正确工作。setter 安排下一快照，不会改写当前词法环境。

应根据语义选择：

- 更新依赖前值：函数式 updater；
- 事件中读取最新非响应值：受控 ref 或 React 19.2 的 `useEffectEvent` 适用场景；
- Effect 真正依赖某值：把它放进依赖并让 setup/cleanup 可重建；
- 其实是派生 UI：render 时计算，不再复制 state。

## 2. state 是快照，身份是协议

React 使用 `Object.is` 比较部分状态/依赖，协调又用元素 type、position、key 判断 UI 身份。直接修改旧对象会同时破坏：

- 前后快照可区分性；
- memo/selectors 的引用判断；
- 并发 render 的隔离；
- 撤销、日志和测试推导。

结构共享不是为“函数式洁癖”，而是把变化路径编码进引用图。key 则表达业务实体跨 render 的身份；随机 key 或可重排列表的 index key 都在撒谎。

## 3. render、commit 与浏览器绘制

render 计算下一棵 UI，可能暂停、重试或放弃；commit 才修改 DOM、更新 ref 并运行对应 Effect。浏览器绘制又是宿主调度阶段。

因此：

- render 必须纯，不能订阅、写存储、发埋点或操作 DOM；
- `useLayoutEffect` 在绘制前同步执行，适合必须测量/修正的视觉工作，但会阻塞；
- `useEffect` 用于与外部系统同步，不保证“页面已经完成所有视觉工作”；
- 需要下一帧信息时理解 `requestAnimationFrame`，不要把 `Promise.resolve()` 当作绘制完成。

## 4. Effect 是独立同步过程

把 Effect 想成：给定依赖快照，启动一个外部同步；依赖变化时先撤销旧同步，再启动新同步。

```jsx
useEffect(() => {
  const controller = new AbortController()
  connect(roomId, {signal: controller.signal})
  return () => controller.abort()
}, [roomId])
```

setup 与 cleanup 必须对称。Strict Mode 在开发中额外执行相关流程，是用来暴露不纯与不完整清理，而不是“React 发疯”。

如果 Effect 只做 `setFullName(first + last)`，它不是同步外部系统，而是在制造一次落后 render 的重复状态。

## 5. 依赖数组不是调度开关

“我只想执行一次，所以写 `[]`”经常把变化值冻结在初次闭包。正确问题是：这个同步过程依赖哪些响应值？若不希望某段事件逻辑随依赖重建，应把“反应式同步”和“读取最新事件数据”分离，而不是欺骗 lint。

React 19.2 的 `useEffectEvent` 能表达某些 Effect 内非响应事件逻辑，但不能拿来藏住本应触发同步的依赖，也不能从任意位置调用。

## 6. 批处理、微任务与优先级

React 更新队列建立在 JavaScript 事件与调度之上，但不能用“微任务/宏任务”完全等同 React lane。批处理减少中间 commit；函数式 updater按队列折叠。

`startTransition`/`useDeferredValue` 让非紧急 React 更新可被更紧急交互打断，不会：

- 让同步算法本身变快；
- 把工作搬到 Worker；
- 减少网络传输；
- 修复阻塞主线程的第三方脚本。

先减少工作、虚拟化或移出 CPU 计算，再用优先级改善体验。

## 7. 外部 store 的快照契约

浏览器事件、WebSocket、BroadcastChannel 或自建 store 不属于 React。`useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` 要求：未变化时 `getSnapshot` 返回稳定值；变化通知与快照读取一致；服务端快照可用于 hydration。

每次调用都返回新对象会造成无限更新：

```js
getSnapshot: () => ({online: navigator.onLine}) // 错误：永远新引用
```

应缓存不可变快照，只在外部状态真实变化时替换。订阅函数必须返回 cleanup。

## 8. 外部消息必须有会话身份

Worker、fetch、SSE、WebSocket 响应到达时，组件可能已切换实体或卸载。仅检查“组件还 mounted”不够：旧请求可能在同一组件的新会话中迟到。

使用 request id/generation/实体 id，在提交 state 前确认消息属于当前逻辑会话；取消用于省资源，身份检查用于保证正确性，两者都要有。

## 9. DOM API 与 React 的所有权

React 管理声明式 DOM；第三方图表、Canvas、媒体、Selection 等可通过 ref 接入。边界原则：

- React 拥有容器与生命周期；外部库拥有容器内部或明确对象；
- setup 一次对应 destroy 一次；
- DOM listener 使用稳定协议与 cleanup；
- ResizeObserver 回调可能形成 resize loop，批量读写并限制更新；
- 高频 pointer/scroll 不要每次都同步驱动整棵 React 树。

## 10. Error Boundary 的边界

Error Boundary 主要处理其子树 render/生命周期中的错误，不自动捕获事件处理器、任意异步回调、服务端错误或边界自身错误。异步状态要进入显式 state machine/query 层，再由 UI 选择错误/重试表现。

全局 `unhandledrejection` 适合发现遗漏，不应成为正常业务错误处理器。

## 11. React Compiler 与纯度

React Compiler 1.0 通过静态分析自动做一类 memo 化；它依赖 Rules of React 与可分析的纯代码。违反纯度可能让优化或升级暴露隐藏 bug。高级做法是：

1. 先保持组件/Hook 纯、数据流明确；
2. 启用官方 lint 规则；
3. 用 profile 证明瓶颈；
4. 渐进启用编译器并用 E2E/性能回归验证；
5. 编译器版本精确升级，尤其在覆盖不足的旧项目。

## 12. 2026 版本意识

官方版本页在本课编写日仍以 React 19.2 为最新文档线，19.2 包含 `Activity`、`useEffectEvent`、Performance Tracks 等。企业仍有 React 18，所以学习重点是两代共通的纯度、快照、协调、Effect 与并发语义，再学习稳定增量。

安全补丁不能只看主版本。React 官方 2025 RSC 公告给过多个安全修复补丁线；使用框架/RSC 时应订阅公告并及时升级。

## 13. Vue 3 直觉翻译

| Vue 直觉 | React 需要的表述 |
|---|---|
| 响应式变量被追踪 | 一次更新安排新 render，函数获得新快照 |
| `computed` | render 中派生；昂贵且有证据才 memo |
| `watchEffect` | 先判断是否真的在同步外部系统 |
| 组件实例方法 | 每次 render 都创建相应闭包，身份需显式处理 |
| Pinia 响应式 store | 外部 store 必须提供稳定 snapshot/subscribe 契约 |
| `nextTick` | 区分 React commit、microtask 与浏览器 paint |

## 代码评审清单

- render 是否纯，是否修改旧快照？
- state 是最小事实还是重复派生？
- key 是否表达业务身份？
- Effect 是否真在同步外部系统，cleanup 是否对称？
- 外部异步结果是否有取消和会话身份？
- 优化是否有浏览器/React profile 证据？
- 订阅快照是否稳定，SSR/hydration 是否一致？

## 本章速记

- 旧值多半是闭包，不是 React 神秘缓存。
- state/props 是 render 快照，引用变化表达新版本。
- render 可丢弃，副作用只能进入受控边界。
- Effect 管一个同步过程，不是通用生命周期垃圾桶。
- React 调度不能替代算法、Worker、网络与 DOM 优化。
