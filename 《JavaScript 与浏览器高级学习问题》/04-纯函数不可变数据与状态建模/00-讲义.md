# 第 04 章：纯函数、不可变数据与状态建模

> “不修改对象”只是表面规则；真正目标是让状态变化可推导、可回放、可测试。

## 学习目标

- 区分纯函数、确定性、幂等和引用透明。
- 用结构共享完成不可变更新，并解释身份变化范围。
- 把派生数据与源数据分开，减少同步 bug。
- 用事件与状态机消除互相矛盾的布尔状态。
- 把副作用描述为命令，使核心状态转换保持纯净。

## 1. 什么是纯函数

纯函数的返回值只由显式输入决定，并且求值不会改变可观察的外部世界。 读取当前时间、随机数、全局可变变量和网络都会引入隐式输入。 修改参数、DOM、缓存或日志都会引入副作用。 纯函数可以安全重复执行、缓存、并行验证和属性测试。 纯函数不等于“没有局部变量”；函数内部局部突变只要不逃逸，仍可保持外部纯度。

```js
function sorted(values) {
  const copy = [...values];
  copy.sort((a, b) => a - b);
  return copy;
}
```

## 2. 确定性、幂等、纯度不要混用

确定性表示相同输入产生相同输出。 幂等表示重复执行一次或多次，最终外部效果与执行一次相同。 HTTP PUT 可以设计为幂等，却显然包含网络副作用。

`Math.random()` 没有写外部状态，但结果不确定，因此不是纯函数。

记录日志的加法函数结果确定，却仍有可观察副作用。 精确使用术语能让重试、缓存和测试策略更可靠。

## 3. 为什么共享可变状态危险

当多个模块持有同一对象引用，任何一方都能改变其他方将来观察到的值。 调用顺序会成为隐藏输入，测试用例也可能互相污染。 异步完成顺序再加入后，故障会变得间歇且难以复现。 不可变状态把“某时刻的数据”固定为快照。 更新通过创建新版本表达，新旧状态可同时存在并被比较。 这对撤销、时间旅行、乐观更新和并发 UI 都很重要。

## 4. 浅复制不是完整更新

```js
const next = { ...state };
next.user.profile.name = "Ada";
```

这里只复制了顶层，`profile` 仍与旧状态共享，旧状态也被改变。 正确更新应只复制从根到变化位置的路径。 未变化分支继续共享身份，这叫结构共享。

```js
const next = {
  ...state,
  user: {
    ...state.user,
    profile: { ...state.user.profile, name: "Ada" },
  },
};
```

“全部深拷贝”虽然避免共享修改，却破坏未变化分支身份并浪费时间与内存。

## 5. 身份就是增量计算信号

若 `next.branch === prev.branch`，消费者可快速知道该分支未变。 React memo、selector 缓存和许多状态库都利用这种信号。 原地修改导致内容变了但身份没变，可能漏更新。 无差别深拷贝导致内容没变但身份全变，可能过度更新。 高质量不可变更新应遵守：变化路径换身份，未变分支保身份，无变化返回原根。

## 6. 规范化与索引

深层嵌套列表会让更新路径长、同一实体重复出现。 可把实体规范化为 `byId` 与 `allIds`，关系用 ID 表达。 这样单实体更新更局部，查找通常从 O(n) 降为近似 O(1)。 规范化也引入维护索引一致性的责任。 不要为很小且只读的数据机械规范化；让访问模式决定结构。 Map 适合真正的键值索引，但序列化和框架工具支持需另行考虑。

## 7. 源状态与派生状态

能由当前状态计算出的数据通常不应重复存储。 例如购物车总价可由商品与数量计算，不必同时维护 total 字段。 重复存储会产生多个真相源，并需要额外同步路径。 昂贵派生可以缓存，但缓存是性能层，不是另一个业务真相。 设计前先问：删除这个字段后，能否无歧义重算？

## 8. 布尔组合会制造非法状态

`isLoading`、`isSuccess`、`isError` 三个布尔值可组合出八种情况。

其中多个同时为 true 往往没有业务意义。 判别联合或明确状态枚举只允许合法状态。

```js
// 概念模型
{ status: "idle" }
{ status: "loading", requestId }
{ status: "success", data }
{ status: "error", error }
```

复杂业务还要区分正交维度，例如“有未保存编辑”和“请求进行中”可以同时成立。 不要强行把所有组合塞进单个 phase；找出真正独立的状态轴。

## 9. 事件比 setter 更有业务语义

`setLoading(false)` 没有解释为什么结束，也无法证明其他字段同步更新。

`SAVE_SUCCEEDED` 能携带 requestId、保存版本和响应数据。

状态转换函数接收旧状态与事件，返回新状态。 合法性检查集中在一个地方，测试可以遍历事件序列。 事件名应描述已经发生的事实或用户意图，而不是 UI 控件细节。

## 10. reducer 与副作用命令

纯 reducer 不应直接 fetch、读时间或生成随机 ID。 这些不确定输入应由外层产生，并通过事件传入。 reducer 可以返回 `[nextState, commands]`。 command 是“需要做什么”的数据描述，由运行时解释执行。 异步结果再作为新事件送回 reducer。 这样同一事件日志可以离线重放，并得到相同状态序列。 这也是 Elm、Redux、状态机和事件溯源共享的核心思想。

## 11. 生产失败案例：保存成功覆盖新编辑

用户输入版本 A 并发起保存，然后继续输入版本 B。 A 的请求完成后，代码把 `dirty=false`，界面声称全部已保存。 实际上服务端只有 A，本地仍是 B。 根因不是 Promise，而是状态模型只有布尔 dirty，没有“哪个版本被保存”。 修复是给编辑与请求建立单调版本，成功事件只确认它携带的版本。 若当前版本更高，状态仍然 dirty。

## 12. 常见反例

```js
function reducer(state, event) {
  state.items.push(event.item);
  return state; // 内容改变，根身份没变
}
```

```js
const next = structuredClone(state); // 所有身份都变，且未表达业务意图
```

另一个反例是在 reducer 中读取 `Date.now()` 生成 ID。 事件无法确定重放，测试只能不断 mock 隐式输入。

## 13. DevTools 与验证

开发环境可使用 `Object.freeze` 或深冻结辅助发现意外修改。 用 `Object.is(prev.branch, next.branch)` 验证结构共享。 记录事件日志并重放，确认最终状态确定。 用 property-based test 生成事件序列，验证“不存在非法状态”等不变量。 React DevTools Profiler 可观察错误身份传播导致的重复渲染。 Vue DevTools 可观察状态变化，但仍要检查是否直接修改了跨模块共享原对象。

## 14. React/Vue 迁移

React 把 state 当渲染快照，不可变更新能可靠触发并缩小更新范围。 函数式 setState 本质上是把状态转换作为函数提交，避免读取旧闭包。 Vue 3 允许通过 Proxy 写入响应式对象，但业务 reducer 仍可保持纯函数。 从 Vue 到 React，要显式创建新身份，而不是把 nested mutation 原样搬过去。 从 React 到 Vue，不必为迎合响应式而放弃纯状态机；可以把 reducer 结果放回 ref。 两个框架都受益于单一真相源、派生状态与明确事件。

## 15. 速记与自检

- 纯函数把所有输入显式化，把副作用留在边界。
- 不可变更新只复制变化路径，无变化应返回原对象。
- 缓存派生值，不要复制真相源。
- 状态建模先找不变量，再决定枚举或正交维度。
- 异步命令在外部执行，结果以事件返回。

自检：深拷贝为何不是结构共享？dirty 布尔为何无法描述并发保存？如何证明 reducer 可重放？
