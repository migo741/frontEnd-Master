# 第 15 章练习

## 练习一：会泄漏的详情抽屉

构造并修复一个详情抽屉：每次打开都创建一个含 5 万项数据的 view model，向 `window` 注册事件，启动 interval，使用 `ResizeObserver`，并把 DOM 节点放进模块级 Map；关闭时只调用 `element.remove()`。

任务：

1. 用三快照法证明连续打开/关闭 20 次后存在持续保持；
2. 从 Heap Snapshot 写出至少两条完整 retaining path；
3. 设计“所有权清单”，让关闭动作对 listener、timer、observer、Map、Blob URL（若有）逐项对称清理；
4. 修复后用同一操作与设备条件证明基线趋稳；
5. 添加自动回归：循环操作后 DOM 数量、订阅数、缓存容量保持在预算内。

交付必须包含截图或导出的 profile、复现步骤和修复前后数值。只贴“把变量设为 null”的代码不算完成。

## 练习二：慢仪表盘的证据驱动优化（高难）

给一个包含 2 万行数据、第三方图表、输入筛选和实时推送的 React 仪表盘，目标是在中端移动设备条件下改善 INP。

要求：

- 先记录至少三次基线，并把一次慢交互分解为输入延迟、处理、呈现延迟；
- 用浏览器 Performance 与 React Profiler 对齐主要成本；
- 从算法、更新频率、DOM 数量、Worker、渲染属性、代码加载中选最小修复集；
- 不允许把所有组件无差别 memo；每项优化写出假设和证据；
- 同时检查 LCP、CLS、JS heap 和功能正确性，避免局部优化回归；
- 产出一页性能报告和一条可在 CI/发布流程执行的性能预算。

验收建议：目标场景 p75 INP 不高于 200ms；如果受实验环境限制未达到，必须能说明剩余最大瓶颈与下一步收益估计。
