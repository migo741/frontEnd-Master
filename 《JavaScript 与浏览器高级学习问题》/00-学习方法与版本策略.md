# 学习方法、环境与版本策略

## 1. 版本结论（截至 2026-08-11）

- JavaScript：以 [ECMAScript 2026](https://tc39.es/ecma262/2026/multipage/) 为已发布基线；提案只有进入 Stage 4 才当作语言事实。
- 浏览器 API：优先查 WHATWG/W3C 规范，再用 [Web Platform Baseline](https://web.dev/baseline) 判断是否能直接用于目标浏览器。
- Node.js：练习默认使用当前受支持的 **Node.js 24 LTS**。Node 26 在本课编写日仍是 Current，适合试验，不作为团队生产默认。状态以 [Node.js Releases](https://nodejs.org/en/about/previous-releases) 为准。
- React：现行官方文档线为 **React 19.2**，最新补丁以 [React Versions](https://react.dev/versions) 为准；遗留企业项目仍需理解 React 18 共通语义。
- React Compiler 1.0 已稳定。高级能力不再等于到处手写 `useMemo`/`useCallback`，而是遵守纯度、用 profile 找瓶颈，并理解编译器何时能安全优化。见 [官方公告](https://react.dev/blog/2025/10/07/react-compiler-1)。

版本号会变，机制变化较慢。课程正文把“长期不变量”和“当期 API”分开写；每季度只需更新根层市场与版本文档，不必推倒整套笔记。

## 2. 推荐练习环境

建议在一个单独练习仓库完成代码，不要把答案直接写回这份讲义：

```text
js-browser-lab/
├── package.json
├── src/chapter-xx/
├── test/chapter-xx/
└── evidence/chapter-xx/
```

最低工具：

- Node.js 24 LTS；
- 一个 Chromium 浏览器加 Firefox 或 Safari，用于交叉验证；
- Chrome/Edge DevTools：Sources、Network、Performance、Memory、Application、Security；
- `node:test` 或 Vitest 做单元测试；
- Playwright 做真实浏览器交互与多标签页测试；
- React DevTools 用于第 17–18 章。

建议脚本契约：

```json
{
  "type": "module",
  "scripts": {
    "test": "node --test",
    "test:watch": "node --test --watch",
    "test:e2e": "playwright test"
  }
}
```

浏览器实验若需要打包器，可用当前稳定 Vite；不要依赖停止维护的 Create React App。

## 3. 每章固定工作流

### 讲义：先预测再验证

打开 `00-讲义.md` 后，先回答：

1. 本章解决什么生产事故？
2. 我现在的直觉是什么？
3. 哪个日志、测试或 DevTools 面板能证明结论？

遇到输出题先写时间线或规范步骤，禁止先粘进控制台。运行结果只能告诉你“是什么”，推导才能迁移到新问题。

### 练习：少而精

- 练习一：60–120 分钟，必须独立完成。
- 练习二：高难典例，允许卡 60–90 分钟后看提示或答案。
- 卡住时必须留下：最小复现、预期、实际、三个已验证假设。
- 算法题必须写复杂度；异步题必须写取消/失败语义；浏览器题必须保存运行证据。

### 答案：四步使用

1. 先只看答案的“因果链”，回到自己的实现再修一次；
2. 再看参考实现，标注每个分支守住的边界；
3. 关闭答案，从空文件复写核心；
4. 改一个约束做二刷，例如把“失败即停止”改为“收集所有错误”。

照抄能有收获的前提是：每抄一段，都能说出它阻止了哪种失败。

## 4. 证据化复盘模板

每章至少保存一个 `retrospective.md`：

```md
## 现象与影响
## 我的第一假设
## 时间线/对象图/模块图
## 证据如何支持或推翻假设
## 根因与最小修复
## 没采用的方案及约束
## 回归测试或监控
## 如果发生在 React 中会呈现为什么症状
```

性能题额外保存：设备/网络条件、三次以上基线、中位数或 p75、修改后数据、是否有回归。微基准若没有预热、随机化和真实工作负载，只能当线索。

## 5. Vue 3 经验如何迁移

| Vue 3 熟悉点 | 本课程需要补上的底层视角 | React 中的结果 |
|---|---|---|
| Proxy 响应式 | Proxy invariant、依赖集合、调度队列 | 理解外部 store 与快照一致性 |
| `watch`/`watchEffect` | 闭包、取消、事件循环、外部系统同步 | 不滥用 Effect，不制造竞态 |
| template 事件 | DOM capture/target/bubble、默认行为、IME | 写可靠表单与可访问交互 |
| 响应式对象原地修改 | 值身份、结构共享、不可变快照 | 正确更新 state、memo 与并发渲染 |
| `nextTick` | microtask checkpoint 与渲染机会 | 不把 Promise 等同于“页面已绘制” |
| Vite 使用经验 | ESM live binding、模块图、副作用 | 能解释拆包和 tree shaking 失败 |

关键切换：框架不会取消 JavaScript 和浏览器规则。React 的很多“玄学 bug”，本质是旧闭包、身份错误、非对称清理、乱序响应或主线程被占满。

## 6. 题目取舍原则

本课程刻意不做：

- 大量只考语法陷阱、与生产无关的输出题；
- 完整手写 Promise/Ajax/深拷贝却不讨论规范边界；
- 没有测量目标的“性能优化大全”；
- 把某个状态库、构建器或面试口诀当作永久答案；
- 与现有 React Master、TS Master 重复的同题练习。

会保留少量经典手写题，但每题必须揭示一个无法靠背 API 替代的心智模型。

## 7. 三套课程的推荐顺序

不必等本课程全学完才碰 React，建议交错：

1. 本课程 01–05；
2. [React Master 01–05](../React%20Master/课程总索引.md)；
3. 本课程 06–15；
4. [TS Master 中与当前项目相关的章节](../TS%20Master/课程总索引.md)；
5. 本课程 16–18，与 React Master 10–18 并行。

如果 TypeScript 已是明显短板，先补 TS Master 01–10；如果 React 的 state/Effect 经常靠试错，先学本课程 02、05、09、17。

## 8. 每季度更新清单

1. 检查 [TC39 finished proposals](https://github.com/tc39/proposals/blob/main/finished-proposals.md)；
2. 检查 [React Blog](https://react.dev/blog) 与安全公告；
3. 检查 [Node.js Releases](https://nodejs.org/en/about/previous-releases)；
4. 检查 [Baseline](https://web.dev/baseline) 和目标浏览器兼容矩阵；
5. 抽样 10–20 个目标城市、目标职级岗位，记录能力词频；
6. 只更新受影响章节的“版本注”，不为了热点重排全部路线。

## 9. 求助时的最小信息

提供以下内容，才能训练高级排错能力：

- 最小复现和运行环境；
- 预期/实际；
- 完整错误栈或 Performance/Network/Memory 证据；
- 已尝试的方案以及为何失败；
- 你认为问题属于语言、浏览器、框架还是业务边界。

能把问题从“页面不对”缩小成“某个 task 后的 microtask 读取了旧闭包，并在下一帧前覆盖新结果”，就已经跨过高级工程师最重要的一道门槛。
