# 第 09 章：DOM、事件、输入与可访问交互

## 本章目标

能沿事件路径解释 capture、target、bubble、默认动作与 Shadow DOM 重定向；能设计支持动态节点、键盘、输入法和可靠清理的交互，并用 DOM、Event Listeners 与 Accessibility 面板验证，而不是只让鼠标点击“看起来能用”。

## 1. DOM 是浏览器维护的对象图

HTML 被解析为 Node 树。Element、Text、DocumentFragment 都是 Node，但只有 Element 有 `matches`、`closest` 与属性集合。

`querySelectorAll` 返回静态 NodeList；`children`、`getElementsByClassName` 等可能返回 live collection。遍历 live collection 时修改 DOM 会改变集合，容易漏项；需要稳定快照时先 `Array.from(collection)`。

频繁查询并不总是瓶颈，但“缓存一个后来已被移除的节点”也可能造成错误或内存保留。缓存要有明确生命周期。

## 2. 事件分派沿一条路径进行

浏览器先确定 event path，再经历：

```text
window -> document -> ... -> target       capture
target                                   target
target -> ... -> document -> window       bubble
```

`event.target` 是原始/重定向后的目标，`event.currentTarget` 是当前正在调用 listener 的节点。异步回调里不要依赖 currentTarget 仍有值，先保存需要的引用。

不是所有事件都冒泡，例如 `focus` 与 `blur`；委托时常用会冒泡的 `focusin`、`focusout`。

## 3. 传播与默认动作是两条轴

`stopPropagation()` 阻止事件继续沿路径传播，不会自动阻止链接跳转或表单提交。`preventDefault()` 请求取消可取消的默认动作，不会自动阻止其他 listener。

`stopImmediatePropagation()` 还阻止同一节点后续 listener，通常会制造难排的跨模块耦合。比“到处 stop”更好的方法是让交互目标明确，用 `data-action` 或独立 button 表达命令。

调用 `preventDefault` 前检查需求与 `event.cancelable`。被动 listener 中不能取消滚动默认动作。

## 4. 事件委托依赖最近的语义目标

动态列表无需给每行反复绑定 listener：

```js
list.addEventListener('click', event => {
  const action = event.target.closest('[data-action]')
  if (!action || !list.contains(action)) return
  dispatch(action.dataset.action, action.closest('[data-id]')?.dataset.id)
})
```

真实 target 可能是按钮里的 SVG/path，不能只比较 `target.tagName`。还要用 containment 检查，避免 `closest` 找到委托根之外的祖先。

委托减少 listener 数量，但不能把所有行为塞进一个无法测试的 switch；解析事件与执行领域命令应分开。

## 5. Shadow DOM 会重定向事件

跨 Shadow Boundary 时，外部观察到的 `event.target` 可能被 retarget 为宿主元素。需要理解真实路径时使用 `event.composedPath()`。

自定义事件若要跨出 shadow root，通常需要 `bubbles: true, composed: true`；这应是组件公共契约，而不是默认全部开启。敏感内部细节不应借事件 payload 泄漏。

## 6. listener 也有资源生命周期

`addEventListener` 的关键选项：

- `capture`：在哪个阶段监听；
- `once`：首次调用后自动移除；
- `passive`：承诺不取消默认动作，滚动输入常见；
- `signal`：AbortSignal 触发时自动移除。

`removeEventListener` 需要匹配 type、函数引用和 capture。匿名函数随手绑定很难对称清理；一个组件/控制器可用一个 AbortController 统一释放。

## 7. Pointer Event 统一鼠标、触控与笔

优先从 Pointer Events 建模，不要分别维护 mouse/touch 两套状态。拖拽时 `setPointerCapture(pointerId)` 可让指针离开元素后仍把后续事件送来，结束或取消时释放。

必须处理 `pointercancel`，并避免只靠拖拽完成关键操作。触屏没有 hover，键盘也没有 pointer；排序等能力需要按钮或键盘等价路径。

## 8. 文本输入不是 keydown 的副产品

中文、日文等 IME 输入会经历 `compositionstart/update/end`。在 composition 期间对每次 keydown 提交搜索，会发出半成品查询。

以值变化为目标时监听 `input`；想在变更前理解编辑意图可研究 `beforeinput`，但需按目标浏览器验证。`change` 的触发时机因控件而异。

`KeyboardEvent.key` 表示用户意图字符，受布局影响；`code` 表示物理键位。快捷键通常还要考虑平台修饰键、重复触发和可编辑区域，不能拦截浏览器/辅助技术的关键组合。

## 9. 原生语义先于 ARIA

能用 `button` 就不要用 `div role="button"`。原生 button 自动获得焦点、Enter/Space 激活、disabled 和表单语义；仿造这些细节成本很高。

表单字段需要可感知的 label；错误信息与字段关联，并在合适区域提示。placeholder 不是 label。DOM 顺序应与视觉和键盘顺序一致，避免用正 tabindex 人工编排。

`:focus-visible` 允许对键盘焦点显示清晰指示，而不必粗暴移除 outline。

## 10. 对话框与焦点是一个状态机

模态框打开时要：

1. 记录触发元素；
2. 把焦点放入对话框；
3. 让背景不可交互；
4. 支持 Escape、取消与明确提交；
5. 关闭后把焦点还给仍存在的合理位置。

原生 `dialog.showModal()` 提供模态和背景 inert 语义，应优先使用并按支持基线提供降级。嵌套 modal、触发元素被删除和异步关闭都要显式决定。

## 11. DOM 写入也有安全边界

显示普通文本使用 `textContent`；创建结构用 `createElement`。`innerHTML`、URL、富文本和第三方 widget 涉及信任边界，不能因为“数据来自自己的 API”就跳过净化。

本章只建立 DOM 层习惯；XSS、CSP、Trusted Types 等在第 14 章系统学习。

## 12. DevTools 与测试证据

- Elements 检查最终 DOM、属性、焦点和 event badge；
- Event Listeners 检查重复 listener 与 passive/capture；
- Accessibility tree 看 name、role、state，而不只看 CSS；
- Sources 设 Event Listener Breakpoint，沿调用栈找到真正注册者；
- Performance 记录输入到处理完成，观察长 handler 和布局；
- 测试优先用 role/name 查询，并用真实键盘序列，而非直接调用 handler。

自动 a11y 检查能抓一部分规则，不能替代键盘、焦点和屏幕阅读器抽查。

## 13. React 与 Vue 迁移提示

React 的事件封装和 Vue 的 `@click`/修饰符最终仍服从浏览器传播与默认动作。不要把 `stop` 修饰符或 JSX handler 当作架构边界。

React portal 的视觉位置与事件/组件树关系、Vue Teleport 的 DOM 位置都可能让“看起来是父子”的直觉失效。调试时同时画组件树、DOM 树与 event path。

挂到 `window/document`、第三方实例或原生 observer 的 listener 必须在 Effect/onUnmounted 对称清理；优先用 AbortSignal 集中生命周期。

## 14. 评审清单

- 是否使用原生语义元素，键盘无需额外模拟即可工作？
- target/currentTarget、传播和默认动作是否分清？
- 委托是否用 closest + contains，并处理嵌套图标？
- IME、粘贴、自动填充和移动端输入是否覆盖？
- listener、pointer capture、observer 是否可靠释放？
- modal 的进入、取消、关闭和焦点恢复是否可测试？
- Accessibility tree 中的 name/role/state 是否正确？

## 本章速记

- 事件路径有 capture/target/bubble，默认动作是另一件事。
- 委托查最近语义目标，不假设 target 就是 button。
- Pointer Event 统一指针，但关键能力仍需键盘等价路径。
- 输入值看 input/IME，不用 keydown 猜文字。
- 原生 HTML 语义通常比补 ARIA 更可靠。
- listener 和焦点都需要明确生命周期。
