# 第 01 章：值、类型、相等与数据边界

> 本章不是背 `typeof` 表格，而是建立一套能解释线上数据问题的值模型。

## 学习目标

- 能区分“变量、值、引用、对象身份”四个概念。
- 能说明 `===`、`Object.is`、SameValueZero 的差异及使用场景。
- 能沿着 `ToPrimitive → ToNumber/ToString` 推导隐式转换。
- 能识别 Number、BigInt、Unicode 和 JSON 边界上的数据损失。
- 能为接口、缓存、表单和状态管理明确制定数据契约。

## 1. 变量不是盒子里的对象

变量保存的是一个值。 原始值不可变，复制原始值就是复制值本身。 对象值带有身份；把对象赋给另一个变量，复制的是指向同一身份的引用。

```js
const a = { count: 1 };
const b = a;
b.count += 1;
console.log(a.count); // 2
```

“按值传递”与“对象可共享”并不矛盾：传递的是引用这个值的副本。 函数不能把调用者变量重新指向别处，却能通过共享引用修改对象。 这也是 React/Vue 中状态污染、浅比较失效的语言根源。

## 2. JavaScript 的值域

原始类型包括 `undefined`、`null`、boolean、number、bigint、string、symbol。 除此之外都是对象；函数是可调用对象，不是独立的原始类型。

`typeof null === "object"` 是历史兼容结果，不能作为 null 检查。

数组、Date、Map 等都返回 `"object"`，应使用品牌检查或明确契约。 跨 iframe 时，`value instanceof Array` 可能失败，`Array.isArray(value)` 更可靠。 不要把 TypeScript 类型当运行时校验；网络输入到达浏览器时仍是未知数据。

## 3. 三种必须掌握的相等语义

`===` 通常是默认选择，但它认为 `NaN !== NaN`，并认为 `0 === -0`。

`Object.is` 使用 SameValue：`NaN` 等于自身，`0` 与 `-0` 不同。

Map、Set、`Array.prototype.includes` 使用 SameValueZero：`NaN` 相等，正负零相等。

```js
Object.is(NaN, NaN); // true
Object.is(0, -0); // false
[NaN].includes(NaN); // true
[NaN].indexOf(NaN); // -1，indexOf 使用严格相等
```

React 的部分状态比较以 `Object.is` 为基础。 因此把状态从 `0` 改成 `-0` 可能被视为变化，而重复设置 `NaN` 可能被视为未变。 相等算法不是冷知识，它决定更新、缓存命中和去重行为。

## 4. 隐式转换要按规范顺序推导

对象参与加法或比较时，先执行 ToPrimitive。 ToPrimitive 会根据 hint 尝试 `Symbol.toPrimitive`、`valueOf`、`toString`。

`+` 同时承担数值加法和字符串连接；任一原始操作数为字符串时会连接。

关系比较和一元运算符又有不同的转换路径。

```js
[] + {};      // "[object Object]"
{} + [];      // 在表达式上下文中结果不同于把 {} 当代码块
Number("");  // 0
Boolean("0"); // true
```

不要靠记答案掌握“怪题”；先写出两侧的原始值，再判断后续转换。 生产代码应在边界显式解析，而不是让运算符替你猜类型。

## 5. Number、BigInt 与金额

Number 使用 IEEE 754 双精度浮点数。 整数只有在 `Number.MIN_SAFE_INTEGER` 到 `Number.MAX_SAFE_INTEGER` 之间可安全表示。

`0.1 + 0.2 !== 0.3` 是二进制浮点表示的结果，不应靠简单四舍五入掩盖业务规则。

金额常用最小货币单位整数、十进制定点库，或服务端约定的字符串传输。 BigInt 可精确表示任意大整数，但不能与 Number 混算，也不能被原生 JSON 直接编码。 接口中的 64 位 ID 应优先保留为字符串，不应先进入 Number 再补救。

## 6. 字符串长度不等于用户看到的字符数

JavaScript 字符串是 UTF-16 code unit 序列。

`str.length` 统计 code unit，不一定是 Unicode code point，更不一定是 grapheme cluster。

扩展运算符可按 code point 拆分，但肤色修饰、组合音标和家庭 emoji 仍可能被拆开。 面向用户的字符限制可使用 `Intl.Segmenter` 的 grapheme 粒度。 切割用户名、光标定位和输入长度统计时必须先确定需要哪一种“长度”。

## 7. 复制与序列化是两件事

展开语法和 `Object.assign` 只复制一层可枚举自有属性。 它们不会保留原型、完整 descriptor，也不会递归复制嵌套对象。

`structuredClone` 支持循环结构、Map、Set、Date 和 transferable。

它不能复制函数、DOM 节点等对象，也不等同于业务序列化协议。

`JSON.stringify` 会丢弃对象属性中的 `undefined`、函数和 Symbol。

数组中的这些值会变为 `null`；`NaN` 与 Infinity 也会变为 `null`。 Date 默认通过 `toJSON` 变为字符串；BigInt 默认直接抛错。 所以“能 stringify”不代表“能无损往返”。

## 8. 生产失败案例：订单号静默变化

服务端返回订单号 `9223372036854775807`。 前端模型把它声明为 number，解析后已经变成另一个整数。 页面看起来正常，复制订单号、缓存索引和撤销请求却指向错误订单。 根因链是：边界契约错误 → JSON 解析进入 Number → 超过安全整数 → 精度不可逆丢失。 修复必须从 API 契约开始，把 ID 当不参与算术的字符串，而不是在显示层格式化。

## 9. 常见反例

```js
// 反例：用 truthy 判断“参数是否提供”
const pageSize = input.pageSize || 20; // 合法的 0 被覆盖 // 更明确：只把 null/undefined 当缺失
const pageSize2 = input.pageSize ?? 20;
```

```js
// 反例：JSON 深拷贝
const copy = JSON.parse(JSON.stringify(source));
```

这会把数据协议的损失规则偷偷当成复制语义。 另一个反例是用 `JSON.stringify(a) === JSON.stringify(b)` 判断深相等。 属性顺序、不可 JSON 值、循环结构和复杂对象都会让结论不可靠。

## 10. DevTools 与验证方法

在 Console 中同时打印值与类型，不要只看字符串化结果。 使用 `Object.is(value, -0)` 判断负零，使用 `Number.isNaN` 避免全局 `isNaN` 的转换。 用 `Number.isSafeInteger` 审计来自接口的整数。 在 Network 面板查看响应原文，区分“服务端已经错误”还是“解析后错误”。 对 Unicode 使用 `Array.from(text)` 和 `Intl.Segmenter` 对照实验。 为序列化协议做 encode/decode 往返测试，而不是只快照编码文本。

## 11. 迁移到 React 与 Vue 的意义

React 依赖身份和 `Object.is` 判断理解状态是否变化。 原地修改对象再传回同一引用，可能让更新不可见或 memo 缓存失真。 Vue 3 会通过 Proxy 观察属性访问，但外部原始对象、解构和序列化仍可能打断语义。 从 Vue 迁移 React 时，不要把“深层改了框架会追踪”当默认前提。 从 React 迁移 Vue 时，也不要假设响应式 Proxy 能替代 API 边界校验。 两个框架都无法恢复已经丢失的 64 位整数或 JSON 特殊值。

## 12. 速记

- 对象赋值复制引用值，不复制对象。
- UI 默认相等比较优先想 `Object.is` 与身份。
- `??` 处理缺失，`||` 处理 falsy，两者语义不同。
- 金额先定单位，ID 当字符串，未知输入先校验。
- 用户看到的字符数用 grapheme，不用 `length` 猜。
- 复制选择复制语义，传输选择协议语义。
