# 第 07 章：`keyof/typeof`、索引访问与映射类型

## 本章目标

从现有值/类型派生新类型，消除重复真相；掌握 key remapping、修饰符和常用 utility 的浅层语义，并避免把类型运算误当运行时转换。

## 1. `keyof`

```ts
type User = {id: string; age: number}
type UserKey = keyof User // 'id' | 'age'
```

若有 string 索引签名，`keyof` 可能是 `string | number`，因为 JS 对象数字键会字符串化。只支持字符串字段的 API 用 `Extract<keyof T, string>`。

`keyof` 联合类型容易反直觉：它给出对联合所有成员都安全可访问的键，而不是简单“所有成员键”。需要成员键并集时可用分布式 helper，但先问运行时是否先缩小成员。

## 2. `typeof` 类型查询

```ts
const statuses = ['draft', 'published'] as const
type Status = typeof statuses[number]
```

让运行时 allowlist 成为单一源。类型位置的 `typeof` 只能查询标识符/属性等受限表达式；它不同于运行时 `typeof`。

函数类型：`typeof fn`；返回类型：`ReturnType<typeof fn>`。不要手写重复 API 结果。

## 3. 索引访问类型

```ts
type Id = User['id']
type Value = User[keyof User] // string | number
```

可用 union key 批量取值。数组元素：`T[number]`；tuple 特定位置：`T[0]`。索引必须是类型，不是 const 值本身；用 `typeof key`。

## 4. 映射类型

```ts
type Flags<T> = {[K in keyof T]: boolean}
type Mutable<T> = {-readonly [K in keyof T]: T[K]}
type RequiredFields<T> = {[K in keyof T]-?: T[K]}
```

映射默认同态时保留原属性 optional/readonly；用 `+/-` 修改。它们只变类型，不复制/冻结对象。

## 5. Key remapping

```ts
type Getters<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K]
}
```

`as never` 过滤 key；模板字面量改名。公共 API 需考虑 acronym、symbol/number 和运行时函数是否真的生成对应方法。

## 6. Utility Types

- `Partial/Required/Readonly`：浅层修饰；
- `Pick/Omit`：key 投影（Omit 对宽 key 有权衡）；
- `Record<K,V>`：完整键映射；
- `Exclude/Extract/NonNullable`：union 过滤；
- `Parameters/ReturnType/ConstructorParameters/InstanceType`：从函数/构造器提取；
- `Awaited`：递归展开 Promise-like；
- `NoInfer`：阻止推断候选。

理解定义比背诵更重要；领域 DTO 仍应命名。

## 7. 从值派生还是从类型派生

运行时需要枚举/验证的集合，应值为源：

```ts
const roleList = ['member', 'admin'] as const
type Role = typeof roleList[number]
```

若只有静态结构，类型为源；但不能运行时遍历 interface。Schema 可同时生成 runtime parser 和 static type，第 10 章。

## 8. Typed Object.keys 的不变量

标准 `Object.keys` 返回 string[]，因为对象运行时可能有类型未声明的额外键。通用 `<T>(o:T)=>(keyof T)[]` 不总健全。只对封闭、由自己构造的 registries 做局部 helper/Schema；不可信对象先解析。

## 9. 映射联合的相关性

常见“映射后索引”生成判别联合：

```ts
type FieldDescriptor<T> = {
  [K in keyof T]: {key: K; value: T[K]}
}[keyof T]
```

这保留每个 key/value 相关性。只写 `{key:keyof T; value:T[keyof T]}` 会允许 key='age' 配 string。

## 10. 错误可读性

命名中间类型、限制 keys、避免十层内联 mapped。IDE hover 能否告诉用户缺哪个字段？必要时让 API 多一个 helper 函数换更好上下文推断。

## 本章速记

类型运算的价值是让一个源产生多个一致视图；映射类型变形属性集合，但不执行运行时投影。标准 Object.keys 的保守性来自结构类型的开放世界。
