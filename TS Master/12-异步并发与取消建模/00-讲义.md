# 第 12 章：异步、并发、取消与流的类型建模

## 本章目标

正确表达 Promise 结果、预期错误、并发聚合、AbortSignal 和 AsyncIterable；设计不会吞错、不泄漏、不乱序的异步 API。

## 1. Promise 只编码成功值

`Promise<T>` 没有 rejected error 类型参数；catch 是 unknown（严格模式）。若调用者必须穷尽预期失败，用 `Promise<Result<T,E>>`；不可恢复异常仍 reject。不要声称 `Promise<T, E>`。

```ts
try { await task() } catch (error: unknown) {
  if (error instanceof Error) /* ... */
}
```

跨 realm/第三方可能 throw string/object；统一 `toError` 保留 cause。

## 2. async 返回

async 函数总返回 Promise，return Promise 会被 adopt/flatten。`Awaited<T>` 模型化 PromiseLike 递归展开。不要手写 `T extends Promise<infer U>` 忽略嵌套/thenable/null。

## 3. 并发组合

- `Promise.all`：全部成功，tuple 输入保留各位置类型；一项 reject 立即让 aggregate reject，但其他任务仍运行。
- `allSettled`：每项判别 fulfilled/rejected，适合独立批任务。
- `race`：首个 settle；其余不自动取消。
- `any`：首个 fulfill；全部失败 AggregateError。

类型正确不等于资源取消。需要传同一/各自 AbortSignal 并在失败策略中 abort。

## 4. 限流与背压

直接 `Promise.all(100000.map(fetch))` 会耗连接/内存。任务池控制 concurrency，定义：

- 保序还是完成序；
- fail-fast 还是 collect errors；
- 取消 queued/running；
- retry/backoff；
- fairness；
- 进度。

这些要进入 API types/options，而不是隐藏默认。

## 5. AbortSignal 协议

接受 signal，不只 boolean cancelled：

```ts
async function load(id: string, signal?: AbortSignal) {}
```

开始前 `signal.throwIfAborted()`（按 runtime 支持），监听 abort 时清理，finally remove listener。组合用户取消/超时/父任务可用 `AbortSignal.any/timeout` 或 polyfill。取消是协作式：下层忽略 signal 就不会停。

区分 aborted 与失败，保留 reason；不要把取消 toast 成系统错误。

## 6. 回调与 Promise 双接口

不要同时 callback+Promise 再导致 double completion。适配 legacy 时用 once guard，处理同步 throw、回调多次和 error-first 约定。新 API 选 Promise/AsyncIterable。

## 7. AsyncIterable

```ts
async function* events(signal: AbortSignal): AsyncGenerator<Event, void, void> {}
for await (const event of events(signal)) { /* backpressure: consumer 拉取 */ }
```

AsyncIterator 泛型分别是 yield、return、next 输入。generator `finally` 清资源；消费者 break 会调用 return（实现需正确）。Push WebSocket 转 AsyncIterable 需要 bounded queue/backpressure/drop 策略，否则内存无限。

## 8. Stream 类型与协议

ReadableStream chunk 可能是 Uint8Array，不是业务消息。TextDecoder 流式处理 UTF-8 半字符，parser 处理半行/多消息。类型只表达 chunk 形状，sequence/dedupe/Schema 才保证协议。

## 9. 并发身份

异步结果必须带 request/operation/resource/version identity，防旧结果覆盖新状态。泛型无法证明时间顺序；runtime requestId/sequence/Abort 共同保证。

## 10. 资源生命周期

WebSocket、file handle、timer、listener、worker 需要显式 dispose。新 JS 显式资源管理/`using` 的目标 runtime 和 TS 支持需确认；公共库仍可提供 `Disposable`/`AsyncDisposable`。错误聚合要避免 cleanup 覆盖主错误。

## 11. 评审清单

- 预期错误 Result 还是 rejection？
- 并发组合是否取消剩余、是否限流？
- signal 是否贯穿下层并清 listener/timer？
- 保序/fail-fast/retry/backpressure 是什么？
- AsyncIterable break/error 是否 dispose？
- chunk 与 message 是否分层解析？
- 旧结果身份如何拒绝？

## 本章速记

Promise 类型只告诉成功值，取消/顺序/背压/资源释放都是运行时协议。高级异步 API 把策略显式化，并用 Result、AbortSignal、AsyncIterable 和身份字段组合。
