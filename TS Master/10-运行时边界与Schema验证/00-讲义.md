# 第 10 章：运行时边界、`unknown` 与 Schema 验证

## 本章目标

建立一条不可绕过的信任管线：不可信 bytes/values → 解析 → Schema 验证/转换 → Domain。掌握单一源、错误路径、版本兼容、性能和安全限制。

## 1. 不可信输入清单

- `fetch().json()`、GraphQL/WS/SSE 消息；
- localStorage/IndexedDB/cookie；
- URL/search params/FormData；
- process.env/import.meta.env；
- postMessage/Worker；
- 第三方 SDK/callback；
- 文件/CSV/JSON；
- Server Action/公开 API 参数。

入口类型从 unknown 开始。DOM 自己产生的受控值仍可能需要业务校验。

## 2. Parse, don't validate then forget

不推荐：

```ts
if (isValid(raw)) doSomething(raw as Domain)
```

推荐 parser 返回新可信值或 Result：

```ts
const parsed = UserSchema.safeParse(raw)
if (!parsed.success) return mapIssues(parsed.error)
const user = parsed.data
```

解析可以 strip 多余字段、标准化、Brand、Date/BigInt 转换。输入与输出类型可能不同：

```ts
type UserWire = Input<typeof UserSchema>
type User = Output<typeof UserSchema>
```

## 3. Schema 单一源的方向

三类选择：

- Schema-first：从 runtime schema 推断 TS，适合应用边界；
- Spec-first：OpenAPI/JSON Schema/Protobuf 生成 client/schema/types，适合跨语言；
- Type-first + generator：开发体验好，但 TS 高级类型/运行时语义不一定可完整生成。

不要手写 interface + 独立 Schema + 独立文档三个真相。必须有 contract test/diff gate。

库可选 Zod、Valibot、ArkType、effect schema 等；课程关注协议，不锁定品牌。比较 bundle、性能、错误、transform、标准 Schema/生态、Tree-shaking。

## 4. Strict/strip/passthrough

- strict/reject unknown keys：配置/命令输入可尽早发现拼写/攻击面；
- strip：输出 DTO/安全投影；
- passthrough：向前兼容协议，但敏感边界慎用。

选择按协议。服务端响应新增字段，客户端通常可忽略；用户配置错字段可能应报错；跨信任边界转发 raw payload 容易夹带数据。

## 5. 默认与可选

默认是在 parse 时产生输出值，不是类型注解。区分缺失/null/undefined；JSON 无 undefined。默认 Date.now/random 会让相同输入产生不同输出，测试/缓存需注入 clock。

Coercion（`'1' -> 1`）便利但可能把空字符串/布尔等误转，表单与 URL 要明确规则并返回原输入错误。

## 6. 错误协议

Schema issue 至少有 path、code、expected/received（注意脱敏）、message key。UI 映射本地化文案；日志不上传密码/token/完整 payload。限制最大 issues，防巨型恶意输入制造内存/日志 DoS。

## 7. 版本化

```ts
type Envelope = {schemaVersion: number; type: string; payload: unknown}
```

先解析 envelope，再按 version/type 分派。升级策略：

- backward compatible additive；
- migration v1→v2→domain；
- unsupported future version 安全拒绝/降级；
- 旧缓存带版本；
- 遥测版本分布，达到阈值再删除迁移器。

不要把所有历史版本 union 直接传播到业务层；边界迁移到当前 Domain。

## 8. HTTP Client 边界

可靠 client：构造 URL/编码请求、AbortSignal、status/content-type/204、响应大小/超时、Schema parse、领域错误、trace。泛型 T 必须来自 decoder：

```ts
request({decoder: UserSchema}) // Promise<User>
```

禁止 `request<User>()` 无 decoder 的自选返回类型。

## 9. 环境变量

`process.env.PORT` 是 string|undefined；启动时一次 parse 整体 config，失败快速退出。客户端 bundler 只暴露 allowlist public env；Schema 不应把服务端 secret 对象整个传浏览器。

## 10. 性能与安全

- payload 大小/深度/数组长度限制；
- parser benchmark 真实形状；
- 不重复 parse 同一可信对象；
- streaming 数据按 event 验证，不累积无限字符串；
- regex 避免灾难回溯；
- transform 不执行不可信代码/网络副作用；
- Schema 错误不泄露内部字段。

## 11. 评审清单

- unknown 从哪里进入，何处变 Domain？
- 谁是 schema/type/spec 单一源？
- unknown keys、默认、coercion、transform 语义是什么？
- 版本如何迁移/删除？
- 错误 path/本地化/隐私如何？
- payload limits 与 parser 性能？
- decoder 是否真正控制返回 T？

## 本章速记

TypeScript 的安全从 `unknown` 边界开始。Schema 不是附加校验，而是把不可信运行时值构造成当前版本 Domain 的唯一入口。
