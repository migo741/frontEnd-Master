# 学习方法、环境与版本策略

## 1. 版本基线

建议在独立实验仓库安装当前稳定补丁并提交 lockfile：

```bash
mkdir ts-master-lab && cd ts-master-lab
npm init -y
npm install -D typescript@^6.0.3 tsx vitest @types/node
npx tsc --init
```

确认：

```bash
npx tsc --version
```

企业兼容分支可安装 5.9 最新补丁，执行双编译：

```bash
npx -p typescript@5.9 tsc -p tsconfig.json --noEmit
npx -p typescript@6.0 tsc -p tsconfig.json --noEmit
```

TS 7 预览只在 CI 非阻塞 job/独立分支实验。它的原生编译器速度很有吸引力，但 Language Service plugin、Compiler API、构建插件和边缘行为必须逐项盘点。

## 2. 起步 tsconfig 不是万能模板

浏览器 + bundler 实验可参考：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "Preserve",
    "moduleResolution": "Bundler",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "useUnknownInCatchVariables": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "noUncheckedSideEffectImports": true,
    "types": [],
    "noEmit": true
  },
  "include": ["src"]
}
```

Node 库不能盲用它：应根据实际 Node 版本与产物选择 `node20`/`nodenext`、package `type/exports` 和 declaration emit。测试配置显式加 Vitest/Node types，避免全局污染生产代码。

## 3. 每章工作流

### 讲义

读前先写：本章类型想保护哪个运行时不变量？编译器无法保护什么？

### 练习

- 先写调用端期望，再实现类型；API 设计从消费者出发。
- 正例用 `expectTypeOf`/赋值检查，负例用 `// @ts-expect-error` 并附原因。
- 每个类型题都写运行时实现/测试，禁止只在 Playground 看绿色。
- 类型错误过长时先简化 API，不把“能算出来”当完成。

### 答案

对照四栏：我的类型、我的运行时、答案的约束、答案的代价。关掉答案后从空文件复写。

## 4. 类型实验工具

```ts
import {expectTypeOf, test} from 'vitest'

test('public contract', () => {
  const value = parseId('u_1')
  expectTypeOf(value).toEqualTypeOf<UserId>()
})

// @ts-expect-error OrderId 不能传给用户 API
getUser(orderId)
```

`@ts-expect-error` 在错误消失时会反向报错，适合负例；`@ts-ignore` 不会，迁移临时使用也必须配 issue 和截止日期。

## 6. JavaScript 背景的思维转换

- 类型注解不改变 JS 运行；先理解值，再写类型。
- 类型是值集合，不只是类名。`'open' | 'closed'` 比 `string` 更精确。
- narrowing 是控制流证明；不是“我告诉编译器相信我”。
- 泛型表达输入输出关系；如果类型参数只出现一次，往往不需要泛型。
- `unknown` 迫使验证；`any` 让不安全传播。
- 结构类型看形状不看声明来源；Brand 是有意增加名义区分的局部工具。

前 12 章可在单包完成；第 13 章起扩为 workspace，最终直接演进成毕业项目。

## 8. 性能与复杂度纪律

- 一个类型让编辑器 hover/补全明显变慢，就必须 trace 和简化。
- 递归类型必须有终止/限深；组合优先接口/命名中间类型，避免巨型交叉。
- 公共错误信息是开发者体验；必要时用 helper/重载换取清晰错误。
- 类型能自动生成时不要手工维护两个真相；运行时 Schema 与静态类型选择单一源。

## 9. 求助时提供

1. 最小复现和 TypeScript 精确版本；
2. tsconfig/package `type/exports`；
3. 期望推断与实际 hover/错误；
4. 运行时环境/构建器；
5. 是否是类型正确性、模块解析、声明 emit 或性能问题；
6. `--traceResolution`、`--extendedDiagnostics` 或性能 trace 的必要摘要。
