# TS Master：从“会写类型”到大型 TypeScript 工程负责人

> 调研与编写日期：2026-08-03  
> 适合你：JavaScript 中级及以上；能使用 TypeScript 完成普通业务，但希望达到一线团队对高级前端/Node/全栈工程师的 TypeScript 要求。

这套指南不把 TypeScript 学成“背语法”和“类型体操比赛”。目标是五项可交付能力：**让非法状态无法表达、让外部数据先验证再信任、设计可推断的公共 API、治理大型代码库、平稳完成版本与 JavaScript 迁移**。

## 从哪里开始

1. 读 [市场调研与能力地图](./00-市场调研与能力地图.md)，理解岗位真正需要的不是 `Pick/Omit` 背诵。
2. 读 [学习方法与版本策略](./00-学习方法与版本策略.md)，建立 TS 6 严格模式实验仓库。
3. 按 01 → 18 顺序学习。每章固定顺序：`00-讲义.md` → `01-练习/README.md` → `02-答案/README.md`。
4. 先提交自己的解法再看答案；抄答案后关掉文档，从空文件重写核心类型和运行时代码。
5. 第 18 章完成一个“类型安全 SDK + 应用”毕业项目，并进行迁移、性能、发布答辩。

## 当前版本结论

- 截至 2026-08-03，TypeScript 官方最新稳定补丁为 **6.0.3**。
- TypeScript 6.0 是现有 JavaScript/TypeScript 编译器代码线的最后一个大版本，也是通往原生 Go 版 TypeScript 7.0 的桥接版本。
- 本课程使用 TypeScript 6.0 最新补丁做实验，保留 5.9 企业兼容说明；TypeScript 7 只做预览、性能对比和迁移演练，不把预览行为当生产基线。
- 不以 namespace、内部 module、AMD、旧版 decorator、全局 UMD 或 `ts-ignore` 堆积为主线；遗留项目只学习识别与迁移。

官方依据：[TypeScript 6.0 发布说明](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/)、[TypeScript Releases](https://github.com/microsoft/TypeScript/releases)。

## 建议节奏

### 标准路线：22 周

- 每周 8–12 小时；第 6–8、13–16 章可各用两周。
- 第 1–5 章：写出可靠业务类型；第 6–9 章：设计高级 API/领域模型；第 10–15 章：打通运行时与生态；第 16–18 章：负责大型工程。

### 12 周冲刺

- 每周 18–24 小时。
- 所有讲义必读；每章只独立完成练习一，练习二读答案后复写；第 18 章不得跳过。

整套训练约 140–220 小时，毕业项目再投入 60–100 小时。

## 每章通过标准

- 能解释一处“类型看似更严格，实际却更不安全”的反例。
- 练习一独立完成，练习二至少能复写并解释权衡。
- 运行时测试与类型测试都通过；负向类型用例必须有预期错误。
- 公共 API 调用端推断自然，不能靠调用者到处显式泛型或 `as`。
- 能说出何时应该停止类型体操、改用运行时校验或更简单 API。

## 毕业能力

- 用判别联合、Brand、Result/状态机编码业务不变量。
- 在网络、存储、消息、环境变量边界从 `unknown` 开始，以 Schema 产生可信类型。
- 设计推断良好、错误信息可读、兼容演进的泛型 API 和 npm 类型库。
- 解释型变、条件类型分布、模块解析、声明 emit、project references 与 checker 性能。
- 主导 JS→TS、strict 开启、TS 5.9→6.0→7.0 预演，提供指标、灰度和回滚。
- 审查 AI 生成的 TS 代码，识别 `any`、断言、假泛型、运行时缺口和复杂度炸弹。

## 三条纪律

1. TypeScript 不验证运行时数据；`JSON.parse(...) as User` 不是校验。
2. 不以类型越长越高级；调用端、错误信息、编译性能和维护成本都是 API 的一部分。
3. `any`、类型断言和 `@ts-ignore` 不是原罪，但每次使用必须标出被隔离的信任边界、owner 和退出条件。
