# 第 08 章：条件类型、`infer`、分布式与模板字面量

## 本章目标

能阅读/编写有边界的类型级函数，理解 union 分布、`never/any` 污染和递归性能；知道什么时候一个运行时 builder 或代码生成优于类型解析器。

## 1. 条件类型

```ts
type ElementOf<T> = T extends readonly (infer U)[] ? U : T
```

它像类型层模式匹配：若 T 可赋给约束，取真分支。若 T 含未决泛型，结果可能延迟计算。

## 2. `infer`

`infer` 只在条件类型匹配位置声明要提取的部分：

```ts
type Return<T> = T extends (...args: never[]) => infer R ? R : never
type First<T> = T extends readonly [infer H, ...unknown[]] ? H : never
type Await<T> = T extends PromiseLike<infer U> ? Await<U> : T
```

重载函数推断通常从最后/最宽实现签名提取，不能对 overload 列表逐个模式匹配；库 API 不应靠 ReturnType 精确恢复所有 overload。

## 3. 分布式条件类型

当左侧是裸类型参数：

```ts
type ToArray<T> = T extends unknown ? T[] : never
type X = ToArray<string | number> // string[] | number[]
```

它对 union 每成员执行再联合。禁用分布：

```ts
type ToArrayNonDist<T> = [T] extends [unknown] ? T[] : never
// (string|number)[]
```

这是大量高级类型 bug 的根源。每个条件类型都要问：是否希望分布？

## 4. `never` 行为

never 是空 union，分布式条件对零个成员执行仍是 never。检测 never 要包 tuple：

```ts
type IsNever<T> = [T] extends [never] ? true : false
```

## 5. `any` 的污染

any 在条件类型中可能产生两分支联合或直接传播，破坏证明。公共 helper 可对 any 做检测，但复杂且有成本；更好是在输入边界禁止 any 流入核心泛型，lint/type tests 控制。

## 6. 模板字面量类型

```ts
type EventName<K extends string> = `${K}Changed`
type Route = `/users/${string}`
```

可与 mapped remap 组合生成 API。union 交叉插值会做笛卡尔积，规模迅速爆炸；大量字符串集合应代码生成或普通 string+runtime validator。

## 7. 模板解析

```ts
type ParamNames<Path extends string> =
  Path extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ParamNames<Rest>
    : Path extends `${string}:${infer Param}` ? Param : never
```

能服务小型路由 API，但 optional/catch-all/escape/query 语法一扩展，类型和 runtime parser 必须保持一致。最好一个 route builder 同时产生二者或用测试对齐。

## 8. 递归与限深

递归类型可能触发 instantiation excessively deep、union explosion 和编辑器卡顿。策略：

- 限制输入域/最大深度；
- 用 tuple counter；
- 命名中间类型、尾递归友好结构；
- 减少分布/交叉；
- 对生成的大类型用代码生成；
- 用 `--generateTrace`/性能工具而非猜。

## 9. Union to Intersection 等体操

利用逆变位置可把 union 转 intersection，但可读性、边界和编译成本差。只有库内部明确需求并有类型/性能测试时用，不把面试谜题带进业务。

## 10. 类型函数设计原则

- 输入域小而明确；
- 递归有终止和限深；
- 对 any/never/unknown/union 写测试；
- 类型与 runtime 单一源或 contract tests；
- public alias 命名/文档/错误可读；
- 测量 declaration/checker 成本；
- 超过阈值改 codegen/builder。

## 本章速记

条件类型是可分布的类型模式匹配，`infer` 提取结构。模板和递归能构造强 API，也最容易造成类型爆炸；高级判断常常是及时停止。
