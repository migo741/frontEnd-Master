# 第 02 章：严格模式、字面量推断与 `satisfies`

## 本章目标

让 strict flags 真正暴露模型缺陷；掌握字面量 widening、上下文类型、`as const` 与 `satisfies`，避免通过断言获得“假精确”。

## 1. `strict` 是基线，不是终点

`strict` 打开一组核心检查，如 null、函数参数、隐式 any 等；大型项目还常启用：

- `noUncheckedIndexedAccess`：索引读取加入 undefined；
- `exactOptionalPropertyTypes`：`x?: T` 不自动等同 `x: T | undefined` 的写入；
- `noImplicitOverride`：子类覆盖必须明确；
- `noPropertyAccessFromIndexSignature`：索引签名字段用 bracket 访问；
- `useUnknownInCatchVariables`（strict 已相关）：catch 从 unknown 开始；
- `noUncheckedSideEffectImports`：副作用 import 不存在也报错；
- `verbatimModuleSyntax`、`isolatedModules`：让单文件转换/类型 import 行为可预测。

不要一次开启后用 2,000 个 `as` 清零。按风险分批、统计错误类别、先修边界源头。

## 2. null/undefined 是领域信息

区分：

- 属性缺失；
- 属性存在且值 undefined；
- 明确 null；
- 尚未加载；
- 加载后为空。

一个 `User | null | undefined` 没说明三者语义。判别状态更清晰：

```ts
type UserState =
  | {status: 'loading'}
  | {status: 'loaded'; user: User | null}
  | {status: 'failed'; error: Error}
```

## 3. 字面量 widening

```ts
const method = 'GET' // 'GET'
let method2 = 'GET'  // string
const request = {method: 'GET'} // 属性可变，method 通常是 string
```

对象是 const 只表示变量绑定不变，属性仍可写，所以属性字面量可能拓宽。可用注解、`as const` 或 `satisfies`，但语义不同。

## 4. `as const`

```ts
const routes = ['home', 'settings'] as const
type Route = typeof routes[number]
```

它把字面量递归保留并增加 readonly。适合静态表/enum-like 数据。不要为了拿字面量把本应可变的业务对象全部 readonly，再到处复制/断言。

## 5. `satisfies`

```ts
type RouteConfig = Record<string, {path: `/${string}`; auth: boolean}>

const routes = {
  home: {path: '/', auth: false},
  admin: {path: '/admin', auth: true},
} satisfies RouteConfig

routes.admin.path // 仍保留 '/admin' 的精确信息
```

注解 `const routes: RouteConfig` 可能把 keys/values 拓宽；断言 `as RouteConfig` 可能跳过错误；`satisfies` 检查兼容又保留表达式类型。它不改变运行时，也不让嵌套对象自动不可变。

## 6. 索引安全

```ts
const users: User[] = []
const first = users[0] // noUncheckedIndexedAccess 下 User | undefined
```

如果业务保证非空，用非空 tuple 建模：

```ts
type NonEmptyArray<T> = readonly [T, ...T[]]
```

不要用 `users[0]!` 抹掉问题，除非同一局部控制流刚证明 length 并且编译器无法连接。

字典同理：`Record<string, User>` 暗示任意 string 都有 User，常常是谎言。用 `Partial<Record<...>>`、Map 或有限 key union。

## 7. 可选属性精确语义

`exactOptionalPropertyTypes` 下：

```ts
type Options = {color?: 'dark' | 'light'}
const a: Options = {}                     // 缺失
const b: Options = {color: undefined}     // 不合法，除非显式含 undefined
```

这会改善 `'color' in options`、对象 spread、Patch/merge 语义。若 API 确实允许“显式 undefined 清除”，写 `color?: ... | undefined` 或更清楚的 patch 指令。

## 8. `any` 隔离

第三方/遗留边界暂时 any 时：马上赋给 unknown 或在 adapter 内解析，不能让 any 流入业务泛型。

```ts
const legacy: any = getLegacy()
const raw: unknown = legacy
const parsed = parseLegacy(raw)
```

记录 any budget：位置、原因、owner、退出条件。目标是控制传播，不是追求仪表盘上的绝对零。

## 9. 配置分环境

浏览器、Node、测试、构建脚本需要不同 `lib/types/module`。基线 config 放通用 strict 规则，子 config 增加环境：

```text
tsconfig.base.json
tsconfig.browser.json   # lib DOM, types []
tsconfig.node.json      # types [node]
tsconfig.test.json      # types [vitest/globals] 或显式 import
```

TS 6 `types` 默认 `[]` 使隐式全局更少，但旧项目升级会出现 process/describe 找不到；应在正确子项目显式添加，不在 root 塞全世界。

## 本章速记

strict flags 把模糊数据模型变成显式错误；`as const` 冻结类型层字面量，`satisfies` 检查契约并保留精确推断。正确修复是完善模型，不是清零错误数量。
