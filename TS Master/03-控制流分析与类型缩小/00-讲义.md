# 第 03 章：控制流分析与类型缩小

## 本章目标

把 narrowing 理解为控制流证明；会用判别联合和穷尽检查让分支与领域状态一致，并识别错误守卫造成的“编译器相信谎言”。

## 1. 缩小是集合求交

```ts
function format(value: string | number) {
  if (typeof value === 'string') return value.trim()
  return value.toFixed(2)
}
```

条件为真分支把联合与 string 集合求交；控制流图跟踪 return、赋值、循环和可达性。离开分支后类型可能恢复，因为变量原始声明仍允许更多值。

## 2. 常用缩小

- `typeof`：注意 null 是 object，函数是 function；
- `instanceof`：依赖真实 prototype/realm，不适合 JSON；
- `in`：属性是否存在，optional 属性可能同时出现在两侧；
- 相等性：两个值相等时取可能类型交集；
- 真值：会同时排除 `''/0/false`，若它们是合法业务值会出错；
- `Array.isArray`：缩小数组；
- 判别字段：最稳定的业务分支。

```ts
if (value) { /* 不能区分合法空字符串和缺失 */ }
if (value !== undefined) { /* 语义精确 */ }
```

## 3. 判别联合

```ts
type Payment =
  | {status: 'idle'}
  | {status: 'processing'; operationId: string}
  | {status: 'succeeded'; receiptId: string}
  | {status: 'failed'; code: string; retryable: boolean}
```

每个变体只含该状态合法字段，优于 `isLoading/error/data?`。switch 后字段自动收窄，新增变体会触发穷尽错误。

## 4. `never` 穷尽检查

```ts
function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`)
}

function label(payment: Payment): string {
  switch (payment.status) {
    case 'idle': return '待支付'
    case 'processing': return '处理中'
    case 'succeeded': return '成功'
    case 'failed': return '失败'
    default: return assertNever(payment)
  }
}
```

`default` 的运行时 throw 仍有价值：输入可能来自旧缓存/未验证 JS。静态穷尽不替代边界校验。

## 5. 类型谓词的责任

```ts
function isUser(value: unknown): value is User {
  return typeof value === 'object' // 谎言：检查远少于承诺
}
```

TypeScript 不验证 predicate 实现。守卫返回 `value is T` 相当于安全关键承诺，必须完整检查/测试。若只检查部分，返回更小事实：

```ts
function isRecord(value: unknown): value is Record<PropertyKey, unknown> { /* ... */ }
```

## 6. Assertion Function

```ts
function assertDefined<T>(value: T, message: string): asserts value is NonNullable<T> {
  if (value == null) throw new Error(message)
}
```

适合测试、启动配置、必须失败的边界。不要用空实现 `asserts` 消除错误；失败策略要明确。

`asserts condition` 也可表达不变量，但过度使用会把普通分支变异常流程。

## 7. 控制流失效和别名

```ts
function process(user: {name?: string}) {
  if (user.name) {
    unknownCallback(user)
    user.name.toUpperCase()
  }
}
```

callback 可能修改对象；TS 为实用性不总使缩小失效。关键值先复制为局部不可变值或使用 readonly/不可变边界：

```ts
const name = user.name
if (name !== undefined) { unknownCallback(user); name.toUpperCase() }
```

## 8. 联合对象不要解构丢关联

某些场景中过早解构可能让 `kind` 与 payload 关系难以追踪（新版本不断改进，但 API 设计仍应清晰）：

```ts
function handle(result: Result) {
  if (result.ok) console.log(result.value)
}
```

先按判别字段缩小完整对象，再取字段，错误更易读。

## 9. `in` 与精确可选

`'x' in obj` 检查属性存在，即使值 undefined。`exactOptionalPropertyTypes` 让“存在/缺失”更可靠；若类型显式允许 undefined，仍需第二步检查值。

## 10. 边界分层

复杂验证不要手写一个声称完整的 type guard。第 10 章用 Schema 产生解析结果；业务层只处理已验证判别联合。理想流：

```text
unknown bytes -> parse/validate -> domain union -> exhaustive business logic
```

## 本章速记

缩小是控制流中的证明，predicate/assertion 是你对编译器的承诺。判别联合把合法状态编码，`never` 让新增状态强制触达所有处理器。
