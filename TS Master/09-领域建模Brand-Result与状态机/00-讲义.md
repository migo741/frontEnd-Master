# 第 09 章：Brand、Result、状态机与领域不变量

## 本章目标

用类型表达业务语义而非数据库形状：相同基础类型的 ID/金额不串用，错误成为显式协议，状态转换只允许合法路径。

## 1. Brand/opaque type

结构类型会让所有 string ID 相容。Brand 增加不可伪造标记（在类型层）：

```ts
declare const userIdBrand: unique symbol
type UserId = string & {readonly [userIdBrand]: 'UserId'}
```

外部不能自然产生 UserId，应由 smart constructor/Schema 验证格式后返回。Brand 运行时仍是 string，不提供加密/真实性；从 JSON 读回会丢品牌，需重新 parse。

不要每个字符串都 Brand。适合高风险且易串的 ID、单位、已验证/已净化状态。

## 2. Smart constructor

```ts
function parseUserId(raw: string): Result<UserId, IdError> {
  return /^usr_[a-z0-9]+$/.test(raw)
    ? ok(raw as UserId)
    : err({kind: 'invalid-user-id', raw})
}
```

断言集中在验证通过处，调用端不能 `as UserId`（lint/code review/type test约束）。构造器可标准化大小写/空格，但要记录是否改变用户输入。

## 3. Result

```ts
type Result<T, E> =
  | {ok: true; value: T}
  | {ok: false; error: E}
```

适合预期、调用者应处理的失败：校验、404、冲突。异常适合不变量破坏/无法恢复环境错误，但 JS 生态常混合；建立边界转换策略。

Result 让错误类型可组合，但 E union 可能膨胀；跨层应映射为该层关心的领域错误，不把数据库/HTTP 错误泄漏到 UI。

## 4. 错误也要判别

```ts
type SaveError =
  | {kind: 'validation'; fields: Record<string, string>}
  | {kind: 'conflict'; currentVersion: number}
  | {kind: 'forbidden'}
  | {kind: 'unavailable'; retryAfterMs?: number}
```

不要只 `Error & {code:string}` 然后任意 code；有限联合提供穷尽。保留 cause/trace 供日志，但用户消息脱敏。

## 5. 金额和单位

JS number 有浮点和单位风险。领域常用最小货币单位 integer + currency：

```ts
type Money<C extends Currency> = {readonly minor: bigint; readonly currency: C}
```

相加需同 currency，汇率转换是显式服务/舍入策略。泛型 currency 可阻止 USD/CNY 编译期相加，但动态 currency 仍需运行时检查。

## 6. 状态机

State 联合描述合法快照；transition 定义合法边：

```ts
type Order =
  | {status: 'draft'; items: readonly Item[]}
  | {status: 'submitted'; orderId: OrderId; submittedAt: Date}
  | {status: 'paid'; orderId: OrderId; receipt: Receipt}
  | {status: 'cancelled'; orderId: OrderId; reason: string}
```

不要提供 `setStatus(status)`；暴露 `submit/pay/cancel` 领域命令，各自输入/输出限制。

## 7. Phantom state 与 runtime state

泛型 `Order<'draft'>` 可让某些方法仅在状态出现，但动态从 API 得到的订单仍是 union，必须缩小。过度 phantom builder 使存储/序列化复杂。业务应用通常判别联合更透明；库的编译期步骤 API才考虑 phantom。

## 8. 不变量的层次

- 类型：字段关系、有限状态、单位；
- 构造器/Schema：格式、范围；
- 领域服务：跨实体/数据库唯一、库存；
- 数据库：事务、约束；
- 分布式协议：幂等、版本、顺序。

不要让精美类型掩盖库存仍需服务端事务。

## 9. 序列化

Date/BigInt/Brand/Map 不自动通过 JSON 保持语义。定义 Wire DTO：Date ISO string，Money minor 可 decimal string，边界 parser 转 Domain。不要让 Domain type 直接声称可 JSON.stringify/parse roundtrip。

## 10. 评审清单

- 哪些基础类型易串且高风险，值得 Brand？
- Brand 由谁验证/恢复，能否被随处断言？
- 失败是 Result 还是 exception，在哪层映射？
- 状态/错误是否判别且穷尽？
- 单位/舍入/动态数据是否运行时校验？
- 类型之外的事务/授权/幂等在哪里？

## 本章速记

领域类型把业务语言写进编译器，但只保护进程内已验证关系。Brand 需要 smart constructor，Result 需要错误映射，状态机需要运行时 transition，金额需要单位与舍入协议。
