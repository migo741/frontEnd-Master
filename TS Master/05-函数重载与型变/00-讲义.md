# 第 05 章：函数类型、重载、回调与型变

## 本章目标

设计函数 API 时保持输入输出关系、调用端错误可读，并理解为什么“能处理 Dog 的函数”不一定能当“能处理 Animal 的函数”。

## 1. 函数类型组成

```ts
type Mapper<T, U> = (value: T, index: number) => U
```

参数、返回、泛型、this、可选/rest 都是契约。实现函数可接受更宽输入、返回更窄输出，但赋值方向受型变影响。

不要写 `Function`：它几乎没有可安全调用的签名。未知可调用值先验证 `typeof value === 'function'`，然后按具体协议包装。

## 2. 参数数量与可选回调

函数接受较少参数通常可用于要求较多参数的回调，因为它可以忽略额外参数：

```ts
const names = ['1', '2'].map(value => Number(value))
```

不要把回调参数写 optional 只因为调用者可以少声明：

```ts
type BadCallback = (value: string, index?: number) => void
```

这表示实现必须能处理 index 缺失；若框架保证传 index，应该必选。

## 3. `void` 返回的特殊规则

一个返回值函数可赋给 `() => void`，调用者承诺忽略返回：

```ts
const cb: () => void = () => 123
```

但显式声明 `function f(): void { return 123 }` 通常不允许返回值。注意 async callback 传给期望 void 的事件 API：Promise rejection 可能无人处理，lint `no-misused-promises`/wrapper 很重要。

## 4. 重载、联合还是泛型

重载适合输入形状有少数离散、返回相关分支：

```ts
function parse(input: string): Ast
function parse(input: Uint8Array): Ast
function parse(input: string | Uint8Array): Ast { /* ... */ }
```

实现签名对调用者不可见，必须兼容所有 overload。联合参数适合返回相同；泛型适合连续关系。不要为每个字面量写几十个 overload，也不要用泛型 `T extends string|number` 却最终返回无关类型。

联合输入变量调用重载可能失败：调用者只有 `string | Uint8Array`，没有命中单一签名。若要支持，应增加联合 overload/改为联合参数。

## 5. 参数型变

设 Dog extends Animal：

- 返回值通常协变：`()=>Dog` 可给 `()=>Animal`；
- 参数安全方向是逆变：能处理所有 Animal 的 handler 可用于只会收到 Dog 的位置；反之不安全。

```ts
type Handler<T> = (value: T) => void
let dogHandler: Handler<Dog>
let animalHandler: Handler<Animal>
dogHandler = animalHandler // 安全：传来的 Dog 也是 Animal
animalHandler = dogHandler // 不安全：可能收到 Cat
```

`strictFunctionTypes` 对函数属性检查更严格；方法历史上保留双变行为以兼容常见类/DOM，库设计不要依赖该漏洞。

## 6. 可变容器与型变

`Dog[]` 被当作 `Animal[]` 后可 push Cat，运行时破坏。readonly 数组只读时协变更合理：

```ts
function visit(animals: readonly Animal[]) {}
```

API 不需要写就接受 readonly，减少别名风险。

## 7. 带标签的 rest tuple

```ts
type LogArgs =
  | [event: 'open', id: string]
  | [event: 'error', error: Error, retryable: boolean]

function log(...args: LogArgs) { /* ... */ }
```

能表达参数列表联合并提供 hover 标签，但函数内解构/缩小要测试目标版本。事件 API 更常用映射表泛型，第 6 章练习。

## 8. `this` 参数

```ts
function handle(this: HTMLButtonElement, event: MouseEvent) {}
```

假 this 参数仅用于检查，不 emit。现代函数式 API 常避免动态 this；声明旧库/DOM 插件时很重要。箭头函数没有动态 this。

## 9. 重载错误信息

公共 API 的 overload 顺序、数量影响错误和 inference。由具体到一般排列；不要暴露 implementation signature；为消费者写失败 fixture，检查错误是否指向真实问题。

## 10. 评审清单

- 输入输出是离散重载、联合还是泛型关系？
- 回调参数是否错误 optional？
- async function 传 void callback 是否吞 rejection？
- handler 型变方向安全吗？是否用 method 双变掩盖？
- 输入容器是否只需 readonly？
- overload 是否支持联合变量/错误是否可读？

## 本章速记

函数类型的难点在方向：返回协变、参数逆变、可变容器破坏安全。重载表达少量离散关系，泛型表达可复用关系；调用端错误信息也是设计结果。
