# 第 22 章练习

本章仍然只有两题，但都是综合验收。不要同时再做第二个毕业项目。

## 练习一：交付多租户 AI 工单与运营工作台

按讲义阶段 A–F 交付一个可访问的旗舰作品。

最低功能：

- 用户登录、tenant 切换、membership 与 RBAC；
- 工单创建、稳定分页、分派、状态、评论和附件；
- Idempotency-Key、统一错误和完整审计；
- Agent run 状态机、Outbox、queue、checkpoint、取消；
- Python worker 的版本契约和固定 Eval；
- SSE 序号、回放、背压、断线恢复；
- tool intent、参数绑定 HITL、Node 幂等执行；
- PostgreSQL 权威、Redis 缓存/限流、对象存储；
- logs/metrics/traces、SLO、成本和容量 dashboard；
- Docker/CI/CD、迁移、canary、回滚、备份与恢复。

强制故障验收：

1. 两个租户猜测同一资源 ID；
2. 相同 HTTP 请求并发重复；
3. Outbox/结果消息重复和乱序；
4. worker checkpoint 后崩溃；
5. 外部 tool 成功后响应丢失；
6. Redis 全清空；
7. 模型超时与迟到结果；
8. SSE 在审批前断开并恢复；
9. canary 发布错误版本并回滚；
10. 从备份与 WAL 恢复后重放 Outbox。

真实用户验收：至少完成三轮“观察 → 指标/反馈 → 修改 → 再验证”。如果无法公开用户数量，提交匿名化研究与内部 owner 证明。

## 练习二：45 分钟系统设计、红队与现场变更

准备一个不依赖幻灯片也能完成的答辩。

时间盒：

```text
0–5 分钟：用户、规模、范围与 SLO
5–12 分钟：领域模型、租户与数据权威
12–22 分钟：同步/异步/Agent/HITL 主链路
22–30 分钟：失败、安全、观测、发布与恢复
30–38 分钟：现场变更
38–45 分钟：取舍、证据、未知风险与追问
```

现场变更由同伴随机抽一题：

- 支持第二模型供应商并保持 Eval/成本可比；
- 一个 tenant 突增到普通租户 100 倍流量；
- 工具审批改为双人四眼原则；
- 用户要求数据驻留在不同区域；
- 长任务最长从 1 分钟变成 24 小时；
- 外部邮件服务不支持 idempotency key；
- 模型供应商发生数据泄漏，需要立即隔离和轮换。

要求现场修改架构图、不变量、数据模型、失败语义、迁移和观测，不只说“加中间件”。

红队至少尝试跨租户、SSRF、Prompt Injection、审批参数替换、重复消费、日志泄密和供应链制品替换。

提交录屏、评审评分表、未答好的问题、48 小时内的补充 ADR，以及重做后的第二版答辩。
