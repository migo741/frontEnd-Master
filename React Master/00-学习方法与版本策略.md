# 学习方法、环境与版本策略

## 1. 版本策略：稳定、现代、可迁移

本课程分三层：

1. **React 18/19 共通层**：函数组件、Hooks、快照、协调、Effect、并发语义、Suspense、`useSyncExternalStore`。这是企业主战场。
2. **React 19 稳定增量**：Actions、`useActionState`、`useOptimistic`、`useFormStatus`、ref 作为 prop、资源与元数据能力；19.2 的 `useEffectEvent`、`Activity` 和性能轨道按专题学习。
3. **框架层**：React Router 的数据路由与 Next.js App Router/RSC。框架会继续演进，所以重点学边界与不变量，不背瞬时 API。

练习包不要写死一个可能很快过时的补丁号。创建项目时安装当前主版本线的**最新补丁**并提交 lockfile：

```bash
npm create vite@latest react-lab -- --template react-ts
cd react-lab
npm install
npm install react@^19.2 react-dom@^19.2
npm run dev
```

如果目标公司明确使用 React 18，再建立一个兼容分支：

```bash
git switch -c compat/react-18
npm install react@^18.3 react-dom@^18.3
```

React 19 专属练习在 React 18 分支用传统事件处理、`useTransition` 或库能力完成，并在 README 记录差异。不要为了“兼容”把整个主线降到 React 16/17。

## 2. 推荐环境

- Node.js：仍在官方支持期的 LTS；不要依赖停止维护的 Node 版本。
- 包管理：npm/pnpm 均可，团队内必须统一并提交唯一 lockfile。
- TypeScript：开启 `strict`，建议同时开启 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`。
- 编辑器：开启 TypeScript、ESLint；格式化与 lint 分工，不让两套规则互相打架。
- 浏览器：Chrome/Edge DevTools + React DevTools；性能题必须保存 profile 截图或 JSON。
- Git：每个练习单独 commit，答案复写使用另一个 commit，便于比较思路变化。

建议的脚本契约：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "typecheck": "tsc -b --pretty false",
    "lint": "eslint . --max-warnings=0",
    "test": "vitest run",
    "test:e2e": "playwright test"
  }
}
```

## 3. 每章固定工作流

### 第一步：讲义

先写下三个问题的初始答案：

- 本章解决的生产问题是什么？
- 最容易滥用的 API/模式是什么？
- 我会用什么证据判断方案有效？

再读 `00-讲义.md`，运行所有“反例”并主动预测结果。

### 第二步：练习

- 先读验收标准，再写设计草图。
- 练习一要求独立完成；练习二是高难典例，允许卡 60–90 分钟后看提示。
- 不提前看答案目录。不会时先写失败原因和假设，这本身就是高级工程师的训练。

### 第三步：答案

- 答案是参考实现，不是唯一实现。
- 对照时做三栏笔记：我的决策、答案的决策、适用约束。
- 关闭答案，从空文件重写关键模块；只复制一遍不会形成可迁移能力。

## 4. 证据驱动的学习记录

每章在自己的练习仓库保留：

```text
docs/chapter-xx/
├── notes.md          # 你的心智模型与误区
├── decision.md       # 关键取舍/ADR
├── evidence/         # profile、瀑布图、覆盖率、截图
└── retrospective.md  # 哪里错、为什么错、下次如何更快发现
```

复盘模板：

```md
## 现象
## 我的第一假设
## 证据如何推翻/支持假设
## 根因
## 最小修复
## 为什么没有采用另一个方案
## 如何防止回归
```

## 5. Vue 3 经验如何迁移

| Vue 3 直觉 | React 中应替换为 |
|---|---|
| 响应式对象被跟踪 | 每次渲染拿到 state/props 的快照 |
| `computed` | 渲染时直接派生；昂贵才测量后 memo |
| `watch`/`watchEffect` | 先问是否真在同步外部系统；不是就用事件或派生值 |
| `v-model` | 受控值 + `onChange`，或清晰的非受控契约 |
| template 指令 | JavaScript 控制流 + JSX |
| scoped slot | children、render prop、组合组件 |
| Pinia store | 先分类状态，再选 Context/外部 store/服务端缓存 |
| 生命周期顺序 | render/commit + Effect 的同步/清理语义 |

最重要的切换：React 不是“我改了一个响应式变量，谁依赖它就更新”，而是“某次更新安排了一次渲染，组件函数重新运行并得到一个不可变快照”。

## 6. 时间预算

单章参考：

- 讲义与预测：2–3 小时
- 练习一：2–4 小时
- 练习二：2–6 小时
- 答案复写与复盘：1–2 小时

整套课程约 140–220 小时，加毕业项目约 60–120 小时。对“高级岗位”而言，这比刷 500 道零散题更接近真实工作，但仍应把练习结果放进一个持续演进的项目，而不是 18 个互不相关的 Demo。

## 7. 求助规则

卡住时按顺序提供：

1. 最小复现；
2. 预期与实际；
3. 已验证的假设；
4. React/浏览器/库版本；
5. profile、网络记录或错误栈。

能把问题缩小一半，通常就已经解决了一半。
