# 第 18 章：毕业项目、系统设计与面试

## 本章目标

把前 17 章合成一个可评审、可测量、可答辩的生产级作品。目标不是“功能多”，而是证明你能识别约束、设计边界、交付质量并解释取舍。

## 一、毕业项目：AI 运营工作台

你将构建一个多租户 B2B 工作台：

- 登录/组织切换/RBAC；
- 工单列表：URL 搜索、筛选、分页、详情；
- 工单编辑：表单校验、版本冲突、离线草稿；
- 实时协作：状态更新、通知、断线恢复；
- AI 助手：流式生成回复、引用、工具确认、取消/重试；
- 管理仪表盘：大列表/图表、性能预算；
- 审计日志和可观测性。

### 非目标

- 不训练模型；用可靠 fake/server adapter。
- 不追求视觉大而全；优先无障碍和交互状态。
- 不为展示而塞入所有状态库。每种状态必须有归属理由。

## 二、推荐技术基线

两条路线任选：

1. Vite + React Router Data/Framework + TanStack Query + 必要的 feature store；适合展示客户端架构。
2. Next.js App Router + RSC/Server Actions + Client Query（仅需要处）；适合展示全栈边界。

共同：React 19.2 最新安全补丁（另建 React 18 兼容说明）、TypeScript strict、Vitest/RTL/MSW、Playwright、ESLint hooks/compiler rules、schema validation、可观测 adapter。库版本使用创建项目时支持线最新补丁并提交 lockfile/SBOM。

## 三、先写设计，后写页面

### 1. 需求与不变量

例：用户只能看到所属 tenant 工单；Server Action 每次重验权限；同一个保存意图幂等；本地旧响应不能覆盖新版本；AI 工具执行需确认。

### 2. 数据分类

URL：列表 query/filter/page/selected ticket；Server cache：ticket/user/audit；Form：edit draft；Shared client：离线 mutation/跨步 AI composer；Local：面板展开；Ref/service：socket/abort/imperative editor。

### 3. 图

至少画：容器/信任边界图、前端模块依赖图、一次“打开工单”的 sequence、一次“AI 工具确认”的状态机、缓存/失效表、错误边界树。

### 4. ADR

至少 5 个：渲染策略、状态库、请求/缓存、实时协议、组件库/表格、微前端是否采用（通常不采用也要论证）。

## 四、迭代里程碑

### M0：基线（1 周）

仓库、CI、类型/lint/test/build、路由壳、MSW/fake server、架构文档。定义性能/可用性/SLO。

### M1：可靠 CRUD（2 周）

URL 列表/详情、Query cache、错误/空/pending、表单与 409 冲突、RBAC 服务端检查。完成最值钱集成测试。

### M2：实时与 AI（2 周）

WebSocket/SSE 状态机、序列/重连、流式 AI、工具确认/审计、取消/重试、长列表性能。

### M3：生产质量（1–2 周）

Profiler/瀑布优化、a11y、威胁模型、observability、E2E、bundle/performance budget、故障演练。

### M4：迁移与答辩（1 周）

写 React 18 兼容/React 19 收益、一次架构演进、发布/回滚、事故复盘；录制 15 分钟演示与 30 分钟答辩。

## 五、系统设计方法

面对“设计一个大型 React 系统”：

1. 澄清用户、规模、SLA、SEO/设备/团队/合规，列非目标。
2. 估算数据/更新/DOM/网络/客户端/服务端容量。
3. 定义实体、状态归属、请求/实时协议、信任边界。
4. 画渲染/加载序列、错误域、缓存/失效。
5. 讨论性能、a11y、安全、可观测、测试、发布。
6. 给备选、取舍、演进和回滚。

不要一开口“用 Redux + 微前端”。先问约束，工具是结论。

## 六、代码面试方法

- 复述需求和边界用例，先设计状态类型/公共 API。
- 写最小正确版本，再加取消、错误、a11y、测试。
- 边写边讲快照、身份和复杂度；发现错误主动建立最小复现。
- 不背冷门 Hook；会查官方文档是正常工程能力，但核心心智模型应脱稿。

## 七、18 个必须脱稿的问题

1. state 为什么像快照？函数式更新解决什么？
2. render/commit 有何区别，并发渲染为何要求纯？
3. key 如何影响 state 身份？何时故意换 key？
4. 什么不是 Effect？依赖数组为什么不能撒谎？
5. 如何解决请求竞态，为什么 abort 与 requestId 都要？
6. Context、Zustand、RTK 如何选？
7. Server state 为什么不直接复制到 Redux？
8. 乐观更新的并发回滚怎么做？
9. Transition 与 deferred/debounce 区别？
10. Suspense 与 Error Boundary 各处理什么？
11. 如何证明一次 React 性能优化有效？
12. React Compiler 后还需理解 memo 吗？
13. RTL/MSW/E2E 各解决什么风险？
14. CSR/SSR/RSC 如何选？Server Component 和 SSR 区别？
15. Server Action 为什么仍要鉴权/校验？
16. 十万行实时表格如何设计？
17. AI 流式 UI 如何处理半包/重复/取消/高频渲染？
18. 如何在不大重写的情况下迁移一个旧 React 系统？

## 八、高级回答结构

每题用：定义 → 适用约束 → 失败模式 → 方案 → 证据/权衡。例“是否用 memo”：先 profile；若慢在子组件纯 render 且 props 稳定，memo 可能有效；若瓶颈是网络/DOM/Context 广播，memo 无效；Compiler 启用后验证生成优化；最后用 profile/INP 回归。

## 九、毕业门槛

项目不是“npm run build 通过”就毕业：

- 设计：约束、不变量、ADR、图、迁移/回滚完整；
- 正确性：竞态/权限/冲突/幂等有测试；
- 性能：有真实 before/after 和预算；
- 质量：键盘/a11y、安全威胁、日志隐私；
- 交付：CI、preview、灰度、runbook、复盘；
- 表达：能回答“为什么不用另一个方案”。

## 十、从高级到资深

毕业后用真实项目积累：主导一次版本/架构迁移、解决一次线上性能或稳定性事故、设计团队规范并度量收益、评审/培养他人、参与开源/技术分享。资深的证据是影响范围和持续结果，不是 Hook 数量。
