# 第 17 章：AI 流式 UI、实时与跨端意识

## 本章目标

2026 岗位越来越看重 AI 产品与全栈/跨端意识。本章不训练模型，而是训练 React 工程师把流式生成、工具调用、取消、恢复、安全和高频渲染做成可靠产品。

## 1. AI 对话不是普通 CRUD

一次消息可能经历：queued → sending → streaming → tool-waiting → completed/failed/cancelled；同时包含文本 delta、reasoning/metadata（未必可展示）、tool call、引用、附件、usage。不能只用 `{role, content}` 一个字符串覆盖所有状态。

```ts
type AssistantTurn = {
  clientId: string
  serverId?: string
  conversationId: string
  status: 'queued' | 'streaming' | 'completed' | 'failed' | 'cancelled'
  parts: MessagePart[]
  sequence: number
}
```

Part 用判别联合：text、tool-call、tool-result、citation、attachment、error。非法/未知事件要 schema 校验并可观测，不能直接渲染。

## 2. 传输选择

- `fetch` + ReadableStream：一次请求中流式响应，天然带请求 headers/body/AbortSignal，适合单 turn。
- SSE：服务器→客户端事件、自动/手写重连和 Last-Event-ID，浏览器 EventSource 不能自由设置所有 headers，常结合 cookie/token URL 策略（谨防泄漏）。
- WebSocket：双向高频、会话/协作，需心跳、重连、背压和协议。

选择从方向、认证、代理/CDN、重连、事件量出发。不要因“实时”默认 WebSocket。

## 3. 增量协议

每个事件至少考虑：conversationId、turnId、eventId/sequence、type、payload、schemaVersion。客户端：

- 校验归属和序列；
- 重复事件幂等忽略；
- 缺口触发恢复/snapshot；
- 完成/错误有终止事件；
- 切会话后旧流不能写入当前视图。

UTF-8 chunk 与业务事件边界不一致。用 `TextDecoder(..., {stream:true})` 和协议 parser 保留残片；不要假设每个 network chunk 是一行 JSON。

## 4. 高频 token 与渲染

每 token `setState` 会产生大量调度/Markdown 重解析。缓冲 delta，每 16–50ms 或每帧批量提交；不可见会话仅更新 store；文本增量与已稳定 parts 分离。Markdown 可在段落/完成时解析，或增量 parser；测量 INP/commit/内存。

自动滚动只在用户接近底部时跟随；用户向上阅读时不抢滚动，显示“有新内容”。长会话虚拟化，但动态行高、图片加载、流式尾行和焦点需要专门策略。

## 5. 取消、重试和分支

Stop 使用 AbortController/服务端 cancel；取消只影响目标 turn。客户端 abort 不保证服务端停止计费/工具执行，协议应有 cancel endpoint/ack。

重试不是简单覆写旧消息：保留用户 turn，创建新的 assistant branch/attempt；idempotency 避免重复创建。编辑旧用户消息会分叉对话，数据模型要表达 parent/branch。

## 6. Tool UI 的信任边界

模型提出 tool call 不等于已授权执行。服务端：工具 allowlist、参数 schema、用户/资源授权、超时/配额、人工确认（高风险）、审计和输出限制。客户端 UI 不执行模型生成的 JS/HTML/URL。

工具卡片显示状态、输入摘要（脱敏）、确认/取消、错误恢复。高风险“转账/删除/发消息”必须让用户明确确认最终参数，不能用乐观假成功。

## 7. Markdown、引用与 prompt injection

模型输出不可信：Markdown 渲染净化 HTML、限制 URL/image、代码块不自动执行。引用必须绑定服务器验证的 source id/URL，不接受模型随口生成链接冒充证据。

Prompt injection 不是只靠前端文案能解决。数据/工具权限隔离、最小上下文、内容标记、输出校验、人确认和审计共同防御。不要把系统 prompt、API key、内部工具结果发送到不可信客户端。

## 8. 错误与可观测性

区分网络断开、rate limit、上下文过长、安全拒绝、工具失败、模型上游、客户端解析。UI 给可执行恢复；日志记录 trace/turn/model/provider latency、首 token 延迟、tokens/s、取消率、工具成功率，不记录敏感 prompt 全文，采样/脱敏并遵循合规。

核心指标：time-to-first-token、time-to-complete、stream gap、render lag、abort ack、恢复成功率、成本/turn、用户任务成功率。

## 9. 跨端意识

React Native 共享 React 心智模型、领域 schema、query/state 逻辑，但宿主不是 DOM：没有 div/CSS/浏览器 API，导航、列表、手势、键盘、安全存储、无障碍和性能工具不同。不要追求“100% UI 代码复用”；优先共享 domain/API/types，平台 UI 按宿主设计。

Web/小程序/RN 实时连接还受后台冻结、移动网络切换、电量、App lifecycle 影响。协议需断点续传/重连，UI 显示同步状态。

## 10. 评审清单

- turn/part/event 身份和状态机是否完整？
- chunk parser 是否处理半包、重复、乱序、缺口？
- 高频 delta 是否缓冲，长会话是否控制 DOM/内存？
- stop 是否端到端取消，切会话是否隔离？
- tool 是否服务端授权/确认/审计？
- Markdown/URL/引用是否不可信处理？
- 指标、成本、隐私和降级是什么？
- 可共享的是领域层还是误把 DOM 搬到跨端？

## 本章速记

AI UI 的难点不是把 token 拼成字符串，而是事件协议、并发身份、背压、安全工具和可恢复状态。它是 React 状态建模、Effect、性能、测试与安全的综合题。
