# 第 15 章：可访问性、安全与可观测性

## 本章目标

把“上线质量”纳入组件和架构定义：不同用户能操作、攻击者不能越权/注入、团队能在事故发生时快速知道谁受影响、哪次发布导致、如何恢复。

## 1. 可访问性从语义开始

优先原生元素：button、a、input、label、fieldset/legend、table、heading、nav/main。原生语义自带键盘和辅助技术协议；给 div 加 role 往往还要手写 focus/键盘/disabled 行为。

页面 heading 层级、landmark、可见 focus、足够对比度、缩放/重排、减少动画偏好都属于基础。不要仅靠颜色表示错误/状态。

## 2. 键盘与焦点

- 交互可用 Tab/Shift+Tab/Enter/Space/Escape/方向键（按组件模式）。
- 打开 Modal：焦点进入；Tab 圈在内部；关闭：恢复触发点；背景不可交互。
- 路由导航：根据 SPA 语义将焦点移到主标题/容器并播报，不每次粗暴聚焦 body。
- 动态删除当前焦点项：将焦点放到可预测相邻项/容器。
- 虚拟列表：focus item 卸载时需 active descendant/保持窗口/替代策略。

不要用正 tabindex 排序。DOM 顺序应与视觉/阅读顺序一致。

## 3. ARIA 使用规则

第一条：能用原生就不用 ARIA。ARIA 改变可访问性树，不提供行为。`aria-label` 会覆盖可见名称，可能造成语音控制不匹配。动态通知选择合适 `aria-live`，避免每个 token/进度都轰炸屏幕阅读器。

复杂 widget 参考 WAI-ARIA Authoring Practices，但生产优先成熟 primitives 并在真实辅助技术测试。

## 4. React 常见安全边界

React 会转义插值文本：`<div>{userInput}</div>` 通常安全；危险点转移到：

- `dangerouslySetInnerHTML`/Markdown/富文本；
- `href/src/style` 等可执行或外带 URL；
- 第三方 DOM 库；
- 服务端注入/序列化；
- 依赖供应链；
- 把 token/PII 放浏览器存储、日志、source map。

HTML 必须按严格 allowlist 净化，并配 CSP/Trusted Types（环境允许时）；不要用 regex 清 HTML。链接只允许预期协议，外链 `target=_blank` 按当前浏览器/策略设置隔离。

## 5. XSS、CSRF、越权不是一个问题

- XSS：攻击脚本在你的 origin 执行；靠输出编码、净化、CSP、减少秘密暴露。
- CSRF：受害者浏览器带 cookie 发非自愿请求；靠 SameSite、CSRF token、Origin 验证、幂等/二次确认等。
- IDOR/越权：改 id 访问他人资源；每个服务端资源请求做对象级授权。

隐藏按钮、客户端路由 guard、TypeScript 类型都不是服务端授权。

## 6. 可观测性的三支柱与用户上下文

- Logs：结构化事件，包含 timestamp、level、event、request/trace id、release、route；不记录密码/token/完整 PII。
- Metrics：速率、错误率、延迟、饱和度 + 前端 Web Vitals/业务成功率。
- Traces：一次导航/用户动作跨浏览器、BFF、后端服务的因果链。

前端错误需捕获：window error、unhandledrejection、Error Boundary、路由/query 错误、资源/chunk 加载、API 失败。去重/采样，source map 私密上传并按 release 符号化。

## 7. 错误边界不等于错误处理完成

记录：错误 fingerprint、component/route stack、release、feature flags、设备/网络、trace id、最近安全 breadcrumbs。不要把用户输入/响应 body 全量上报。UI 显示追踪 id 与可恢复操作，后台用 trace 关联。

错误率必须有分母：失败数/受影响会话/请求，而不是一条异常截图。发布对比新旧 cohort，建立 SLO/告警阈值并避免报警疲劳。

## 8. Web Vitals 与业务监控

上报 LCP/INP/CLS 时包含页面模板、设备/网络、release，限制高基数字段。业务指标如“搜索完成/下单成功”与技术指标关联；否则优化 20ms 未必改善用户。

监控本身要有性能预算、批量/idle/sendBeacon 策略、失败不影响主流程。第三方 SDK 必须评估隐私、CSP、包大小和区域合规。

## 9. 事故响应

流程：确认影响 → 止血/回滚/flag → 保留证据 → 定位 release/路径 → 修复与验证 → 复盘系统原因。可恢复操作优先；不要在没有观测的情况下连续发布“试试看”补丁。

复盘无责但有行动：为什么测试/监控/边界没更早发现？owner 和完成日期是什么？

## 10. Definition of Done

- 键盘、focus、语义、错误播报验收；
- 输入/URL/HTML/权限做威胁检查；
- 敏感数据与日志审查；
- error/pending/empty/offline/slow 状态；
- 关键业务事件、错误、性能指标；
- rollout/rollback/owner/runbook。

## 本章速记

可访问性让交互协议完整，安全让信任边界完整，可观测性让反馈闭环完整。三者不是上线前附加项，而是高级 React 组件和系统的公共 API。
