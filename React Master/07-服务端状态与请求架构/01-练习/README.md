# 第 07 章练习

## 练习一：用户目录缓存策略

页面包含：筛选/分页用户列表、用户详情抽屉、编辑姓名、hover 预取下一位详情。

任务：

- 设计 query key factory；列表 key 包含规范化 filters/page，详情按 id。
- 为列表/详情分别给出 staleTime/gcTime/retry 并写业务理由。
- React Router loader 在进入页面时预取列表，组件订阅同一缓存；禁止双请求。
- detail hover 200ms 后预取；离开/网络受限时不盲预取。
- 编辑成功后，用服务端返回的完整 User 更新 detail，并让可能包含该用户的列表最终一致。
- 运行时校验响应；处理 401/403/404/422/5xx。
- 测试请求去重、旧筛选取消、编辑后列表/详情一致。

交付一张网络瀑布对比：Effect fetch 版 vs loader + cache 版。

## 练习二：并发乐观点赞（高难）

同一条消息可以快速点击点赞/取消。网络允许乱序和失败：操作 A 乐观点赞，操作 B 乐观取消；B 成功，A 最后失败。

要求：

- UI 立即响应；按钮仍可操作或明确选择串行策略。
- A 失败不能用旧快照回滚掉 B 的成功结果。
- 每个 mutation 有 clientMutationId；服务端返回权威 `liked/count/version`。
- 处理重复请求/idempotency、离线、401、版本冲突。
- 最终对权威数据重验证；测试所有 6 种完成顺序/失败组合。

先画事件时间线，再写代码。允许选择“同实体 mutation 串行化”降低复杂度，但必须解释用户体验和吞吐取舍。
