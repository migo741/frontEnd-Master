# 第 11 章练习

## 练习一：性能法医

给任意一个你已有的 React CRUD 页面，注入三个问题：

- Provider 每次 render 创建巨型 value；
- 列表每行做昂贵日期/权限计算；
- 路由 chunk 加载后才串行请求三个接口。

任务：

1. 用 production build 建基线：网络瀑布、Profiler flamegraph/ranked、Performance long task、bundle。
2. 不改代码先写根因排序和预期收益。
3. 分三次独立 commit 修复：状态/Context 边界，计算/列表，加载序列。
4. 每次复测；若 `memo` 没收益就删除。
5. 启用 React Compiler 的小范围试验，记录编译覆盖、行为测试和 profile 差异。
6. 写性能预算并在 CI 加至少一项可自动检查的门禁。

答案不看绝对毫秒，重点看实验设计和证据链。

## 练习二：十万行实时表格方案（高难）

场景：100,000 行，每秒 2,000 条价格更新；用户可排序、筛选、固定列、键盘导航和选择。低配办公电脑仍需可用。

要求：

- 写容量估算：更新频率、DOM 节点、JS/内存、网络。
- 设计数据接收、批处理、store selector、排序索引、虚拟化和渲染边界。
- 可见行价格更新延迟目标 < 250ms；滚动 60fps 为目标但明确测试设备。
- 后台行更新不能让所有可见行 render；选择状态不能复制整行。
- 处理 WebSocket backpressure、断线重同步、序列号缺口。
- 可访问性与虚拟化冲突给出折中。
- 定义 5 个性能/稳定性监控指标和降级开关。

不要求写完整表格；实现一个 10,000 行/模拟 500 update/s 的原型并 profile。
