# 第 11 章：性能工程与 React Compiler

## 本章目标

建立“测量 → 定位 → 最小优化 → 验证 → 防回归”的闭环；理解 React Compiler 1.0 后手工 memo 的位置变化，但仍能在未启用编译器/库边界中正确使用 memo。

## 1. 先定义用户指标

不要从“render 次数”开始。先定义场景：冷启动、切路由、打开弹窗、输入筛选、滚动表格。指标包括：

- Core Web Vitals：LCP、INP、CLS；
- TTFB/FCP/TBT（实验室辅助）；
- 业务指标：可交互时间、搜索结果完成、结算成功；
- 资源：JS 大小、请求瀑布、DOM 节点、内存增长。

实验需写设备、网络、数据规模、build 类型。开发 StrictMode/render 时间不能直接当生产结论。

## 2. 四类瓶颈

1. 网络：串行请求、缓存错误、首包过大。
2. JavaScript：长任务、算法、解析、过多 render 工作。
3. React commit：大量 DOM mutation/Effect/layout effect。
4. 浏览器：style/layout/paint、图片/字体、布局抖动。

React Profiler 看组件 render/commit；Chrome Performance 看 JS、layout/paint、网络；bundle analyzer 看代码；Memory 看泄漏。工具必须对症。

React 19.2 的 Performance Tracks 在 Chrome profile 中提供 Scheduler/Components 轨道，有助于观察优先级、render、effect，但不要只截图不解释因果。

## 3. 更新范围比 memo 更重要

优先：

- state 下沉到真正需要的子树；
- 用 children 组合，避免高频父 state 让大子树重算；
- Context 按领域/频率拆分；
- 外部 store 使用 selector；
- 服务端状态不复制；
- 大列表虚拟化；
- 避免 Effect 触发额外一轮派生 state。

结构正确后，很多 memo 不需要。

## 4. `memo/useMemo/useCallback`

- `memo`：props Object.is 相同时可跳过组件 render，但 context/自身 state 更新仍 render。
- `useMemo`：缓存计算结果；React 可在特定情况下丢弃缓存，所以不能依赖其语义正确性。
- `useCallback`：缓存函数引用，本质类似 `useMemo(() => fn)`。

有效需同时满足：计算/子组件确实昂贵、依赖多数时间稳定、memo 成本更低、没有频繁新对象/函数破坏比较。自定义 `arePropsEqual` 容易漏函数闭包或深比较更慢，慎用并 profile。

## 5. React Compiler 1.0

Compiler 在构建时理解 Rules of React，自动应用 memo 化，减少手工 `memo/useMemo/useCallback`。采用步骤：

1. 先升级 hooks lint 并修复 purity/rules violations；
2. 小范围/目录渐进启用；
3. 用 compiler healthcheck/构建日志确认覆盖和跳过原因；
4. 跑完整测试和性能基线；
5. 不要一次删除所有手工 memo，先证明编译结果/库边界。

Compiler 不修复昂贵算法、巨大 DOM、网络瀑布、Effect 风暴、错误状态边界。它也要求代码遵守 React 规则；编译跳过通常应作为代码质量信号调查。

官方入口：[React Compiler](https://react.dev/learn/react-compiler)。

## 6. 列表性能

十万行不能只靠 memo。方案组合：

- 服务端分页/游标；
- 虚拟化窗口 + overscan；
- 稳定 item id；
- 行高测量与 resize 缓存；
- 高频 hover/selection 局部化；
- 排序/过滤用索引、worker 或服务端；
- 可访问性：总行数/位置语义、键盘焦点在卸载行间的策略。

虚拟化会让 DOM 节点复用，测试不要假设所有行同时存在。

## 7. Bundle 与加载序列

- 按路由/功能分割，框架 loader 并行预取；
- 检查 barrel export/tree-shaking、副作用标记；
- 大编辑器/图表按意图加载；
- 图片尺寸/格式、字体子集/预加载需测量；
- third-party script 设预算与加载策略；
- RSC/SSR 可减客户端 JS，但会引入服务端和缓存复杂度。

不要用 gzip 后总数掩盖 parse/execute 和缓存失效。

## 8. 内存与泄漏

常见：未清理 listener/timer/socket、无限 query 页、缓存保留巨大对象、闭包持有 DOM/文件、Portal/第三方实例未 destroy。用重复“进入/离开页面”场景做 heap snapshot/对象增长，而不是看到一次内存高就下结论。

## 本章速记

性能不是“少 render”竞赛。React Compiler 让手工 memo 从默认动作回归为有证据的工具；架构、算法、DOM、网络和测量闭环仍是高级工程师的核心。
