# React Master：从 CRUD 到大型 React 应用负责人

> 调研与编写日期：2026-08-03  
> 适合你：JavaScript 中级、Vue 3 中级、React 初级；已经能做 CRUD，但希望达到一线团队对高级 React 工程师的要求。

这不是 API 百科，也不是题海。它训练的是四件事：**正确建模、稳定交付、解释原理、做出架构取舍**。完成文稿和练习可以显著补齐高级 React 岗位所需的知识与作品证据；“资深/专家”头衔仍然需要真实项目中的规模、故障和协作经验，文稿不会假装能替代它们。

## 先从哪里开始

1. 先读 [市场调研与能力地图](./00-市场调研与能力地图.md)，知道为什么学这些。
2. 再读 [学习方法、环境与版本策略](./00-学习方法与版本策略.md)，建立练习仓库。
3. 按 01 → 18 顺序学习。进入每章后严格遵循：`00-讲义.md` → `01-练习/README.md` → `02-答案/README.md`。
4. 先提交自己的版本再看答案。实在不会时，可以抄答案，但抄完必须关掉答案，从空文件重写关键部分，并用自己的话解释取舍。
5. 每章结束更新本页的进度表；第 18 章用综合项目验收。

## 版本结论

- 当前 React 官方文档的最新稳定主版本线是 **React 19.2**。本课程的核心心智模型、Hooks、状态与性能内容同时适用于 React 18 和 19。
- 练习默认按 **React 19.2 的最新安全补丁版本**理解；不要安装已知存在 RSC 漏洞的 `19.2.0`。公司项目若仍是 React 18，绝大多数章节可以原样实践，React 19 专属内容会明确标注。
- React 18 仍值得掌握的是并发渲染语义、自动批处理、Transitions、Suspense 和 `useSyncExternalStore`，不是旧式类组件。
- 不以类组件、生命周期背诵、Create React App、Enzyme、手写老 Redux 为主线。你只需在遗留项目中能读懂它们。
- SPA 练习采用 Vite；路由采用现代 React Router 的 Data/Framework 思路；服务端渲染与 RSC 采用 Next.js App Router 作为主案例。

详见 [学习方法与版本策略](./00-学习方法与版本策略.md)。

## 建议节奏

### 标准路线：24 周

- 每周 8–12 小时；每章约 1 周，难章用 2 周。
- 第 1–5 章解决“写得对”；第 6–10 章解决“数据与交互复杂后仍写得对”；第 11–15 章解决“上线后可靠”；第 16–18 章解决“能解释、能设计、能负责”。
- 每 3 章安排一次半天回顾：不看资料画出数据流、边界和故障路径。

### 冲刺路线：12 周

- 每周 18–24 小时。
- 讲义都读，练习只做每章的“练习一”，再做第 18 章完整项目。
- 冲刺适合面试补强，不适合把所有知识都沉淀为长期能力。

## 通过标准

每章不是“看完”就算通过。至少满足四项：

- 能在 10 分钟内不看资料讲清本章核心模型。
- 练习一能独立完成，练习二至少能读懂并复写答案。
- 能说出一个错误方案为什么在小 Demo 中可用、到生产中为什么会坏。
- 代码通过类型检查、lint 和相关测试；有性能内容时必须给测量证据。

毕业时你应该能：

- 从业务不变量推导组件树、状态归属、缓存与错误边界，而不是从库名出发。
- 独立交付 TypeScript React 功能，覆盖路由、表单、服务端状态、测试、性能与可访问性。
- 用 Profiler/Performance/网络瀑布/日志定位问题，并提交包含基线和回归保护的修复。
- 解释 render/commit、协调、闭包快照、Effect、并发更新、Suspense、RSC 的边界。
- 写技术方案、ADR、灰度/回滚和事故复盘，进行代码评审并推动团队规范。

## 学习纪律

1. **不凭感觉优化**：先定义指标和场景，再测量，再优化，再做回归测试。
2. **不把 Effect 当业务流程编排器**：优先事件、派生值、loader/query、reducer。
3. **不把所有状态塞进全局库**：先判断它是 URL、服务端缓存、表单、局部 UI 还是跨树客户端状态。
4. **不背答案**：面试中的高级感来自约束、证据和取舍。
5. **不追版本号表演先进**：生产项目优先稳定补丁、安全公告、可迁移性和团队收益。
