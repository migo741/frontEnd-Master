# 第 16 章：React 内部原理与源码阅读

## 本章目标

不是背私有字段，而是建立足以解释行为、定位问题、阅读变更的内部模型。React 私有实现会变；面试中应先讲公开语义，再用实现帮助解释，不能把源码细节当永久 API。

## 1. 为什么需要 Fiber

早期递归协调一旦开始很难让出主线程。Fiber 把工作表示为可遍历的节点/工作单元，使 render 阶段可暂停、恢复、放弃和按优先级调度。

一个 Fiber 粗略包含：类型、key、父/子/兄弟指针、待处理/已记忆 props/state、更新队列、副作用 flags、lanes，以及指向另一棵版本的 `alternate`。字段会变化，记关系即可。

## 2. current 与 work-in-progress

React 通常维护：

- current tree：屏幕已 commit 的版本；
- work-in-progress tree：本次 render 构建的候选版本。

render 可以在 WIP 上计算且放弃，不污染屏幕；commit 后角色切换。这解释了为什么 render 中修改外部系统危险：WIP 可能从未提交，副作用却已经发生。

## 3. begin/complete/commit 的概念

- begin work：根据类型/props/update 计算子节点，决定复用/新建；
- complete work：子树完成后准备宿主变更/汇总 flags；
- commit：分阶段应用 mutation、更新 ref、layout/passive effects。

render 阶段应纯且可重入；commit 阶段不可随意中断，需快速完成 DOM 变更和同步 Effect。

## 4. 协调与 key

列表协调不是通用最优树 diff，而是在 React 的假设下追求 O(n) 常见性能：不同类型产生不同子树；开发者用 key 表达跨 render 身份。无 key/错误 key 时，React 只能按位置推断。

同 key 但 type 变了仍会重建；key 相同只在同级比较有意义。移动、插入、删除会产生 placement/deletion 等 flags，commit 再操作 DOM。

## 5. Hook 为什么不能条件调用

函数组件 Fiber 保存一条 Hook 记录链。render 时每次 Hook 调用按顺序消费/创建记录；下一次 render 需要相同顺序把 `useState` 对应到同一槽位。条件调用改变顺序，后续 state 全部错位。

这只是实现帮助理解；公开规则由 lint/文档定义。不要依赖 Hook 链私有形状。

## 6. State 更新队列

setter 创建 update，带 action/优先级等信息，加入队列并调度 root。render 针对当前 render lanes 处理符合优先级的更新；被跳过的低优先级更新保留供以后重放，因此队列需要 base state/base queue 维持一致性。

函数式 updater 能按队列前值组合；闭包值形式相当于计算好的替换。批处理、Transition 和 lanes 都在此模型中汇合。

## 7. Lanes 与调度

lane 可看作更新优先级/集合的位掩码表示。输入、默认更新、Transition、重试等可落在不同 lanes；调度器选择最高优先级可工作 lanes，必要时让出主线程。具体 lane 名/位会变，面试不要背二进制。

关键公开结论：低优先级 render 可被更紧急更新抢占；多个相关更新可 entangle；过期工作不会永远饿死；commit 只提交一致的树。

## 8. Bailout 与引用

props/state/context/lanes 表明没有工作时，React 可复用已有子树；`memo`/Compiler 提供更多跳过机会。引用相等是优化信号，不是业务正确性替代。直接 mutation 会让“看起来相等”但内容改变，破坏这些假设。

## 9. 事件系统

React 使用跨浏览器的事件抽象和 root 级委托（具体版本实现有演进），把事件与更新优先级/批处理连接。事件传播仍有 capture/bubble；Portal 的 React 事件按 React 树传播，DOM 位置可能不同。

不要凭旧文章背“所有事件都绑 document”。检查目标版本源码/文档。业务层更应依赖标准事件语义和 React 公共 API。

## 10. Effect 链与时序

Effect 的创建发生在 render 记录，执行在 commit 相应阶段。依赖比较通常用 Object.is 逐项；cleanup 在重运行前/卸载时执行。Passive effects 的调度与浏览器绘制有细节，不应用 `setTimeout` 经验猜绝对顺序，需依赖文档与实验。

## 11. 源码阅读方法

1. 固定 tag/commit，不读漂移的 main 就下结论。
2. 从公开行为写最小实验和测试。
3. 从入口/错误信息/测试反查源码，而不是从巨型文件第一行读。
4. 画调用链，只记录与问题相关的 state/flags。
5. 阅读同目录测试和 PR/commit 说明。
6. 输出“观察到的事实 / 推断 / 未确认”，标注版本。

推荐问题驱动：为什么 index key 串 state？函数式 updater如何组合？`useSyncExternalStore` 如何检查 snapshot？Suspense retry 如何被调度？

## 12. 面试表达模板

先公共语义：组件 state 与树身份绑定。再实现直觉：Fiber 通过 type/key/position 协调 current/WIP，并把 state 保存在匹配 Fiber 的 Hook 队列。最后限制：具体字段/算法会随版本变化，生产代码不能依赖。

## 本章速记

Fiber 是可调度的工作/树节点；current/WIP 让 render 可放弃；lanes 表达优先级；Hook 顺序映射状态；commit 才改变外部世界。源码知识的价值是解释和验证，不是背私有变量。
