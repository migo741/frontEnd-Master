# 第 10 章：并发 UI、Suspense 与错误恢复

## 本章目标

理解“并发”是可中断的渲染调度，不是多线程执行组件；能用 Transition、Deferred Value、Suspense 和边界设计不阻塞、可恢复的交互。

## 1. 并发渲染的核心

React 18+ 可以为更新分配优先级，开始一棵树的 render 后被更紧急工作打断，稍后继续或丢弃。这意味着：

- 组件 render 必须纯；
- render 次数不可作为业务事件次数；
- 旧 render 的 Effect 不会在未 commit 时执行；
- 低优先级 UI 可以“落后”，但输入等紧急反馈保持响应。

JS 仍主要跑在主线程。若一个组件 render 内同步循环 500ms，React 不能在这段函数中间神奇抢占；要优化算法、分块或 Web Worker。

## 2. `startTransition/useTransition`

把非紧急 state 更新标为 Transition：

```tsx
const [isPending, startTransition] = useTransition()

function selectTab(next: Tab) {
  setSelectedTab(next) // 若 tab 控件本身必须立即反馈，可拆成紧急值
  startTransition(() => setVisibleTab(next))
}
```

适合导航、复杂结果区更新、非紧急筛选。不适合控制文本输入的 state：输入必须同步跟随键盘。Transition 内的更新可能被更紧急更新打断/替换。

异步 Action 在 `await` 后的更新在不同版本/语义下可能需要再次包 `startTransition`；按当前官方文档和框架封装实践，不背过时结论。

## 3. `useDeferredValue`

当你拿到一个值但无法控制它的 setter，可创建允许滞后的版本：

```tsx
const deferredQuery = useDeferredValue(query)
const isStale = query !== deferredQuery
return <Results query={deferredQuery} dimmed={isStale} />
```

它不等于 debounce：没有固定时间，也不会减少所有网络请求（除非缓存/数据层协作）。它让 React 在紧急更新后再尝试渲染慢子树。输入结果可用 stale 样式提示，避免旧数据被误认为新查询结果。

## 4. Suspense 是“未就绪边界”

Suspense 让子树在数据/代码未就绪时向最近边界声明等待，展示 fallback；数据读取必须由支持 Suspense 的框架/缓存提供。不要在 render 中随手创建 Promise。

边界设计原则：

- 以用户感知的加载序列分组，不为每个组件套 spinner；
- 保留应用壳/旧内容，避免全屏闪烁；
- skeleton 尺寸接近真实内容，减少 CLS；
- 可并行的数据在边界前启动，避免 reveal 串行；
- Suspense 处理 pending，不处理所有错误；与 Error Boundary 配套。

## 5. Reveal 与瀑布

嵌套边界可分阶段显示：外层先展示主体，内层稍后展示相关推荐。但若 child 请求直到 parent 数据完成后才启动，边界无法消除网络瀑布。要在路由/服务端提前并行或重构 API。

`SuspenseList` 等能力的稳定性/框架支持需按当前版本确认，不把实验 API 写进企业基线。

## 6. Error Boundary 与重试

错误边界捕获其子树 render/lifecycle 中的错误，不自动捕获：事件处理器、普通异步回调、服务端错误、边界自身错误。数据层可在 render 时把已记录错误抛给边界。

恢复通常需要：

- 展示安全错误与追踪 id；
- 重置 query/error boundary；
- 以资源 id/重试 token 改变 key 重建子树；
- 保留未受影响壳和用户输入；
- 防无限重试。

## 7. React 19.2 `Activity`

`<Activity mode="hidden">` 可隐藏子树、卸载 effects、延后更新，同时保留部分 UI state 并允许后台预渲染。可用于预备下个页面或保留返回状态。它不是 CSS `display:none`：Effect 生命周期和调度语义不同。使用前确认运行环境/框架与性能收益，React 18 兼容路线仍用条件渲染、路由缓存或外部 state。

## 8. 常见误用

- 所有 setState 都包 Transition：错误，用户反馈会迟滞。
- `useDeferredValue` 当请求 debounce：请求层仍需取消/缓存/防竞态。
- fallback 用整页白屏：破坏已完成内容。
- 边界太细：spinner 碎片化；太粗：一个小卡片摧毁整页。
- 在 render 里发请求/写缓存而没有框架协议：重试造成副作用。
- 用并发 API 掩盖 O(n²) 和超大 DOM：应先解决根因。

## 9. 评审清单

- 哪个更新必须立即反馈，哪个允许落后？
- 慢是 render、DOM、网络还是 JS 长任务？
- Transition 后旧内容是否清楚标记？
- 数据/代码何时启动，是否有瀑布？
- Suspense/Error boundary 是否对应用户感知故障域？
- 重试如何重置，是否保留输入，是否可能循环？
- 降级到 React 18 的策略是什么？

## 本章速记

并发 UI 的本质是为更新排序并允许放弃过时工作。Suspense 是就绪边界，Error Boundary 是故障边界；二者不能替代数据层、取消和真实性能优化。
